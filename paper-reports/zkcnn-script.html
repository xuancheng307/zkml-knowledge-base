zkCNN 口頭報告講稿

Zero Knowledge Proofs for Convolutional Neural Network Predictions and Accuracy

各位好，今天我要報告的論文是 zkCNN，全名是「Zero Knowledge Proofs for Convolutional Neural Network Predictions and Accuracy」，是來自 Texas A&M University 的 Tianyi Liu、Xiang Xie 和 Yupeng Zhang 在 2021 年發表於 ACM CCS 的工作。

這篇論文可以說是 ZKML 領域的奠基之作。它第一次證明了：對於像 VGG-16 這樣有一千五百萬參數的大型 CNN，我們可以在不到兩分鐘內產生一個零知識證明，證明模型推論的正確性。

我今天會按照報告頁面的架構來講：研究動機、技術背景、新型 Sumcheck 協定、卷積證明、系統設計、實驗結果，最後是結論。

先給大家一個總結式的核心句：

zkCNN 的核心突破是：設計了一個全新的 sumcheck protocol for FFT，把 prover 複雜度從 O(N log N) 降到 O(N)。這讓證明 FFT 的時間比直接計算 FFT 還快，從而讓大型 CNN 的可驗證推論變得實際可行。

好，接下來我就照區塊開始。

* * *

區塊一：研究動機

先從問題背景開始。

機器學習模型現在被廣泛應用在金融、醫療、自動駕駛等關鍵領域。但這帶來兩個核心問題：

第一是模型完整性。當你把資料送給遠端伺服器做推論，你怎麼確認它真的用了宣稱的模型？它可能偷偷用了一個便宜但不準確的模型，省下運算成本。

第二是準確度驗證。假設有人說他的模型在某個測試集上達到 99% 準確度，你怎麼驗證？難道要把測試集給他嗎？這樣他可能作弊。

這兩個問題就是 zkCNN 要解決的。它想做到：

場景一（預測證明）：客戶把資料 x 送給伺服器，伺服器計算 y = f(x) 並附上證明。客戶可以驗證 y 確實是用正確的模型算出來的。

場景二（準確度證明）：模型擁有者證明他的模型在某測試集上達到特定準確度，但不需要透露模型權重或測試資料。

在 zkCNN 之前，已經有一些嘗試。主要有兩個先前工作：

第一個是 vCNN，發表在 IEEE S&P 2020。它用 QAP（Quadratic Arithmetic Programs）方法，好處是證明大小很小，只有 288 bytes。壞處是極慢，處理一個 LeNet-5 要 546 秒，將近十分鐘。而且需要 trusted setup。

第二個是 ZEN，發表在 USENIX Security 2021。它用 GKR 協定加上 Freivalds' Algorithm，比 vCNN 快很多，但處理 LeNet-5 還是要 18.7 秒。更重要的是，它不支援像 VGG 這樣的大型網路。

zkCNN 的目標是：比 vCNN 快一千倍以上，而且能支援 VGG-16 這樣的大型模型。

* * *

區塊二：技術背景

在講 zkCNN 的核心技術之前，我需要先介紹兩個背景知識：GKR 協定和 Sumcheck Protocol。

先講 GKR 協定。

GKR 是 Goldwasser、Kalai、Rothblum 在 2008 年提出的互動式證明系統。它專門針對分層算術電路設計。什麼是分層算術電路？就是電路被分成很多層，每一層的輸出是下一層的輸入。

GKR 的核心想法是：從電路的最後一層開始，用 sumcheck 把「驗證這一層的輸出」規約成「驗證上一層的輸出」。一層一層往上規約，最後規約到輸入層。Verifier 只需要檢查輸入，就能確認整個電路的計算正確。

GKR 的複雜度是：Prover 時間 O(|C|)，跟電路大小成線性；Verifier 時間 O(d log |C|)，跟電路深度和電路大小的對數成正比。

接著講 Sumcheck Protocol。

Sumcheck 是 GKR 的核心組件。它要解決的問題是：證明一個多元多項式在所有布林輸入上的求和等於某個值。

具體來說，給定一個 l 元多項式 g(x₁, ..., xₗ)，Prover 要證明：
H = Σ g(b₁, ..., bₗ)，其中每個 bᵢ 取遍 {0, 1}

Sumcheck 的複雜度是：Prover 時間 O(2^l)，Verifier 時間 O(l)，通訊量 O(l)。

現在問題來了。CNN 的核心運算是卷積，而卷積可以用 FFT 加速。直覺上，我們應該把 FFT 電路用 GKR 來證明。

但這裡有個大問題：FFT 電路有 O(log N) 層，每一層用 GKR 做 sumcheck 需要 O(N) 時間。所以總共是 O(N log N)。

這意味著什麼？證明 FFT 的時間跟直接計算 FFT 一樣慢！這完全沒有意義。

這就是 zkCNN 要解決的核心技術問題。

* * *

區塊三：新型 Sumcheck Protocol for FFT

這是 zkCNN 最核心的技術貢獻。

作者觀察到：FFT 有一個非常特殊的結構，叫做蝶形結構（butterfly structure）。Cooley-Tukey 遞迴告訴我們：

a(ω^j) = a⁽⁰⁾(ω^2j) + ω^j · a⁽¹⁾(ω^2j)

其中 a⁽⁰⁾ 是偶數項係數，a⁽¹⁾ 是奇數項係數。

關鍵觀察是：每一層的運算可以用稀疏多項式來表達。而且不同層之間有固定的關聯模式。

zkCNN 的核心想法是：不要對 FFT 的每一層分別做 sumcheck，而是設計一個「跨層」的 sumcheck，一次處理整個 FFT。

這個新的 sumcheck protocol 把 Prover 時間從 O(N log N) 降到 O(N)，Verifier 時間維持 O(log N)，通訊量也是 O(log N)。

技術上，協定分成多個 phase，每個 phase 處理 FFT 的一層轉換。但關鍵是：每個 phase 只對一個變數做 sumcheck，而且利用前一輪的計算結果，避免重複工作。

這個改進有多重要？讓我用實驗數據來說明。

對於 2^18 大小的 FFT（約 26 萬個點）：

- 直接用 GKR 的 FFT 電路方法：大約 3 秒

- naive 方法：超時（超過 1000 秒）

- zkCNN 新方法：約 0.1 秒

快了 30 倍！這就是為什麼 zkCNN 能處理大型 CNN 的關鍵。

* * *

區塊四：2D 卷積的零知識證明

有了高效的 FFT sumcheck，接下來就是把 2D 卷積轉換成 FFT 運算。

這個轉換基於一個經典的數學定理：卷積定理。它說：

X * K = IFFT(FFT(X) ⊙ FFT(K))

也就是說，空間域的卷積等於頻域的逐元素乘法。

zkCNN 的卷積證明流程：
1. 對輸入 X 和 kernel K 做 2D FFT
2. 在頻域做逐元素乘法
3. 對結果做 2D IFFT
4. 裁剪到有效輸出區域

每一步都用 sumcheck 來證明，其中 FFT/IFFT 用新設計的線性時間協定。

2D FFT 怎麼處理？它可以分解成兩次 1D FFT：先對每一行做，再對每一列做。所以總 prover 時間是 O(n²)，對於 n×n 的輸入。

實際的 CNN 有多個輸入通道和輸出通道。zkCNN 可以批次處理這些卷積，共享 FFT 計算，平行化 sumcheck。

從實驗數據來看，對於 256×256 的單一卷積：

- naive sumcheck：大約 32 秒（kernel 大小 64）

- zkCNN sumcheck：約 0.3 秒

快了 100 倍！

* * *

區塊五：zkCNN 系統設計

CNN 不只有卷積層，還有 ReLU、池化、全連接等。zkCNN 需要為每種層設計電路。

先講 ReLU。

ReLU 的定義很簡單：ReLU(x) = max(0, x)。但在有限域上實現很麻煩，因為有限域沒有「正負」的概念。

zkCNN 的做法是：把 x 分解成 k 個位元 (b₀, b₁, ..., b_{k-1})。如果最高位 b_{k-1} = 1，表示 x 是負數，輸出 0；否則輸出 x。

這需要兩類約束：

1. 重組約束：x = Σ bᵢ · 2^i

2. 布林約束：bᵢ · (1 - bᵢ) = 0，確保每個 bᵢ 只能是 0 或 1

接著講 Max Pooling。

Max pooling 需要比較多個元素選出最大值。這比 ReLU 更複雜，因為要做多次比較。每次比較都需要位元分解來判斷誰大誰小。

zkCNN 用位元分解來處理所有涉及「比較」的運算。這是一個通用的技巧：把有限域元素分解成位元，就可以用算術電路模擬布林邏輯。

代價是：每個元素需要 O(k) 個額外的約束，其中 k 是位元寬度。

最後講量化。

神經網路用浮點數，但 ZKP 在有限域上運算。zkCNN 用定點數來近似浮點數：把實數乘以 2^f 後取整數。

問題是：定點數乘法會增加位數。如果不截斷，位數會爆炸。zkCNN 在每層後做截斷，並證明截斷的正確性。

另一個重要設計：zkCNN 用離散對數承諾，不需要 trusted setup。這比 vCNN 用的 QAP 更有優勢，因為不用擔心 setup 被破壞。

* * *

區塊六：實驗結果

現在來看實驗數據。實驗環境是 AWS r5.8xlarge，32 核心 CPU，256 GB 記憶體。

先看主要結果：VGG-16 on ImageNet。

VGG-16 效能：
- 模型參數：1500 萬
- Prover 時間：88.3 秒
- Verifier 時間：59.3 毫秒
- 證明大小：341 KB

這是第一次有人能在合理時間內為 VGG-16 這樣的大型模型產生零知識證明！

跟先前方法比較，用 LeNet-5 作為基準：

- vCNN：546.3 秒 prover，3.7 毫秒 verifier，288 bytes 證明

- ZEN：18.7 秒 prover，0.2 毫秒 verifier，10 KB 證明

- zkCNN：0.43 秒 prover，8.8 毫秒 verifier，35 KB 證明

zkCNN 比 vCNN 快 1264 倍，比 ZEN 快 43 倍！

代價是什麼？證明大小變大了，從 288 bytes 變成 35 KB。Verifier 時間也變長了。這是因為 zkCNN 用的是互動式證明（轉成非互動後用 Fiat-Shamir），而 vCNN 用的是 SNARK。

從時間分解來看，卷積層佔了 80% 以上的 prover 時間。這解釋了為什麼 FFT sumcheck 優化如此關鍵。

最後看準確度證明。對 MNIST 的 1000 筆測試資料：

- Prover 時間：436 秒（約 7 分鐘）

- Verifier 時間：9.1 秒

- 可驗證準確度：98.5%

驗證者可以確認這個模型確實達到 98.5% 的準確度，完全不需要看到測試資料或模型權重。

* * *

區塊七：結論與討論

總結 zkCNN 的主要貢獻：

1. 理論貢獻：首個線性時間的 FFT sumcheck protocol，把 prover 時間從 O(N log N) 降到 O(N)

2. 系統貢獻：完整的 CNN 電路設計，包含卷積、ReLU、池化、全連接

3. 實驗突破：首次為 VGG-16（1500萬參數）產生可驗證的零知識證明，比先前方法快 1264 倍

zkCNN 也有局限性：

第一，它只支援 CNN，不支援 Transformer 或 RNN。

第二，證明大小是 341 KB，比 vCNN 的 288 bytes 大很多。如果要上鏈，這可能是問題。

第三，ReLU 和 max pooling 需要位元分解，開銷還是很大。後續工作如 ZKML 2024 嘗試用 lookup table 來優化這部分。

從歷史角度看，zkCNN 是 ZKML 領域的里程碑。它首次證明了大規模 CNN 的可驗證推論在實務上可行。後續的 zkLLM、ZKTorch 都建立在這個基礎上。

特別是它的 FFT sumcheck 技術，不只適用於 CNN，任何需要 FFT 的場景都可以用。這是一個基礎性的貢獻。
