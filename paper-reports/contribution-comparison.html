差異比較

與現有 ZK 超越函數計算方法的系統化比較

1產業與學術全景

1.1兩大範式

在零知識證明中計算超越函數（transcendental functions），現有方法可歸納為兩個根本不同的範式：查表法（Lookup-based）與多項式近似（Polynomial Approximation）。前者將函數值預先計算並存入大型查找表，後者則用低次多項式逼近目標函數。兩者在 table 成本、每次呼叫成本、以及適用範圍上各有取捨。

範式 原理 Table 成本 每次呼叫成本 適用函數
查表法 (Lookup-based) 預計算 f(x) 的所有可能值 大 (65K+/函數) 1 lookup 任意
多項式近似 (Polynomial) degree-d 多項式近似 f(x) 小 (256 共用) d 次乘法 + 驗證 需平滑、單調

1.2查表系統

ezkl (2022+, production)

ezkl 是目前最主流的 ZKML 框架，以 Halo2 為 proof backend，接受 ONNX 格式的模型輸入。對於非線性函數（如 exp、sigmoid、GELU），ezkl 採用 logUP 查表機制，每個函數需要 65K 以上的 table entries。由於其易用性與完整的工具鏈，ezkl 已成為業界的 de facto 標準。然而，大型查找表帶來顯著的記憶體與 proving 開銷，尤其在需要同時支援多個不同函數時。

ZKML Compiler (EuroSys'24)

ZKML Compiler 是首個支援真實規模深度學習模型的 ZK 框架，成功驗證了 ResNet-18、VGG-16、以及 DistilGPT-2（8.1M 參數）。其核心貢獻在於 layout optimization——透過精密的電路佈局策略，使大規模模型的驗證成為可能。該系統支援 43 種 ML layer，但非線性函數的處理方式與 ezkl 相同，仍然依賴 lookup table，每個函數約需 16K entries。

RISC Zero (zkVM)

RISC Zero 採用完全不同的策略：它是一個通用的 zkVM，能夠執行任意 RISC-V 程式並生成 STARK 證明。開發者可以用 Rust 撰寫標準程式碼，無需手動設計電路。然而，這種通用性的代價是極差的效能——BERT-base 模型大約需要 108 cycles，不適合對效能敏感的場景。對於需要精確控制電路結構的超越函數計算，zkVM 的抽象層級過高。

1.3多項式/代數系統

zkTaylor (AAIA'24)

zkTaylor 使用 Taylor 展開搭配 Circom/Groth16 proof system 來建構 exp 函數的 ZK 電路。這是一篇僅 5 頁的短文，提出了在零知識證明中使用多項式近似的基本想法，但缺乏精度分析，未討論 Minimax 等更優的多項式選擇策略，也未與查表方法做系統比較。其貢獻主要是概念性的，實用價值有限。

ZKFixedPointChip (Xiao, 2023)

ZKFixedPointChip 是與我們最接近的先行工作。它在 Halo2 上使用 lolremez 工具生成 Minimax 最優多項式，支援 exp2、log2、sin 等函數，degree 介於 12-14 之間。然而，ZKFixedPointChip 存在幾個關鍵缺失：(1) 未設計 Output Range Verification (ORV) 機制；(2) 未實作 deferred truncation；(3) 未提供正式誤差分析或誤差分解；(4) 未進行 Minimax 與 Taylor 的對照實驗以量化精度改善。此專案為 hackathon 作品（11 commits），無正式論文發表。

Lagrange Labs (ePrint 2025/2326)

Lagrange Labs 提出了基於 Gauss-Legendre quadrature 搭配 Padé 有理近似的方法，使用 Noir/Barretenberg 作為 proof backend。該系統支援 sin、cos、tan、sigmoid、GELU、erf 等函數，且具有常數深度（≤ 4）的優勢。然而，Padé 有理近似需要除法電路（乘法逆元），在 ZK 電路中引入額外的 constraint 成本。更重要的是，有理近似並非 L∞ 最優——Padé 近似最小化的是某種加權誤差，而非最大絕對誤差。此外，該工作未涵蓋 ln 函數的 benchmark。

ZIP (CCS'25)

ZIP 採用分段多項式（piecewise polynomial）搭配 Caulk multi-lookup 機制，使用 gnark + PlonK proof system。該系統支援 GeLU、SeLU、ELU、exp 等函數，並提出了 "approximation soundness" 的概念——使用 Caulk lookup 驗證近似結果的正確性。ZIP 使用 IEEE-754 雙精度浮點數表示，與我們的定點數方案不同。值得注意的是，ZIP 不覆蓋 ln 函數，且其 approximation soundness 的驗證機制本質上是查表（lookup），而非利用多項式單調性的代數驗證。

zkLLM (CCS'24)

zkLLM 專門針對大型語言模型（7B-13B 參數），其核心貢獻包括 tlookup（tensor-aware lookup）和 zkAttn（專門的 attention 驗證機制）。LLaMA-7B 的 prove time 約 8 分鐘，proof size 小於 200KB。zkLLM 與我們的定位完全不同：它專注於系統層級的最佳化（如何高效驗證完整的 LLM 推論），而我們專注於函數層級的方法論（如何精確計算單一超越函數）。兩者是互補而非競爭的關係。

2文獻空白分析

2.1無 Minimax vs Taylor 系統性比較

ZKFixedPointChip 使用了 lolremez 工具產生 Minimax 係數，但從未與 Taylor 展開做對照實驗，也未量化精度改善幅度。據我們的文獻回顧，目前沒有任何工作在零知識證明的脈絡下提供 Minimax 與 Taylor 的系統性比較。我們提供了據我們所知首個受控比較（controlled comparison）：在同一電路結構（Horner evaluation, degree 5）、同一查找表（256-entry ByteTable）、同一有限域（BN254）下，僅替換多項式係數，從而公平地量化兩種方法的精度差異。

2.2無 Output Range Verification (ORV)

據我們的文獻回顧，沒有任何現有系統具有 Output Range Verification 或類似的機制。在缺乏 ORV 的情況下，惡意的 prover 可以提交超出合法範圍的輸入，使多項式求值溢出，但仍然通過電路的其他約束。ZIP 的 "approximation soundness" 使用 Caulk lookup 來驗證近似結果——這是一種查表機制，本質上依賴預計算的正確值表。相較之下，ORV 利用多項式在指定區間上的單調性，透過 byte decomposition 驗證輸出落在合法範圍內。兩者的目標和機制完全不同。

2.3無 Horner context 的 Deferred Truncation

zkGPT (USENIX Security'25) 提出了 "constraint fusion" 技術，但其作用在 GKR/sum-check protocol 的上下文中，與 Halo2/Horner 架構無關。Truncation Untangled (PoPETs'25) 討論的是 MPC 截斷方案，屬於 layer boundary 層級的局部延後（defer until ReLU boundary），而非整個多項式鏈的全域延後。據我們的文獻回顧，在 Halo2 的 Horner evaluation 電路中，將多步截斷延後合併為單次截斷的策略，目前尚無先例。BN254 的 254-bit 域元素遠大於我們的 96-bit 中間值表示，提供了充足的 headroom 來安全地延後截斷。

2.4無正式誤差預算

ZKFixedPointChip 直接引用 lolremez 的輸出作為近似誤差，但沒有將誤差分解為各個來源。據我們的文獻回顧，沒有現有的 ZK 超越函數電路提供完整的誤差分解。我們提供了完整的三層誤差預算：εtotal = εapprox + εquant + εtrunc，其中 εapprox 為多項式近似誤差、εquant 為係數量化誤差、εtrunc 為截斷誤差。此外，我們透過窮舉驗證（exhaustive verification）覆蓋了所有 45,427 個（exp/ln）或 65,536 個（erf）合法輸入點。

2.5ln 和 erf 在小表方案中無先例

ln(1+x)：Lagrange Labs 未提供 ln 的 benchmark 數據，ZIP 不覆蓋 ln，ZKFixedPointChip 支援的是 log2（以 2 為底的對數，不同的函數，且使用 degree 14 多項式）。據我們所知，我們提供了首個帶有正式精度分析的小表（256 entries）ZK ln 電路。

erf(x)：據我們的文獻回顧，沒有先前的工作使用多項式近似建構 ZK erf 電路。Lagrange Labs 支援 erf，但使用的是 Gauss-Legendre quadrature 搭配 Padé 有理近似（rational approximation），而非純多項式。我們的 erf 電路使用 degree-5 Minimax 多項式，max ULP = 3，只需 256-entry ByteTable。

4逐項貢獻論證

4.1Contribution 1：Minimax 係數選擇

我們的核心觀察是：在相同的電路結構與計算成本下，Minimax（Remez 演算法）多項式相較於 Taylor 展開，能顯著降低最大逼近誤差。窮舉驗證顯示（156,390 個合法輸入全部覆蓋），在 degree-5 Horner evaluation 電路中，Minimax 係數對 exp 函數的精度改善幅度達 12 倍。

函數 Taylor ULP Minimax ULP 改善 備註
exp(x)−1 12 1 12x 公平比較 (5 vs 5 非零係數)
ln(1+x) 762 1 762x 公平比較 (5 vs 5 非零係數)
erf(x) 1,467 3 489x 不完全公平 (5 vs 3 非零係數)*

*erf(x) 是奇函數，其 Taylor 展開在 5 次多項式中只有 3 個非零係數（x, x³, x&sup5;），而 Minimax 使用了全部 5 個。公平的 headline 數字應該用 exp 的 12x。

與 ZKFixedPointChip 的差異

ZKFixedPointChip 使用了 lolremez 生成 Minimax 係數，但未與 Taylor 做對照實驗、未量化 ULP 改善、未進行窮舉驗證。我們在同一電路、同一查找表、同一有限域下替換係數，提供了據我們所知首個受控比較，使精度改善的幅度可以被嚴謹量化。

與 FHE 的差異

Minimax 多項式在全同態加密（FHE）領域自 2021 年 Lee et al. (EUROCRYPT) 起已成為標準技術。然而，FHE 與 ZK 的計算模型存在根本差異：FHE 使用 CKKS rescaling（非顯式截斷），且沒有 prover/verifier 對抗模型。ZK 的有限域整數運算、顯式截斷操作、以及對抗式 prover 的存在，使得 Minimax 的應用需要全新的工程考量——包括係數量化到有限域、截斷策略的選擇、以及 soundness 的保證。

4.2Contribution 2：Output Range Verification (ORV)

ORV 利用多項式在指定區間上的嚴格單調性來驗證輸入範圍。其機制如下：對於單調多項式 P，若 w = floor(P(R) / S5) 且 w ∈ [0, S−1]，則 R 必然在合法範圍 [0, RMAX] 內。這個驗證透過 byte decomposition 實現——將 w 分解為位元組並查表確認每個位元組落在 [0, 255] 範圍內，成本極低。

ORV 據我們所知是全新的概念——既不在 ZKFixedPointChip，也不在 Lagrange Labs 或 ZIP 中出現。據我們的文獻回顧，沒有任何現有系統利用多項式單調性來驗證輸入範圍的合法性。

與 ZIP "approximation soundness" 的差異

ZIP 的 "approximation soundness" 使用 Caulk lookup 驗證 |y − f(y')| ≤ δ · |f(y')|，本質上是查表機制。ORV 使用 byte decomposition 驗證 w ∈ [0, S−1]，是純代數約束。兩者的機制完全不同：ZIP 依賴預計算的正確值，ORV 利用多項式本身的數學性質。

4.3Contribution 3：Deferred Truncation

在 Horner evaluation 的每一步乘法後，定點數的位寬會增加，通常需要立即截斷以防止溢出。然而，BN254 有限域的 254-bit 容量遠大於我們 96-bit 的中間值表示，提供了充足的 headroom。我們的 deferred truncation 策略將 degree-5 Horner 鏈中的 5 次截斷延後合併為最終的 1 次截斷。實驗顯示（三個函數窮舉驗證），這不僅減少了電路中的 constraint 數量，還一致地改善了精度 2.0 倍——因為避免了 4 次中間截斷的累積誤差。

與 zkGPT "constraint fusion" 的差異

zkGPT (USENIX Security'25) 的 "constraint fusion" 作用在 GKR/sum-check protocol 上下文中，是對 sum-check 多項式的約束合併。這與我們在 Halo2 PLONKish 電路中的 Horner evaluation deferred truncation 在架構層級上完全不同——前者是 protocol-level 的最佳化，後者是 arithmetic circuit-level 的截斷策略。

與 Truncation Untangled (PoPETs'25) 的差異

Truncation Untangled 討論的是 MPC（secure multi-party computation）情境下的截斷方案，屬於 layer boundary 層級的局部延後——將截斷延後到 ReLU boundary。我們的 deferred truncation 是整個多項式鏈的全域延後：在 degree-5 的 Horner evaluation 中，將所有 5 次截斷合併為 1 次。兩者的作用範圍、計算模型、以及安全模型均不同。

4.4Contribution 4：Universal Kernel

固定電路結構：5 gates, 12 lookups, 9 rows, 256-entry ByteTable。切換函數只需替換 5 個係數常數。

我們的 kernel 對所有支援的函數使用完全相同的電路拓撲。這意味著切換目標函數時，不需要重新設計電路、不需要修改 constraint 邏輯，只需替換 5 個多項式係數。實測結果（4 函數 real KZG proof, 5-run average）顯示，不同函數間的 prove time 差異小於 1.4%，proof size 完全相同。

函數 Prove (ms) Verify (ms) Proof (B) Max ULP
exp(x)−1 137.8 1.75 4,960 1
ln(1+x) 135.9 1.88 4,960 1
erf(x) 137.0 1.83 4,960 3
GELU(x) 137.5 1.76 4,960 1

Prove time 差異 < 1.4%，proof size 完全相同。據我們的文獻回顧，無其他系統達到此結構通用性——ZKFixedPointChip 的不同函數使用不同 degree（12-14），ezkl 的不同函數使用不同大小的查找表，Lagrange Labs 的不同函數需要不同的 Padé 參數化。

4.5Contribution 5：Function Coverage Theorem (C1-C6)

我們提出了一組充分條件 C1-C6，用以判定一個超越函數是否可被我們的 universal kernel 處理。滿足 C1-C6 的函數可以直接套用我們的電路結構，只需計算對應的 Minimax 係數。

條件 名稱 作用
C1 零錨點 消除常數項，啟用 ORV
C2 嚴格單調 保證 ORV soundness
C3 輸出有界 輸出可用 pp-bit 表示
C4 多項式可近似 Horner 求值的前提
C5 係數量化 有限域中不溢位
C6 輸入分解 byte decomposition 可行

初步分析顯示，10 個以上常見函數（sigmoid、tanh、GELU、softplus、sin、arctan、erfc、expm1、log1p、softmax 中的 exp 等）均可滿足 C1-C6，代表這是一個可擴展的通用框架。Coverage theorem 將我們的系統從「支援 4 個函數的實作」提升為「可覆蓋任意滿足條件之函數的方法論」。

5誠實的限制

1. ULP 範圍限制：max ULP claims 僅限於 Horner evaluation kernel 本身。End-to-end 精度取決於 range reduction 的實作品質——例如 exp 需要先將輸入分解為整數部分與小數部分。Range reduction 的精度損失不在本論文範圍內。
2. Batch 場景：N=1,000 時，我們的 prove time 為 1,011ms，而 Method B（Chunk lookup）僅需 135ms（7.5x 劣勢）。每次求值需要 9 rows，而查表法只需 1 row。在大量批次計算中，查表法的效率優勢明顯。
3. Proof size：4,960B vs Method A（Direct lookup）的 736B，大了 6.7x。雖然在絕對值上仍然可接受（不到 5KB），但並非最小。
4. GELU 覆蓋：目前的 GELU 實作只覆蓋 [0, 1] 區間。x > 1 時需要分段擴展（piecewise extension），這是未來工作的一部分。
5. erf 489x caveat：erf 的 489x 精度改善數字來自 5 vs 3 非零係數的不完全公平比較（Taylor 展開只有 3 個非零項，而 Minimax 使用全部 5 個）。公平的 headline 數字應該用 exp 的 12x。

6結語——定位總結

我們提出了一套結合四個設計決策的方法論：Minimax 係數選擇、Output Range Verification、Deferred Truncation、以及 Universal Kernel 設計。不同於 ZKFixedPointChip (2023) 使用 Minimax 但缺乏正式分析，我們提供了缺失的方法論——區間選擇、截斷策略比較、ORV 設計、以及正式誤差預算和窮舉驗證。不同於查表方法（ezkl 65K+, ZKML Compiler 16K+），我們的電路只使用 256-entry ByteTable。不同於 Lagrange Labs 的 GL quadrature + Padé 有理近似，我們使用純多項式並具有可證明的 L∞ 最優性。

我們的定位並非取代查表法——在 batch 場景和需要零精度損失的情境下，查表法仍有其優勢。我們的貢獻在於：當 table size 受限、需要多函數支援、且可接受微小精度損失（max ULP ≤ 3）時，提供了一個有系統理論支撐的替代方案。
