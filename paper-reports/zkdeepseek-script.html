ZK-DeepSeek: 671B 參數模型的零知識驗證

口頭報告講稿 | 預估時間：12-15 分鐘

1. 開場與背景 ~2 分鐘

大家好，今天我要介紹的是 ZK-DeepSeek，這是浙江大學的 Yuenan Wang 在 2025 年發表的工作，首次實現了對 671B 參數超大規模模型的零知識驗證。

我們知道 zkLLM 已經能驗證 13B 參數的 LLM，但 DeepSeek-V3 這樣的模型有 671B 參數，而且採用了全新的架構：MoE（混合專家）和 MLA（多頭潛在注意力）。這些架構帶來了全新的驗證挑戰。

ZK-DeepSeek 的目標就是解決這個問題：如何高效驗證這些超大規模、新架構的模型？

講者提示：可以先介紹 DeepSeek 在開源 AI 社群的影響力，以及為什麼驗證這類模型很重要。

2. DeepSeek 架構簡介 ~2 分鐘

在介紹技術方案之前，讓我們先了解 DeepSeek 的兩個關鍵創新：

第一個是 MLA（Multi-head Latent Attention）。傳統 Transformer 的 KV Cache 隨序列長度線性增長，非常消耗記憶體。MLA 的做法是將 Key 和 Value 投影到一個共享的低維潛在空間，推理時再透過輕量投影層重建。這大幅降低了記憶體需求。

第二個是 MoE（Mixture of Experts）。671B 參數中，每次推理只激活一小部分「專家」。這透過一個 gating 網路來決定哪些專家處理當前 token。

這兩個架構特性都需要專門的 ZK 驗證方案。

3. 核心技術：CRPC ~3 分鐘

ZK-DeepSeek 的第一個核心貢獻是 CRPC（Common Reduced Polynomial Circuits），也就是通用降維多項式電路。

神經網路的核心運算是矩陣乘法。假設我們有 X 乘以 W 等於 Y，傳統的 SNARK 驗證需要 O(a×n×b) 個約束，對於超大矩陣來說這是不可接受的。

CRPC 的關鍵洞察是：我們可以定義一個 ZMul 函數，把整個矩陣乘法壓縮成單一多項式恆等式。透過 Schwartz-Zippel 引理，只要選取隨機的 z 值，如果恆等式成立，我們就有極高的信心矩陣乘法是正確的。

讓我解釋一下 Schwartz-Zippel 引理的原理。如果兩個多項式不相等，那麼在有限域上隨機選一個點，它們相等的機率是可以忽略的。這意味著我們不需要逐元素檢查矩陣乘法的每個輸出，只需要驗證一個隨機點上的多項式等式。

複雜度從 O(anb) 降低到 O(an + nb)，這是數量級的改進。

另外，當神經網路的單一層太大時，ZK-DeepSeek 使用遞迴證明組合。具體做法是：先把大矩陣按行分割，再把每行分割成固定大小的區段。為每個小區段生成證明後，再把這些小證明遞迴合併成單一證明。最終的證明大小是常數，驗證時間也是常數，不管原始模型有多大。

講者提示：可以用一個簡單的 3×3 矩陣乘法作為例子，說明傳統方法需要 27 個約束，而 CRPC 只需要 6+6=12 個。

4. GeMM 驗證協議 ~2 分鐘

基於 CRPC，ZK-DeepSeek 設計了 GeMM（General-purpose Matrix Multiplication）驗證協議，需要確保三個正確性條件：

  • 輸入一致性：這一層的輸入必須等於上一層的輸出
  • 乘法正確性：矩陣乘法本身是正確的
  • 模型完整性：使用的權重確實是承諾的模型參數

這三個條件都透過承諾比對來驗證，使用相同的隨機 z 值確保一致性。

5. MLA 與 MoE 支援 ~3 分鐘

對於 MLA，ZK-DeepSeek 需要驗證四個額外操作：

  • Key 投影到潛在空間
  • Value 投影到潛在空間
  • Key 從潛在空間重建
  • Value 從潛在空間重建

這些都是矩陣乘法，可以用 CRPC 高效處理。

對於 MoE，驗證更複雜。需要驗證：

  • 路由機制（gating）正確選擇了 Top-K 專家
  • 被激活的專家計算正確
  • 專家輸出的加權組合正確

好消息是，因為 MoE 是稀疏的，我們只需要驗證被激活的專家，這反而降低了驗證成本。

6. 其他組件與實現細節 ~2 分鐘

除了矩陣乘法，神經網路還有其他組件需要驗證：

Softmax：使用定點數近似，將指數運算分段並透過預計算查表實現。這和 zkLLM 的方法類似。

RoPE（旋轉位置編碼）：預計算所有 sin 和 cos 值，儲存為權重矩陣。證明者只需驗證與預計算值的一致性。

LayerNorm：透過近似和查表處理平方根等非線性操作。

值得一提的是軟體實現的細節。ZK-DeepSeek 使用 Python 3.12 搭配 CUDA 12.9 進行 GPU 加速。SNARK 驗證後端採用 o1js 2.10 運行在 Node.js v24.8 上。整個系統基於 Fiat-Shamir 啟發式來構建非互動式證明。

為了確保與有限域算術的相容性，所有神經網路參數都被轉換為整數表示。這包括矩陣權重的定點數量化、RoPE 係數的預計算表格、以及 Softmax 常數的分段近似。

7. 總結與影響 ~1 分鐘

讓我們總結 ZK-DeepSeek 的主要貢獻：

  • CRPC：將矩陣乘法約束從 O(anb) 降至 O(an+nb)
  • 首個 MoE/MLA 支援：原生支援 DeepSeek 架構
  • 671B 規模突破：相較 zkLLM 的 13B 擴展約 50 倍

這項工作代表 ZKML 領域的最新進展。從 2021 年的 zkCNN 到今天的 ZK-DeepSeek，我們看到可驗證模型的規模不斷擴大。未來的挑戰包括進一步降低證明時間、支援更長序列、以及實現更高的精度保持。
