FRI 多項式承諾

核心概念

FRI（Fast Reed-Solomon Interactive Oracle Proof of Proximity）是一種基於雜湊函數的多項式承諾方案，是 STARK 證明系統的核心組件[1]。FRI 不需要可信設置，且具備後量子安全性，但證明大小較大。

核心思想

Reed-Solomon 編碼

FRI 利用 Reed-Solomon 碼的數學性質[1]：

  • 次數 \(d\) 的多項式可由 \(d+1\) 個點唯一確定
  • 若函數 \(f: D \to \mathbb{F}\) 是次數 \(\leq d\) 的多項式，則其在任意子集上的限制也具有此性質
  • 若 \(f\) 不是低次多項式，則它與任何低次多項式有顯著距離

接近性測試

FRI 的目標是證明[1]：

給定對函數 \(f: D \to \mathbb{F}\) 的預言機存取，
\(f\) 與某個次數 \(\leq d\) 的多項式 \(\delta\)-接近。

其中 \(\delta\)-接近表示：\(|\{x \in D : f(x) \neq p(x)\}| < \delta |D|\)

FRI 協議

基本構造

FRI_Commit(f, D):
  // f: 次數 ≤ d 的多項式
  // D: 求值域（通常是乘法子群）

  // 第 0 層：對整個域求值
  f_0(x) = f(x) for x ∈ D
  commitment_0 = MerkleTree(f_0)

  // 迭代折疊
  for i = 1 to log(d):
    // 接收隨機挑戰
    α_i = Hash(transcript)

    // 折疊：將 f 分解為奇偶部分
    // f(x) = f_even(x²) + x · f_odd(x²)
    // f'(x) = f_even(x) + α · f_odd(x)
    f_i(x) = fold(f_{i-1}, α_i)

    // 在更小的域上求值
    D_i = {x² : x ∈ D_{i-1}}
    commitment_i = MerkleTree(f_i)

  // 最終層：常數多項式
  return (commitment_0, ..., commitment_k, f_final)

折疊過程

FRI 的關鍵是多項式折疊[1]：

fold(f, α):
  // 將 f(x) 分解：
  // f(x) = f_even(x²) + x · f_odd(x²)

  // 例如：f(x) = c_0 + c_1·x + c_2·x² + c_3·x³
  // f_even(y) = c_0 + c_2·y
  // f_odd(y) = c_1 + c_3·y

  // 折疊後：
  f'(y) = f_even(y) + α · f_odd(y)

  // 關鍵性質：
  // deg(f') ≤ deg(f) / 2
  // 若 f 是低次多項式，f' 也是
  // 若 f 不是，折疊後更容易檢測

查詢階段

FRI_Query(commitments, x, num_queries):
  proofs = []

  for q = 1 to num_queries:
    x_0 = sample_random(D)
    query_proof = []

    for i = 0 to k-1:
      // 查詢配對點
      x_i = current_domain_point
      -x_i = -x_i (共軛點)

      // 從 Merkle 樹獲取值和證明
      (v_+, proof_+) = MerkleQuery(commitment_i, x_i)
      (v_-, proof_-) = MerkleQuery(commitment_i, -x_i)

      // 驗證者檢查折疊一致性
      v_next = (v_+ + v_-)/2 + α_i · (v_+ - v_-)/(2·x_i)

      query_proof.append((v_+, v_-, proof_+, proof_-))
      x_{i+1} = x_i²

    proofs.append(query_proof)

  return proofs

驗證

FRI_Verify(commitments, final_value, queries):
  for each query in queries:
    x_0 = query.start_point

    for i = 0 to k-1:
      (v_+, v_-, proof_+, proof_-) = query[i]

      // 驗證 Merkle 證明
      assert MerkleVerify(commitment_i, x_i, v_+, proof_+)
      assert MerkleVerify(commitment_i, -x_i, v_-, proof_-)

      // 驗證折疊一致性
      expected = (v_+ + v_-)/2 + α_i · (v_+ - v_-)/(2·x_i)
      actual = query[i+1].v_+ (在 x_i² 處)
      assert expected == actual

    // 驗證最終值
    assert query.final == final_value

  return true

複雜度分析

操作 時間複雜度 空間複雜度 說明
Setup O(1) O(1) 完全透明，無需設置
Commit O(n log n) O(n) FFT + Merkle 樹建構
Prove O(n log n) O(n) log n 輪折疊 + 查詢
Verify O(λ log² n) O(log n) λ = 安全參數（查詢數）
證明大小 - O(λ log² n) 較大，主要缺點

安全性參數

查詢數量

安全性與查詢數量直接相關[1]：

soundness_error ≈ (1 - δ + ε)^num_queries

其中：
  δ = 接近性參數（通常 1/2 或 1/4）
  ε = 碼率相關誤差
  num_queries = 查詢數量

典型配置：
  - 80-bit 安全性：約 40 次查詢
  - 128-bit 安全性：約 64 次查詢

證明大小影響：
  每次查詢 ≈ 32 bytes × log(n) × 2（Merkle 路徑）
  128-bit 安全，n = 2^20：
    ≈ 64 × 32 × 20 × 2 ≈ 80 KB

Blowup Factor

求值域大小與多項式次數的比值[2]：

blowup_factor = |D| / (d + 1)

常見選擇：
  - 2x：高效率但安全性較低
  - 4x：平衡選擇
  - 8x：更高安全性

影響：
  - 更大的 blowup → 更小的 δ → 更少查詢 → 更小證明
  - 但需要更多計算和儲存

DEEP-FRI 變體

DEEP（Domain Extension for Elimination of Preprocessing）改進版本[2]：

DEEP-FRI 改進：
  1. 在域外點進行查詢
  2. 減少 blowup factor 需求
  3. 更好的安全性分析

協議變化：
  - 驗證者選取隨機點 z ∉ D
  - 證明者提供 f(z) 及一致性證明
  - 將問題轉化為接近性測試

優勢：
  - 4x blowup 可達 2x blowup 的效果
  - 證明大小減少約 50%

在 STARK 中的應用

STARK 架構

FRI 是 STARK 證明系統的核心[3]：

STARK 證明流程：
  1. 算術化：將計算轉換為多項式約束
     - 執行軌跡 → 軌跡多項式 T(x)
     - 約束 → 組合多項式 C(x)

  2. 多項式承諾：使用 FRI
     - 對 T(x), C(x) 進行 FRI 承諾

  3. 查詢：
     - 驗證者隨機選取查詢點
     - 證明者提供 FRI 證明

  4. 驗證：
     - 檢查約束滿足性
     - 驗證 FRI 證明

FRI 在 STARK 中的角色：
  - 證明 C(x) = T(x) · Z(x) / V(x) 是低次多項式
  - 這確保了軌跡滿足所有約束

後量子安全性

安全假設

FRI 僅依賴雜湊函數的安全性[1]：

  • 抗碰撞性：難以找到 \(x \neq y\) 使 \(H(x) = H(y)\)
  • 抗原像性：給定 \(h\)，難以找到 \(x\) 使 \(H(x) = h\)
  • 隨機預言機模型：Fiat-Shamir 變換的安全性

量子安全分析

經典安全 vs 後量子安全：

雜湊函數（如 SHA-256）：
  - 經典：256-bit 安全
  - 量子：128-bit 安全（Grover 算法）

FRI 影響：
  - 增加雜湊輸出長度（256 → 512 bits）
  - 或增加查詢次數
  - 證明大小約增加 2 倍

與 KZG/IPA 比較：
  - KZG/IPA：基於橢圓曲線，不抗量子
  - FRI：僅需調整參數即可抗量子

效能優化

FFT 優化

FRI 大量使用 FFT：

標準 FFT：O(n log n)

優化技術：
  1. NTT（Number Theoretic Transform）
     - 使用有限域而非複數
     - 避免浮點誤差

  2. 並行化
     - FFT 天然可並行
     - GPU 加速可達 10-100x

  3. 快取優化
     - 改善記憶體存取模式
     - 減少 cache miss

Merkle 樹優化

Cap 高度優化：
  - 預先公開 Merkle 樹頂部
  - 減少每次查詢的證明大小

  標準 Merkle 路徑：log(n) 個雜湊
  Cap 高度 = k：log(n) - k 個雜湊

位元組對齊：
  - 使用 SIMD 指令加速雜湊
  - 批次處理 Merkle 節點
