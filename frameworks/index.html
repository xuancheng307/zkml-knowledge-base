註：多項式承諾方案

ZKTorch 驗證時間說明

ZKTorch 的驗證時間（秒級）遠高於 ZKML（毫秒級）。根據論文 Table 4 數據，ResNet-50 驗證時間為 62.8s，BERT 為 26.7s[2]。這可能與其平行累積架構的驗證策略有關，但具體原因需參閱原論文。

優缺點分析

ZKML (EuroSys 2024)

優點缺點
  • 首個支援 ImageNet 規模模型的系統
  • 完整的 Auto-Tuning 框架
  • 系統性的量化與配置空間研究
  • 學術論文支持，理論完整
  • 僅支援 TensorFlow 輸入
  • 部分開源
  • 無證明聚合

ZKTorch

優點缺點
  • 並行證明累積，效能最佳
  • 支援完整 MLPerf 模型集
  • 完整開源
  • 證明大小最小（KZG）
  • 需要可信設置（KZG）
  • 較新，生態尚未成熟

EZKL

優點缺點
  • ONNX 支援，PyTorch 一鍵轉換
  • 完整開源，社群活躍
  • CLI 工具易用
  • EVM 驗證器生成
  • 大型模型效能較差
  • 配置調優較複雜
  • 文檔較分散

zkLLM

優點缺點
  • 首個支援十億級參數 LLM
  • 專門針對 Transformer 優化
  • 使用 tlookup 處理非線性
  • 僅支援 LLM
  • 記憶體需求極高
  • 證明時間仍較長

RISC Zero

優點缺點
  • 通用計算，任意 RISC-V 程式
  • 無需電路特化開發
  • 透明設置（STARK）
  • 後量子安全
  • 證明大小較大
  • ML 效能不如專用系統
  • 驗證時間較長

選擇決策樹

需要 ZKML？
│
├─ 快速原型/學習
│   └─→ EZKL（ONNX 支援、易上手）
│
├─ 生產環境
│   ├─ 模型規模
│   │   ├─ 小型（MNIST, CIFAR）
│   │   │   └─→ EZKL 或 ZKML
│   │   │
│   │   ├─ 中型（ResNet, MobileNet）
│   │   │   └─→ ZKTorch（最快）或 ZKML
│   │   │
│   │   └─ 大型（LLM）
│   │       └─→ zkLLM
│   │
│   └─ 需要鏈上驗證
│       ├─ 證明大小敏感
│       │   └─→ ZKTorch (KZG) 或 ZKML
│       │
│       └─ 無信任設置需求
│           └─→ RISC Zero (STARK)
│
└─ 通用計算（非純 ML）
    └─→ RISC Zero
