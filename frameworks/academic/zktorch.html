ZKTorch (2025)

論文資訊

Chen, B.-J., Tang, L., & Kang, D. "ZKTorch: Compiling ML Inference to Zero-Knowledge Proofs via Parallel Proof Accumulation." arXiv preprint arXiv:2507.07031, 2025.[1]

概述

ZKTorch 是目前最先進的 ZKML 編譯器系統，直接從 PyTorch 模型編譯生成 ZK 電路。相較於前一代 ZKML 系統，ZKTorch 透過平行累積（parallel accumulation）技術實現了顯著的效能提升，成功支援大規模 ML 模型的可驗證推理[1]。

關鍵創新：平行累積

ZKTorch 的核心創新是平行累積 (Parallel Accumulation) 技術，解決了 ZKML 的主要效能瓶頸[1]：

問題背景

傳統累積問題：
  線性層 y = Wx + b 需要大量乘法累加

  y_i = Σ_j (W_ij · x_j) + b_i

  ZK 電路中的累積約束：
    acc_0 = 0
    acc_1 = acc_0 + W_0 · x_0
    acc_2 = acc_1 + W_1 · x_1
    ...
    y = acc_n + b

  問題：深度為 O(n)，序列依賴導致無法平行化

平行累積解決方案

平行累積樹結構：
        層 0:  a₀ a₁ a₂ a₃ a₄ a₅ a₆ a₇
               ↘↙   ↘↙   ↘↙   ↘↙
        層 1:   s₀₁  s₂₃  s₄₅  s₆₇
                ↘↙       ↘↙
        層 2:   s₀₋₃     s₄₋₇
                   ↘↙
        層 3:    sum_total

  深度：O(log n) 而非 O(n)
  平行度：每層可同時計算多個部分和

效能改進

指標 傳統方法 平行累積 改進
電路深度 O(n) O(log n) 指數級降低
證明並行度 低 高 充分利用多核
證明時間 基準 ~2-5x 加速 顯著改進

使用方式

基本用法

import torch
import zktorch

# 定義 PyTorch 模型
class MyModel(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.linear = torch.nn.Linear(128, 64)
        self.relu = torch.nn.ReLU()

    def forward(self, x):
        return self.relu(self.linear(x))

model = MyModel()
sample_input = torch.randn(1, 128)

# 編譯為 ZK 電路
circuit = zktorch.compile(model, sample_input)

# 生成證明
proof = circuit.prove(input_data)

# 驗證證明
is_valid = circuit.verify(proof, public_inputs)

進階配置

config = zktorch.Config(
    # 量化設定
    quantization_bits=8,

    # 電路最佳化
    enable_parallel_accumulation=True,
    optimization_level=2,

    # 後端選擇
    backend="halo2",
    commitment_scheme="kzg",

    # 效能調整
    num_threads=8,
    memory_limit_gb=64
)

circuit = zktorch.compile(model, sample_input, config=config)

與 ZKML (2024) 的比較

ZKTorch 可視為 ZKML 系統的下一代版本，由同一研究團隊開發[1][2]：

特性 ZKML (2024) ZKTorch (2025)
輸入格式 TensorFlow PyTorch (MLPerf 模型)
累積策略 序列累積 平行累積
模型支援 CNN 為主 CNN/RNN/Transformer
Auto-Tuning 有 有，更進階
開發便利性 需 TensorFlow 格式 支援 MLPerf 模型集

技術限制

  • 動態形狀：模型輸入形狀需在編譯時確定
  • 控制流：有限支援資料依賴的分支
  • 自定義運算：非標準 PyTorch 算子需額外定義
  • 模型規模：超大模型（如 GPT-4）仍具挑戰
