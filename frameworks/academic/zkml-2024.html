ZKML (EuroSys 2024)

論文資訊

標題：ZKML: An Optimizing System for ML Inference in Zero-Knowledge Proofs
作者：Bo-Jhang Chen, Sruthi Waiwitlikhit, Ion Stoica, Daniel Kang
發表：EuroSys '24, April 22-25, 2024, Athens, Greece
機構：UC Berkeley, University of Illinois Urbana-Champaign

研究動機

ZKML 是首個能夠為現實規模機器學習模型產生 ZK-SNARK 證明的端到端框架[1]。在此論文發表之前，所有 ZKML 相關工作僅能處理 MNIST、CIFAR-10 等小型模型，無法擴展到實際應用所需的模型規模。

核心問題

論文識別出 ZKML 的三個核心挑戰：

挑戰 描述 ZKML 解決方案
電路設計複雜 不同運算需要不同的最優電路實現 多種 Gadgets + 自動選擇
配置空間龐大 電路參數選擇影響效能達 24 倍 成本估算器 + 優化器
非線性函數困難 激活函數難以用多項式約束 查表優化策略

突破性成果

ZKML 首次支援以下現實規模模型的可驗證推理：

  • 視覺模型：ResNet-18、VGG-16、MobileNet（ImageNet 規模）
  • 語言模型：DistilGPT-2（8,130 萬參數）
  • 推薦系統：Twitter 推薦演算法 MaskNet（4,810 萬參數）
  • 擴散模型：小型 Stable Diffusion（1,950 萬參數）

Gadgets 設計

ZKML 將 ML 運算分解為四大類 Gadgets，這是系統效能的核心[1]：

1. Shape Operations（形狀操作）

零成本抽象

由於張量可持有對先前分配儲存格的引用，形狀操作（reshape、slice、concat、transpose）可邏輯上執行而無需分配新儲存格，因此對證明時間「免費」。

支援的形狀操作：

  • reshape：改變張量形狀
  • slice：切片操作
  • concat：拼接操作
  • transpose：轉置操作
  • split：分割操作

2. Arithmetic Operations（算術操作）

Gadget 運算 約束形式 儲存格數
Add(x, y) x + y x + y - z = 0 3
Mul(x, y) x · y x · y - z = 0 3
Div(x, y) ⌊x/y⌋ x = q · y + r, 0 ≤ r < y 4
DivRound(x, y) Round(x/y) 含捨入邏輯的約束 5
Square(x) x² x · x - z = 0 2
DotProd(x, y) x · y (向量) 累積乘積約束 n + 1

3. Pointwise Non-linearities（逐點非線性）

激活函數如 ReLU、ELU、Sigmoid、Tanh 難以用低次多項式約束表示。ZKML 提供兩種實現方式[1]：

方式一：位元分解

ReLU(x) = max(x, 0) 的位元分解實現：

【編碼前提】
ZKML 使用 offset encoding 處理有號整數：
  實際值範圍 [-2^(b-1), 2^(b-1)-1] 映射到 [0, 2^b)
  x_offset = x_signed + 2^(b-1)（加偏移量）

範例（b=8）：x=-1 → x_offset=127；x=0 → x_offset=128

1. 將偏移後的值 x_offset 分解為 b 個位元
2. 最高位 b_{b-1} = 1 表示原值 ≥ 0；= 0 表示原值 < 0
3. 根據最高位選擇輸出原值或 0

約束（offset encoding）：
  x_offset = x + 2^(b-1)           (加偏移)
  x_offset = Σᵢ bᵢ · 2ⁱ           (位元分解，0 ≤ x_offset < 2^b)
  bᵢ · (bᵢ - 1) = 0               (每個 bᵢ ∈ {0,1})
  y = x · b_{b-1}                  (若最高位=1 則原值≥0，輸出 x)

儲存格數：b + 2
適用場景：ReLU 操作數量較少時

（註：具體 gadget 實作細節請參見 ZKML 論文 §4.1）

方式二：查表（Lookup Table）

查表實現：

1. 預計算：建立 {(x, f(x))} 查表
2. 約束：驗證 (input, output) 對存在於表中

表大小：2^n 行，n 是輸入位元數
儲存格數：2（僅需 input 和 output）

優點：每次操作成本固定
缺點：表大小受限於電路總行數

適用場景：大量非線性操作時
關鍵洞察

最佳實現方式取決於模型中非線性操作的全域分布。若只執行少量 ReLU，位元分解可能更高效；若執行數百萬次 ReLU，查表更划算。ZKML 優化器會自動選擇最佳策略。

4. Specialized Operations（特化操作）

主要為 Softmax 所需的複雜操作：

Gadget 運算 實現方式
Maximum max(a, b) 多項式約束 (c-a)(c-b)=0 + 查表約束（確保 c ≥ a, c ≥ b）
Scaled Exp y = exp(x) · SF 查表實現（指數函數難以多項式近似）
VarDiv Round(numer/denom) Limb 分解處理大數除法；numer=分子、denom=分母

Variable Division 細節

Softmax 需要除以動態計算的分母：
  softmax(xᵢ) = exp(xᵢ) / Σⱼ exp(xⱼ)

VarDiv 使用 limb 分解處理大數：
  1. 將大數分解為多個 limbs（例如每個 16 位）
  2. 對每個 limb 分別驗證
  3. 重新組合得到結果

這避免了在有限域中直接處理超大數值

佈局優化器

優化問題形式化

Halo2 電路可視為 2D 網格，具有以下特性[1]：

  • 儲存格值屬於大質數有限域 Fp
  • 行數必須是 2 的冪次：rows = 2k
  • 三種約束方式：多項式約束、複製約束、查表約束

同一 ML 模型可有多種電路佈局，效能差異可達 24 倍。優化目標：

minimize  C(layout)  // 總成本
subject to:
  rows ≤ 2^k_max      // 行數上限
  memory ≤ M_max      // 記憶體上限
  accuracy ≥ θ        // 準確度門檻

優化器演算法

ZKML 優化器流程：

輸入：TensorFlow 模型 M, 配置約束 C

Phase 1: 生成邏輯佈局
  for each layer L in M:
    gadget_options = enumerate_gadget_choices(L)
    logical_layouts.add(gadget_options)

Phase 2: 生成物理佈局
  for each logical_layout in logical_layouts:
    for k in [k_min, k_max]:  // 變化行數
      physical_layout = place_gadgets(logical_layout, k)
      if satisfies_constraints(physical_layout):
        candidates.add(physical_layout)

Phase 3: 成本估算與選擇
  for each candidate in candidates:
    cost = estimate_cost(candidate)
  return argmin(candidates, key=cost)

輸出：最優電路佈局

成本估算模型

ZKML 成本估算聚焦於四項主要操作[1]：

操作 描述 複雜度
FFT 快速傅立葉變換，多項式運算 O(n log n)
MSM 多標量乘法，橢圓曲線運算 O(n)
Lookup Table 查表建立與驗證 O(n)，其中 n = 2k = rows
Field Ops 有限域元素運算 O(1) 每次

FFT 成本估算公式

C_FFT = n_FFT · t_FFT(k) + n'_FFT · t_FFT(k')

其中：
  k = log₂(rows)           電路行數的對數
  k' = k + log₂(d_max - 1) 擴展大小
  d_max                    約束最大次數
  t_FFT(k)                 大小為 2^k 的 FFT 時間（預先測量）

FFT 數量計算：
  n_FFT = N_i + N_a + 3·N_lk + ⌈(N_pm + d_max - 3)/(d_max - 2)⌉

其中：
  N_i    instance 列數
  N_a    advice 列數
  N_lk   查表數量
  N_pm   置換約束數量

MSM 數量

承諾方案      MSM 數量
KZG          n_FFT + d_max - 1
IPA          n_FFT + d_max

估算準確性

ZKML 使用 Kendall 等級相關係數衡量估算準確性[1]：

後端 Kendall τ 說明
KZG 0.89 高度相關
IPA 0.88 高度相關

這意味著估算器能準確排序不同佈局的相對效能，即使絕對值可能有誤差。

應用場景

可信審計（Trustless Audits）

ML 模型日益強大且訓練於私有資料。ZK-SNARK 允許模型提供者承諾固定模型，並證明輸出確實由該模型產生，實現端到端的可信審計[1]。

範例：OpenAI 未公開 GPT-4 權重；Twitter 推薦系統訓練於用戶私有資料。

隱私生物認證

結合 ZK-SNARK 與認證感測器，可實現無信任的生物識別驗證。用戶拍攝照片後，使用 ML 模型驗證臉部是否匹配先前註冊的身份，同時保護隱私。

無信任信用評分

在區塊鏈場景中，用戶可能需要低抵押貸款。透過 ZK-SNARK 計算並驗證信用評分，借貸雙方都能確保評分計算的誠實性。

限制與未來工作

當前限制

  • 記憶體限制：最大模型（DistilGPT-2）需要 1TB RAM
  • 架構公開：模型架構（非權重）需要公開
  • 固定輸入長度：NLP 模型需要固定長度輸入
  • 不支援分支/迴圈：分支和迴圈會被展開

未來發展方向

  • 更高效的記憶體管理
  • GPU 加速證明生成
  • 更大模型規模支援
  • 與 zkVM 的整合
