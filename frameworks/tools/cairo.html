Cairo

核心概念

Cairo 是 StarkWare 開發的圖靈完備程式語言，專為 STARK 證明系統設計[1]。Cairo 程式編譯為 AIR（Algebraic Intermediate Representation）約束，透過 STARK 生成可驗證的計算證明。Cairo 是 StarkNet L2 的原生語言，也用於 StarkEx 等產品。

概述與生態系統

Cairo 簡介

Cairo（CPU AIR）是第一個為通用可證明計算設計的生產級語言[1]：

Cairo 生態系統：

┌─────────────────────────────────────────────────────────────┐
│                    Cairo 語言                                │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐     │
│  │ .cairo 檔案  │ → │ Sierra/CASM │ → │   AIR 約束   │     │
│  └─────────────┘    └─────────────┘    └─────────────┘     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    STARK 證明系統                            │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐     │
│  │ Cairo VM    │ → │ STARK Prover│ → │   證明驗證   │     │
│  │ 執行軌跡    │    │ (STONE/     │    │ (L1/L2)    │     │
│  │             │    │  Platinum)  │    │             │     │
│  └─────────────┘    └─────────────┘    └─────────────┘     │
└─────────────────────────────────────────────────────────────┘

主要組件：
  - Cairo 編譯器：.cairo → Sierra → CASM
  - Cairo VM：執行 CASM 並生成軌跡
  - STONE/Platinum：STARK 證明器
  - StarkNet：L2 網路

核心優勢

Cairo 的獨特優勢：

1. 透明設置
   - 無需可信設置
   - 任何人可驗證

2. 後量子安全
   - 僅依賴雜湊函數
   - 抵抗量子攻擊

3. 高效擴展
   - 證明大小 O(log n)
   - 驗證時間 O(log n)

4. 通用計算
   - 圖靈完備
   - 支援遞迴

5. 生產就緒
   - StarkNet 主網運行
   - 數十億美元 TVL

版本演進

Cairo 0 vs Cairo 1

特性 Cairo 0 Cairo 1 (當前)
語法風格 Python-like Rust-like
類型系統 弱類型 強類型 + 泛型
記憶體安全 手動管理 自動管理
編譯目標 CASM Sierra → CASM
Gas 計量 無保證 編譯時保證
狀態 維護中 活躍開發

Sierra 中間層

Sierra（Safe Intermediate Representation）：

Cairo 1 編譯流程：
  Cairo → Sierra → CASM → 執行

Sierra 的作用：
  1. 保證程式終止
     - 所有執行路徑都有明確結束
     - 防止無限迴圈

  2. Gas 安全
     - 編譯時計算最大 gas 消耗
     - 防止 DoS 攻擊

  3. 類型安全
     - 強類型系統
     - 編譯時錯誤檢查

  4. 可升級性
     - CASM 可能改變
     - Sierra 提供穩定抽象

資料類型

Cairo 資料類型：

基本類型：
  felt252     # 域元素（0 到 P-1）
  bool        # 布林值
  u8, u16, u32, u64, u128, u256  # 無符號整數
  i8, i16, i32, i64, i128        # 有符號整數

複合類型：
  (T1, T2, ...)  # 元組
  [T; N]         # 固定長度陣列
  Array       # 動態陣列
  Span        # 陣列切片（唯讀）

特殊類型：
  Option      # Some(value) 或 None
  Result   # Ok(value) 或 Err(error)
  Box         # 堆分配指標
  Nullable    # 可為空指標

felt252 說明：
  - 域元素，範圍 [0, P-1]
  - P ≈ 2^251 + 17 * 2^192 + 1
  - 加減乘除都是域運算

// 迴圈
fn sum_array(arr: Span) -> felt252 {
    let mut sum = 0;
    let mut i = 0;
    loop {
        if i >= arr.len() {
            break;
        }
        sum += *arr.at(i);
        i += 1;
    };
    sum
}

// 迭代器（更慣用）
fn sum_array_iter(arr: Span) -> felt252 {
    let mut sum = 0;
    for value in arr {
        sum += *value;
    };
    sum
}

記憶體模型

唯讀記憶體

Cairo 記憶體特性：

1. 唯讀（Immutable）
   - 一旦寫入，不可更改
   - 符合 STARK 證明需求

2. 非確定性
   - 可以「猜測」值
   - 用約束驗證正確性

3. 連續分配
   - 記憶體地址連續
   - 簡化約束

範例：
  // 「修改」實際上是重新分配
  let x = 10;
  let x = x + 1;  // 新的 x，不是修改

  // 陣列操作
  let mut arr = array![1, 2, 3];
  arr.append(4);  // 追加到新位置

Builtins 概覽

Cairo Builtins（高效原語）：

1. range_check
   - 驗證值在 [0, 2^128) 範圍
   - 用於整數運算安全

2. pedersen
   - Pedersen 雜湊函數
   - 用於 Merkle 樹

3. poseidon
   - Poseidon 雜湊函數
   - ZK 友好，效率更高

4. ecdsa
   - ECDSA 簽名驗證
   - 用於帳戶驗證

5. bitwise
   - 位元運算（AND, OR, XOR）
   - 用於位元操作

6. ec_op
   - 橢圓曲線運算
   - 用於加密操作

7. keccak
   - Keccak-256 雜湊
   - 以太坊相容

Cairo VM

虛擬機架構

Cairo VM 組件：

寄存器：
  - pc (Program Counter)：當前指令地址
  - ap (Allocation Pointer)：下一個可用記憶體地址
  - fp (Frame Pointer)：當前函數幀基址

指令格式：
  [op0] op [op1] = [dst]

  其中：
  - op0, op1：運算元
  - op：運算符（+, *, call, jmp, etc.）
  - dst：目標

執行流程：
  1. 讀取 pc 處的指令
  2. 計算運算元值
  3. 執行運算
  4. 寫入結果
  5. 更新 pc, ap
  6. 重複直到 ret

執行軌跡

Cairo 執行軌跡結構：

┌─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ pc  │ ap  │ fp  │ op0 │ op1 │ dst │ ... │
├─────┼─────┼─────┼─────┼─────┼─────┼─────┤
│  0  │ 10  │ 10  │ ... │ ... │ ... │ ... │
│  1  │ 11  │ 10  │ ... │ ... │ ... │ ... │
│  2  │ 12  │ 10  │ ... │ ... │ ... │ ... │
│ ... │ ... │ ... │ ... │ ... │ ... │ ... │
└─────┴─────┴─────┴─────┴─────┴─────┴─────┘

軌跡 → AIR 約束：
  1. 指令解碼約束
  2. 運算元讀取約束
  3. 運算結果約束
  4. 狀態更新約束
  5. 記憶體一致性約束

StarkNet 整合

智能合約

// StarkNet 合約範例

#[starknet::interface]
trait ICounter {
    fn get(self: @TContractState) -> u128;
    fn increment(ref self: TContractState);
}

#[starknet::contract]
mod Counter {
    use starknet::ContractAddress;

    #[storage]
    struct Storage {
        counter: u128,
        owner: ContractAddress,
    }

    #[constructor]
    fn constructor(ref self: ContractState, owner: ContractAddress) {
        self.owner.write(owner);
        self.counter.write(0);
    }

    #[abi(embed_v0)]
    impl CounterImpl of super::ICounter {
        fn get(self: @ContractState) -> u128 {
            self.counter.read()
        }

        fn increment(ref self: ContractState) {
            let current = self.counter.read();
            self.counter.write(current + 1);
        }
    }
}

定點數運算

// Cairo 定點數實現

#[derive(Copy, Drop)]
struct Fixed {
    value: i128,
    scale: u32,  // 小數位數
}

impl FixedArithmetic of Arithmetic {
    fn add(self: Fixed, other: Fixed) -> Fixed {
        assert(self.scale == other.scale, 'Scale mismatch');
        Fixed {
            value: self.value + other.value,
            scale: self.scale,
        }
    }

    fn mul(self: Fixed, other: Fixed) -> Fixed {
        // 乘法後需要縮放
        let result = self.value * other.value;
        let scaled = result / pow(10, self.scale);
        Fixed {
            value: scaled,
            scale: self.scale,
        }
    }
}

// ReLU 實現
fn relu(x: Fixed) -> Fixed {
    if x.value >= 0 {
        x
    } else {
        Fixed { value: 0, scale: x.scale }
    }
}

神經網路範例

// 簡單 MLP 實現

fn fully_connected(
    input: Span,
    weights: Span>,
    bias: Span
) -> Array {
    let mut output = array![];
    let output_size = weights.len();
    let input_size = input.len();

    for i in 0..output_size {
        let mut sum = *bias.at(i);
        let row = *weights.at(i);

        for j in 0..input_size {
            let prod = (*row.at(j)).mul(*input.at(j));
            sum = sum.add(prod);
        };

        output.append(sum);
    };

    output
}

fn mlp_forward(
    input: Span,
    w1: Span>,
    b1: Span,
    w2: Span>,
    b2: Span
) -> Array {
    // 第一層
    let hidden = fully_connected(input, w1, b1);

    // ReLU 激活
    let mut activated = array![];
    for h in hidden.span() {
        activated.append(relu(*h));
    };

    // 第二層
    fully_connected(activated.span(), w2, b2)
}

ZKML 優勢與限制

Cairo 用於 ZKML 的特點：

優勢：
  ✓ 透明設置，無需可信儀式
  ✓ 後量子安全
  ✓ 準線性證明時間
  ✓ StarkNet 原生部署
  ✓ Giza 提供高階抽象

限制：
  ✗ 證明大小較大（~100KB+）
  ✗ 驗證成本較高
  ✗ 生態系統小於 Circom
  ✗ 學習曲線陡峭

適用場景：
  - 中小型模型（<1M 參數）
  - 需要後量子安全
  - StarkNet 生態專案
  - 長期運行的 AI 服務
