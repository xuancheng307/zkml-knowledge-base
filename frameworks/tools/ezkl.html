EZKL

論文來源

本頁內容主要基於 South et al. 於 2024 年發表的 "Verifiable evaluations of machine learning models using zkSNARKs" 論文，以及 EZKL 官方文檔。

概述

EZKL 是一個開源的 ZKML 工具包，能夠將任意機器學習模型轉換為零知識證明電路[1]。其核心創新在於提供了一個通用且靈活的證明系統，支援從 ONNX 格式模型自動生成證明電路，無需針對特定模型架構進行手動優化。

EZKL 基於 Halo2 證明系統構建，採用 PLONKish 算術化方案，特別適合需要可驗證 ML 推理的應用場景，包括：

  • 私有模型的可驗證效能聲明
  • 模型偏差（bias）檢測與驗證
  • 區塊鏈上的可驗證 AI 推理
  • 閉源模型的第三方審計

系統架構

EZKL 的工作流程分為四個主要階段[1]：

1. 證明設定（Proof Setup）

將訓練好的模型轉換為證明電路：

  1. 將模型導出為 ONNX 格式
  2. 將 ONNX 運算轉換為電路約束
  3. 生成證明金鑰（pk）和驗證金鑰（vk）

設定函數形式化為：

$$\text{Setup}(1^\lambda, W, f) \rightarrow (pk, vk)$$

其中 \(\lambda\) 是安全參數，\(W\) 是模型權重，\(f\) 是模型架構。

2. 見證生成（Witness Generation）

對於每個推理輸入 \(x\)，生成見證檔案：

$$(x, f(x, W), H(W))$$

其中 \(H(W)\) 是模型權重的雜湊值，用於後續驗證模型一致性。

3. 證明生成（Prove）

使用見證和證明金鑰生成零知識證明：

$$\text{Prove}(pk, W, x, y) \rightarrow \pi \supset \{H(W), y\}$$

4. 驗證（Verify）

驗證者使用驗證金鑰檢查證明的有效性，確認：

  • 推理計算正確執行
  • 模型權重雜湊與聲明一致
  • 輸出結果未被篡改

核心技術

通用 ONNX 支援

EZKL 的核心優勢是能夠處理任何可表示為 ONNX 計算圖的模型[1]。這是透過將所有 ML 運算歸約為四種基本論證（arguments）實現的：

論證類型 用途 約束形式
累積點積（Cumulative Dot Product） 矩陣乘法、全連接層 \(x_i \cdot y_i + m_i = m_{i+1}\)
累積和/積（Cumulative Sum/Product） 歸約運算 \(x_i \circ m_i = m_{i+1}\)
逐元素運算（Elementwise） 加減乘除 \(x_i \circ y_i = m_i\)
查表論證（Lookup） 非線性函數 logUP 查表

非線性函數處理

EZKL 使用 logUP 查表論證來約束非線性函數（如 ReLU、GELU、Sigmoid）[2]。這比直接在電路中計算非線性函數更加高效。

logUP 優勢

相比原始 Halo2 的查表機制，logUP 基於對數導數的多變量查表方案具有更低的約束開銷。

模型權重雜湊

EZKL 在證明電路中加入模型權重的 ZKG 雜湊計算[3]，確保：

  • 權重保持私密（作為見證輸入）
  • 可驗證使用的是特定模型
  • 防止模型提供者在推理時偷換模型

效能數據

以下是不同模型類型的證明效能數據[1]：

模型 參數量 約束數 證明時間 驗證時間 證明大小

MLP 3.6K 1.9K 0.3s 0.02s 21KB
Small CNN 19.8K 35.8K 3.1s 0.03s 15KB

nanoGPT 250K 9.4M 2781s 2.69s 0.7MB

證明時間隨約束數量線性增長，而約束數量與模型運算量（MACs/FLOPs）成正比。大型模型需要顯著的計算資源。

應用場景

可驗證評估證明（Verifiable Evaluation Attestation）

EZKL 的主要應用是生成可驗證評估證明，證明私有模型在特定基準測試上的表現[1]：

  1. 模型開發者在測試集上執行推理
  2. 為每個推理生成零知識證明
  3. 將證明打包為可驗證評估證明
  4. 發布證明，任何人都可驗證

這解決了閉源模型的信任問題：用戶無需信任開發者的聲明，可以自行驗證模型效能。

推理時模型驗證

在生產環境中，可以使用「預測後證明」（Predict, then Prove）策略[1]：

  1. 模型正常執行推理，立即返回結果
  2. 同時或稍後生成推理證明
  3. 用戶可以驗證使用的模型與聲明一致

這種方法允許在不影響推理延遲的情況下提供可驗證性。

挑戰式審計

用戶可以隨機或選擇性地「挑戰」模型提供者[1]：

  • 要求提供特定推理的證明
  • 驗證模型權重雜湊與已發布的評估證明一致
  • 發現模型提供者偷換模型的行為

證明聚合

對於大型評估數據集，EZKL 提供三種聚合策略[1]：

策略 優點 缺點
簡單打包 計算高效，靈活 暴露所有推理輸出
聚合電路 單一證明驗證所有推理 聚合電路成本高
自定義 Halo2 電路 只暴露聚合指標（如準確率） 需要額外開發

使用流程

EZKL 的典型使用流程：

# 1. 導出模型為 ONNX
python export_model.py --output model.onnx

# 2. 生成設定檔
ezkl gen-settings -M model.onnx

# 3. 校準量化參數
ezkl calibrate-settings -M model.onnx -D calibration_data.json

# 4. 編譯電路
ezkl compile-circuit -M model.onnx -S settings.json

# 5. 設定證明系統
ezkl setup -M model.onnx --pk-path pk.key --vk-path vk.key

# 6. 生成見證
ezkl gen-witness -M model.onnx -D input.json

# 7. 生成證明
ezkl prove --pk-path pk.key --witness witness.json

# 8. 驗證證明
ezkl verify --vk-path vk.key --proof proof.json

限制與挑戰

計算成本

  • 證明時間隨模型規模線性增長
  • 大型模型需要大量 RAM 存放證明金鑰
  • 目前不適合前沿大型語言模型

精度損失

  • 量化引入數值誤差
  • 需要在精度和效能間權衡
  • 部分模型可能因量化導致準確率下降

EVM 相容性

  • Halo2 使用的 Pasta 曲線與 EVM 原生 BN254 不同
  • 需要額外的遞迴包裝或使用 KZG 後端

未來發展

EZKL 團隊正在積極開發的改進包括[1]：

  • 證明分割與並行化：將大模型拆分為多個子證明
  • GPU 加速：利用 GPU 加速多純量乘法
  • 替代證明系統：探索 Nova、Spartan 等更高效的系統
  • 模型優化：設計 ZKP 友好的模型架構
