Noir

核心概念

Noir（法語「黑色」）是由 Aztec Protocol 開發的開源零知識領域專用語言（DSL）[1]。Noir 採用類 Rust 語法設計，專注於提供簡潔、安全且高效的 ZK 電路開發體驗。其核心理念是讓開發者能夠以接近傳統程式設計的方式撰寫 ZK 電路，而無需深入了解底層密碼學細節。

概述與特點

Noir 核心特點

  • 類 Rust 語法：熟悉的現代程式語言風格
  • 後端無關：預設 Barretenberg；ACIR 可轉換至其他 PLONK 類後端，或轉為 R1CS 供其他證明系統使用
  • 強型別系統：編譯時期捕捉約束錯誤
  • 標準庫豐富：內建密碼學原語與常用函數
  • 遞迴證明支援：原生支援證明組合
  • ACIR 中間表示：抽象電路中間表示法

ACIR 中間表示

Definition：ACIR

Abstract Circuit Intermediate Representation (ACIR) 是 Noir 編譯器產生的中間表示格式。ACIR 定義了一組通用的約束原語，可被轉換為不同後端的具體電路格式：

$$\text{ACIR} = \{(\text{opcode}_i, \text{inputs}_i, \text{outputs}_i)\}_{i=1}^{n}$$

每個 opcode 對應一種電路操作，例如算術運算、範圍檢查、雜湊函數等。

ACIR Opcode 功能說明 約束類型
AssertZero 驗證多項式等於零 算術約束
BlackBoxFuncCall 呼叫預定義黑盒函數 專用電路
Brillig 未約束計算區塊 輔助計算
MemoryOp 記憶體讀寫操作 查表約束

約束系統

約束 vs 計算

在 Noir 中，區分約束計算（constrained）與非約束計算（unconstrained）至關重要：

  • 約束計算：產生 ACIR opcodes，在證明中被驗證
  • 非約束計算：僅作為輔助計算，不納入證明

約束與斷言

// assert 創建約束
fn constrained_example(x: Field, y: Field) {
    // 這個斷言會被編譯為電路約束
    assert(x * x + y * y == 25);

    // 等價於要求存在滿足條件的 witness
    // 驗證者會檢查此約束
}

// 範圍約束（隱式）
fn range_constraint(x: u8) {
    // u8 型別自動添加 x < 256 的範圍約束
    let doubled = x * 2;  // 可能溢位，需小心
}

// 明確範圍檢查
fn explicit_range(x: Field) {
    // 使用標準庫進行範圍檢查
    let x_u32: u32 = x as u32;  // 添加 32-bit 範圍約束
    assert(x_u32 < 1000);
}

非約束函數（Brillig）

// 非約束函數 - 不產生電路約束
unconstrained fn compute_hint(x: Field) -> Field {
    // 這段計算不會被證明
    // 用於計算 witness hint
    let mut result = x;
    for _ in 0..100 {
        result = result * result;
    }
    result
}

// 結合約束與非約束計算
fn verified_sqrt(x: Field) -> Field {
    // 步驟 1: 非約束計算 - 找出平方根（hint）
    let sqrt_hint = unsafe {
        compute_sqrt_hint(x)
    };

    // 步驟 2: 約束驗證 - 確認結果正確
    assert(sqrt_hint * sqrt_hint == x);

    sqrt_hint
}

unconstrained fn compute_sqrt_hint(x: Field) -> Field {
    // 使用迭代法計算平方根
    // 這是輔助計算，不進入證明
    x  // 簡化示例
}
安全注意事項
  • 非約束結果必須驗證：使用 unconstrained 計算的 hint 必須透過 assert 確認
  • Prover 可操控 hint：惡意 prover 可提供任意 hint 值
  • 約束完整性：確保所有關鍵邏輯都有對應約束

密碼學原語

use std::hash::{pedersen_hash, poseidon, keccak256, sha256};

fn hash_examples(data: [Field; 2]) {
    // Pedersen Hash - ZK 友好
    let h1 = pedersen_hash(data);

    // Poseidon Hash - 更高效的 ZK 雜湊
    let h2 = poseidon::bn254::hash_2(data);

    // Keccak256 - 以太坊相容
    let preimage: [u8; 32] = [0; 32];
    let h3 = keccak256(preimage, 32);

    // SHA256
    let h4 = sha256(preimage);
}

// Merkle Tree 驗證
fn verify_merkle_proof(
    leaf: Field,
    path: [Field; 32],
    indices: [bool; 32],
    root: Field
) {
    let mut current = leaf;

    for i in 0..32 {
        let (left, right) = if indices[i] {
            (path[i], current)
        } else {
            (current, path[i])
        };
        current = pedersen_hash([left, right]);
    }

    assert(current == root);
}

遞迴證明

遞迴證明概念

Noir 原生支援遞迴證明（Recursive Proofs），允許在電路內部驗證另一個證明。這是實現 zkRollup、證明聚合等應用的關鍵技術。

遞迴驗證核心：

$$\text{verify}(\pi_{\text{inner}}, \text{vk}, \text{public\_inputs}) \rightarrow \{0, 1\}$$

在外層電路中驗證內層證明 \(\pi_{\text{inner}}\) 的有效性。

use std::verify_proof;

// 遞迴驗證器電路
fn recursive_verifier(
    // 內層證明
    proof: [Field; PROOF_SIZE],
    // 驗證金鑰
    verification_key: [Field; VK_SIZE],
    // 內層公開輸入
    public_inputs: [Field; NUM_PUBLIC_INPUTS],
    // 新的計算
    additional_input: Field
) -> pub Field {
    // 步驟 1: 驗證內層證明
    assert(verify_proof(
        verification_key,
        proof,
        public_inputs
    ));

    // 步驟 2: 基於驗證結果進行額外計算
    let inner_output = public_inputs[0];
    let combined_result = inner_output + additional_input;

    combined_result
}

// 證明聚合
fn aggregate_proofs(
    proof1: [Field; PROOF_SIZE],
    proof2: [Field; PROOF_SIZE],
    vk: [Field; VK_SIZE],
    inputs1: [Field; N],
    inputs2: [Field; N]
) -> pub Field {
    // 驗證兩個獨立證明
    assert(verify_proof(vk, proof1, inputs1));
    assert(verify_proof(vk, proof2, inputs2));

    // 聚合結果
    inputs1[0] + inputs2[0]
}

遞迴證明應用

  • zkRollup：將多筆交易證明聚合為單一證明
  • IVC（增量驗證計算）：持續累積計算的正確性證明
  • 跨鏈橋：在目標鏈驗證源鏈的共識證明
  • 隱私協議：組合多個隱私證明

應用範例

隱私投票系統

use std::hash::pedersen_hash;

// 投票電路
fn main(
    // 私密輸入
    voter_secret: Field,           // 選民秘密
    vote_option: u8,               // 投票選項 (0 或 1)
    merkle_path: [Field; 20],      // Merkle 路徑
    merkle_indices: [bool; 20],    // 路徑方向

    // 公開輸入
    nullifier_hash: pub Field,     // 防重複投票
    merkle_root: pub Field,        // 選民名單根
    vote_commitment: pub Field     // 投票承諾
) {
    // 1. 驗證選民身份（在 Merkle 樹中）
    let voter_leaf = pedersen_hash([voter_secret]);
    let mut current = voter_leaf;

    for i in 0..20 {
        let (left, right) = if merkle_indices[i] {
            (merkle_path[i], current)
        } else {
            (current, merkle_path[i])
        };
        current = pedersen_hash([left, right]);
    }
    assert(current == merkle_root);

    // 2. 驗證 nullifier（防重複投票）
    let computed_nullifier = pedersen_hash([voter_secret, 1]);
    assert(computed_nullifier == nullifier_hash);

    // 3. 驗證投票有效（0 或 1）
    assert((vote_option == 0) | (vote_option == 1));

    // 4. 驗證投票承諾
    let computed_commitment = pedersen_hash([voter_secret, vote_option as Field]);
    assert(computed_commitment == vote_commitment);
}

隱私代幣轉帳

use std::hash::poseidon;

struct Note {
    owner: Field,      // 所有者公鑰
    amount: Field,     // 金額
    salt: Field,       // 隨機鹽值
}

impl Note {
    fn commitment(self) -> Field {
        poseidon::bn254::hash_3([self.owner, self.amount, self.salt])
    }

    fn nullifier(self, secret_key: Field) -> Field {
        poseidon::bn254::hash_2([self.commitment(), secret_key])
    }
}

// 隱私轉帳電路
fn transfer(
    // 輸入 note（私密）
    input_note: Note,
    input_secret_key: Field,
    input_merkle_path: [Field; 32],
    input_merkle_indices: [bool; 32],

    // 輸出 notes（私密）
    output_note_1: Note,
    output_note_2: Note,  // 找零

    // 公開輸入
    input_nullifier: pub Field,
    output_commitment_1: pub Field,
    output_commitment_2: pub Field,
    merkle_root: pub Field
) {
    // 1. 驗證輸入 note 存在於樹中
    let input_commitment = input_note.commitment();
    let mut current = input_commitment;

    for i in 0..32 {
        let (left, right) = if input_merkle_indices[i] {
            (input_merkle_path[i], current)
        } else {
            (current, input_merkle_path[i])
        };
        current = poseidon::bn254::hash_2([left, right]);
    }
    assert(current == merkle_root);

    // 2. 驗證所有權
    let owner_pubkey = poseidon::bn254::hash_1([input_secret_key]);
    assert(owner_pubkey == input_note.owner);

    // 3. 驗證 nullifier
    let computed_nullifier = input_note.nullifier(input_secret_key);
    assert(computed_nullifier == input_nullifier);

    // 4. 驗證金額守恆
    assert(input_note.amount == output_note_1.amount + output_note_2.amount);

    // 5. 驗證輸出承諾
    assert(output_note_1.commitment() == output_commitment_1);
    assert(output_note_2.commitment() == output_commitment_2);
}

Aztec.nr 合約範例

// Aztec.nr 私密代幣合約（簡化示例）
contract PrivateToken {
    use dep::aztec::prelude::{
        AztecAddress, FunctionSelector, NoteHeader, NoteInterface,
        PrivateContext, PublicContext, Map, PublicMutable, PrivateSet
    };

    // 狀態
    struct Storage {
        balances: Map>,
        total_supply: PublicMutable,
    }

    // 私密轉帳函數
    #[aztec(private)]
    fn transfer(
        &mut self,
        from: AztecAddress,
        to: AztecAddress,
        amount: Field
    ) {
        // 從發送者銷毀 note
        let sender_notes = storage.balances.at(from);
        let notes = sender_notes.get_notes(NoteGetterOptions::new());

        // 驗證餘額足夠並創建新 notes
        let change = notes.sum() - amount;
        assert(change >= 0);

        // 創建收款者 note
        let recipient_notes = storage.balances.at(to);
        recipient_notes.insert(TokenNote::new(amount, to));

        // 創建找零 note
        if change > 0 {
            sender_notes.insert(TokenNote::new(change, from));
        }
    }

    // 公開鑄造函數
    #[aztec(public)]
    fn mint_public(
        &mut self,
        to: AztecAddress,
        amount: Field
    ) {
        storage.total_supply.write(
            storage.total_supply.read() + amount
        );
    }
}

// 定點數精度
global SCALE: Field = 1000;  // 3 位小數

// ReLU 激活函數
fn relu(x: Field) -> Field {
    // 使用 unconstrained 判斷符號
    let is_positive = unsafe { x_is_positive_hint(x) };

    // 約束驗證
    if is_positive {
        x
    } else {
        0
    }
}

unconstrained fn x_is_positive_hint(x: Field) -> bool {
    // 非約束判斷（簡化示例）
    true
}

// 兩層 MLP
fn mlp_forward(
    input: [Field; 4],
    weights_1: [[Field; 4]; 8],   // 4x8
    bias_1: [Field; 8],
    weights_2: [[Field; 8]; 2],   // 8x2
    bias_2: [Field; 2]
) -> [Field; 2] {
    // 第一層
    let mut hidden = [0; 8];
    for i in 0..8 {
        let mut sum: Field = 0;
        for j in 0..4 {
            sum += input[j] * weights_1[i][j];
        }
        sum = sum / SCALE + bias_1[i];
        hidden[i] = relu(sum);
    }

    // 第二層
    let mut output = [0; 2];
    for i in 0..2 {
        let mut sum: Field = 0;
        for j in 0..8 {
            sum += hidden[j] * weights_2[i][j];
        }
        output[i] = sum / SCALE + bias_2[i];
    }

    output
}

// 主電路：驗證推理結果
fn main(
    // 私密輸入
    input: [Field; 4],
    weights_1: [[Field; 4]; 8],
    bias_1: [Field; 8],
    weights_2: [[Field; 8]; 2],
    bias_2: [Field; 2],

    // 公開輸入
    expected_output: pub [Field; 2],
    model_hash: pub Field
) {
    // 執行推理
    let output = mlp_forward(input, weights_1, bias_1, weights_2, bias_2);

    // 驗證輸出
    assert(output[0] == expected_output[0]);
    assert(output[1] == expected_output[1]);
}
ZKML 開發注意事項
  • 電路大小：大型模型需要分層處理，單一電路有限制
  • 精度損失：定點數轉換需仔細處理累積誤差
  • 開發成本：目前需手動實現 ML 算子
  • 效能優化：需針對 PLONKish 約束系統優化
