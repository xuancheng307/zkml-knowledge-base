核心發現

最重要發現

ZKLoRA 的校準機制是驗證成功的必要條件。直接使用 ezkl 會導致 100% 驗證失敗，錯誤訊息為「constraint system not satisfied」。這證明 ZKLoRA 不僅是便利工具，更是技術上的必要條件。

1ZKLoRA 校準是必要的

實驗四證明，直接使用 ezkl 進行 LoRA 驗證會 100% 失敗。ZKLoRA 的校準機制負責：

  • 調整量化參數確保數值精度
  • 設定適當的 scale 值避免溢位
  • 確保電路約束可被滿足

結論：ZKLoRA 框架是成功驗證的技術必要條件，而非單純的便利工具。

2Rank 參數不影響證明時間

實驗一發現，當 LoRA rank 從 8 增加到 64（參數量增加 8 倍）時，證明時間僅增加 1.7%。

  • Rank 8 (147K 參數): 541 秒
  • Rank 64 (1.18M 參數): 550 秒

結論：電路 setup 時間主導證明時間，可自由選擇高 rank 以獲得更好的模型品質。

3線性擴展支援並行化

實驗二、三證明，證明時間與層數呈線性關係：

Ttotal ≈ 130 × L + C（L = 層數）

  • 每層的證明可獨立生成
  • 使用 N 個 CPU 核心可將時間降至約 1/N
  • Setup 階段可預計算並快取（節省 48% 時間）

4記憶體是主要瓶頸

實驗八發現，Proving Key (PK) 大小是主要的記憶體限制：

  • hidden=768, rank=8: PK ≈ 5.4GB
  • hidden=2048, rank=128: PK ≈ 12.8GB

結論：大規模模型需要分散式證明架構，而非單純增加計算時間。

系統比較：ezkl vs RISC Zero

重要說明

ezkl 與 RISC Zero 產生不同大小的證明（1.76MB vs 0.19MB），因此不能單純比較速度。以下比較著重於各系統的特性與適用場景。

系統類型證明時間證明大小硬體需求
ezkl (Halo2)ML 專用電路75.5s1.76MBCPU
RISC Zero (GPU)通用 zkVM59.0s0.19MBCUDA GPU
RISC Zero (CPU)通用 zkVM589.8s0.19MBCPU

ezkl (Halo2)

  • ML 專用電路，針對矩陣運算優化
  • 證明較大（1.76MB）
  • 純 CPU 即可高效運行
  • 無需可信設置（transparent setup）

適用：純 CPU 環境、ML 專用任務、離線驗證

RISC Zero (STARK)

  • 通用 zkVM，可執行任意程式
  • 證明較小（0.19MB），約為 ezkl 的 1/9
  • 需要 GPU 才能達到合理效能
  • 支援遞迴證明組合

適用：有 GPU、需要小證明（如上鏈）、通用計算
