模型到電路轉換

論文章節

本頁內容主要整理自 ZKML (EuroSys 2024) 論文 §3「Gadgets」與 §4「電路優化」，並整合 ZKTorch、zkCNN 等框架的轉換方法。

概述

將機器學習模型轉換為零知識證明電路是 ZKML 系統的核心步驟。此過程涉及將高階 ML 運算（如卷積、矩陣乘法、激活函數）分解為低階的算術約束，使其可在有限域 \(\mathbb{F}_p\) 上執行並被 ZK-SNARK 系統證明[1]。

轉換過程面臨的主要挑戰包括：

  • 浮點數轉換：ML 使用浮點數，但 ZK 電路在有限域上運算
  • 非線性函數處理：激活函數無法直接用多項式約束表示
  • 電路規模爆炸：大型模型可能產生數十億約束
  • 效能與精度權衡：不同轉換策略影響證明時間和模型準確率

轉換流程概覽

典型的模型到電路轉換流程如下[1][2]：

  1. 模型匯出：將訓練好的模型匯出為 ONNX 或其他中間表示
  2. 量化：將浮點權重和激活值轉換為定點數表示
  3. 算符分解：將 ML 層分解為基礎運算（gadgets / basic blocks）
  4. 約束生成：為每個基礎運算生成多項式約束
  5. 電路佈局優化：選擇最佳的電路配置以最小化證明成本

電路結構：PLONKish 模型

在 halo2 等 PLONKish 證明系統中，電路被表示為一個二維網格[1]：

組件 說明 約束
儲存格（Cells） 網格中的每個位置，儲存有限域 \(\mathbb{F}_p\) 中的值 -
列（Columns） 分為 advice（見證值）、instance（公開輸入）、selector（選擇器） -
行（Rows） 行數必須是 2 的冪次，即 \(2^k\) k = logrows
多項式約束 強制某行的儲存格滿足多項式等式 Custom Gates
複製約束 強制兩個儲存格值相等 Copy Constraints
查表約束 強制某行模式存在於預定義的表中 Lookup Constraints

Gadgets 分類（ZKML）

ZKML 系統將 ML 運算分解為四大類 gadgets[1]：

1. 形狀運算（Shape Operations）

形狀運算包括 reshape、slice、concat、transpose 等。這些運算的特點是不需要分配新的儲存格——張量可以持有對先前已分配儲存格的引用，因此在證明時間上「免費」。

零成本抽象

由於形狀運算只是重新詮釋現有數據的佈局，不涉及實際計算，因此不產生額外約束。這是 ZKML 相較傳統電路表示的重要優化。

注意：此「零成本」特性是 ZKML、EZKL 等專用框架的設計優化。在 Circom 等通用電路描述語言中，reshape/concat 可能需要顯式複製約束，依實作方式而異。

2. 算術運算（Arithmetic Operations）

基本算術運算及其約束形式：

Gadget 運算 約束形式 儲存格數
Add(x, y) \(x + y\) \(x + y - z = 0\) 3
Mul(x, y) \(x \cdot y\) \(x \cdot y - z = 0\) 3
Div(x, y) \(\lfloor x/y \rfloor\) \(x = q \cdot y + r\)，需：(1) range check \(r \in [0, y)\)；(2) \(y \neq 0\)；(3) \(x, y\) 在合法整數範圍內 4+
DivRound(x, y) \(\text{round}(x/y)\) 等價式：\(\text{round}(x/y) = \lfloor (2x + y) / (2y) \rfloor\)，轉為一次 Div + 額外 range 約束 5
Square(x) \(x^2\) \(x \cdot x - z = 0\) 2
DotProd(x, y) \(\mathbf{x} \cdot \mathbf{y}\) 累積乘積約束 n+1

3. 逐點非線性（Pointwise Non-linearities）

激活函數如 ReLU、ELU、Sigmoid、Tanh 等難以用低次多項式約束表示。ZKML 提供兩種實現方式[1]：

方式一：位元分解

以 ReLU 為例，\(\text{ReLU}(x) = \max(x, 0)\)：

  1. 將輸入 \(x\) 分解為 \(b\) 個位元
  2. 檢查最高位（符號位）判斷正負
  3. 根據符號位選擇輸出 \(x\) 或 \(0\)

此方法需要 \(b + 2\) 個儲存格，適合 ReLU 操作數量較少的情況。

方式二：查表（Lookup Table）

預先計算非線性函數的輸入-輸出對，建立查表：

  • 表大小：\(2^b\) 行，其中 \(b\) 是輸入的總位元數（fixed-point 表示）
  • 約束：驗證 (input, output) 對存在於表中
  • 優點：每次操作僅需 2 個儲存格
  • 缺點：表大小受限於電路總行數（rows = \(2^k\)）
可行性條件

若電路行數為 \(2^k\)，ReLU lookup table 需要 \(2^b\) 行。要能容納此表，必須滿足 \(2^b \leq 2^k\)，即 \(b \leq k\)。例如 \(k = 17\)（logrows）時，最多支援 \(b = 17\) 位元的 ReLU 查表。

關鍵洞察

最佳實現方式取決於模型中非線性操作的全域分布。若只執行少量 ReLU，位元分解可能更高效；若執行數百萬次 ReLU，查表更划算。ZKML 優化器會自動選擇最佳策略[1]。

4. 特化運算（Specialized Operations）

某些 ML 運算需要專門設計的 gadgets[1]：

Maximum（最大值）

計算 \(\max(a, b)\)，使用以下約束組合：

  1. 選擇約束：\((c - a)(c - b) = 0\)（確保 \(c\) 等於 \(a\) 或 \(b\)）
  2. Range 約束：透過 lookup / range table 證明 \((c - a) \in [0, \ldots, N)\) 且 \((c - b) \in [0, \ldots, N)\)（確保 \(c \geq a\) 且 \(c \geq b\)）

其中 \(N\) 為值域上界（如 \(2^{16}\)），由電路的 range table 決定。

Scaled Exponentiation（縮放指數）

計算 \(y = \exp(x) \cdot \text{SF}\)，其中 SF 為縮放因子。使用查表實現，因為指數函數難以用多項式近似。

Variable Division（變數除法）

Softmax 需要除以動態計算的分母。VarDiv gadget 必須在 ZK 電路中正確模擬整數除法語義：

論文記號對應

ZKML 原論文定義 VarDiv(a, b) = Round(b/a)，其中 \(a, b \in [0, \ldots, N)\)。本頁採用更直覺的命名：令 a ≡ denom、b ≡ numer，因此 VarDiv(denom, numer) = Round(numer/denom)。兩者語義等價。

Floor 除法（最常用）

計算 \(q = \lfloor \text{numer}/\text{denom} \rfloor\)：

約束模板：
  見證：q（商）, r（餘數）

  約束 1：numer = q × denom + r（除法定義）
  約束 2：0 ≤ r < denom（餘數範圍，透過 range check）
  約束 3：denom ≠ 0（除數非零）
  約束 4：q ≥ 0, denom > 0（Softmax 分母恆正）

  boundedness 要求：
    - numer, denom 必須在合法整數範圍內（如 < 2^64）
    - 避免域取模造成語義漂移
    - 需配合 range check 確保所有值在預期範圍
Round-to-nearest 除法

若需四捨五入語義 \(q = \text{round}(\text{numer}/\text{denom})\)：

約束模板：
  見證：q（商）, r（調整後餘數）

  約束：numer = q × denom + r 且 -denom/2 ≤ r < denom/2

  實作技巧：
    q = floor((numer + denom/2) / denom)
    注意 denom/2 的整數化（奇數 denom 需特殊處理）
    tie-break 規則需明確定義（如 ties-to-even）

以 Softmax 為例，計算 \(\exp(x_i) / \sum_j \exp(x_j)\) 時，分子為 \(\exp(x_i)\)，分母為動態計算的總和（恆正），因此 \(\text{denom} > 0\) 前提成立。對於大數情況，可使用 limb 分解處理：將大數分解為多個較小的 limbs，分別驗證除法正確性。

與 fixed-point 的關聯

VarDiv 的截斷語義對應 定點數頁面 的 Option B（見證 q, r 並證明 \(z = q \times 2^s + r\) 且 \(0 \leq r < 2^s\)）。兩者共用相同的可證明語義，確保整數截斷而非域除法。

Basic Blocks 架構（ZKTorch）

ZKTorch 採用不同的抽象方式，定義 20 種基礎區塊（basic blocks）來覆蓋 ML 運算[2]：

類別 基礎區塊 支援平行累積
算術運算 Add, Sub, Mul, MulConst, MulScalar, Sum, Div, Mod 部分
布林運算 BooleanCheck, Eq Eq
最大值 MaxProof 否
形狀運算 Concat, CopyConstraint, Permute 部分
查表 CQ, CQ2 是
矩陣乘法 CQLin, MatMul 是
排序檢查 OneToOne, Ordered 否

ZKTorch 的編譯器將 ML 層自動轉譯為 basic blocks 的組合。其中 13 種 blocks 支援平行累積，可利用二元樹式平行歸約（parallel tree reduction，基於 Mira accumulation scheme 的平行延伸）實現 \(O(\log N)\) 深度的證明組合[2]。注意：此處 \(O(\log N)\) 指的是樹深度（可平行化的關鍵路徑），總計算工作量仍為 \(O(N)\)。

Sumcheck 協議（zkCNN）

zkCNN 採用完全不同的方法：使用 sumcheck 協議直接證明卷積運算[3]。

GKR 協議

zkCNN 基於 GKR（Goldwasser-Kalai-Rothblum）協議，適用於分層算術電路：

  1. 將 ML 模型表示為分層電路，每層的輸出是下一層的輸入
  2. 使用 sumcheck 協議從輸出層向輸入層遞歸驗證
  3. 最終驗證歸約為對輸入層的簡單檢查

多線性擴展（Multilinear Extension）

向量 \(\mathbf{v} \in \mathbb{F}^n\) 的多線性擴展定義為：

$$\tilde{V}(x_1, \ldots, x_{\log n}) = \sum_{b \in \{0,1\}^{\log n}} v_b \cdot \prod_{i=1}^{\log n} (x_i \cdot b_i + (1-x_i)(1-b_i))$$

這種表示允許使用 sumcheck 協議高效驗證向量運算。

卷積證明

zkCNN 將 2D 卷積轉換為兩個 1D 卷積的組合，使用 FFT 在頻域中計算，然後通過 sumcheck 驗證：

$$\text{Conv2D}(X, K) = \text{iFFT}(\text{FFT}(X) \odot \text{FFT}(K))$$

這種方法的證明大小為 \(O(\log n)\)，驗證時間為 \(O(n)\)[3]。

全連接層（FullyConnected）

矩陣乘法 \(\mathbf{y} = \mathbf{W}\mathbf{x} + \mathbf{b}\) 的轉換[1]：

  • 分解為多個 DotProd gadgets
  • 每行對應一個輸出神經元
  • 偏差向量使用 Add gadgets

Pooling 層

  • Max Pooling：使用 Maximum gadgets
  • Average Pooling：使用 Sum + DivRound gadgets
  • Global Pooling：對整個特徵圖執行上述操作

Batch Normalization

在推理時將 BatchNorm 摺疊（fold）入前一層[4]：

$$w_{\text{fold}} = \frac{\gamma \cdot w}{\sqrt{\sigma_B^2 + \epsilon}}, \quad b_{\text{fold}} = \frac{\gamma (b - \mu_B)}{\sqrt{\sigma_B^2 + \epsilon}} + \beta$$

這避免了在 ZK 電路中實現除法和平方根。

電路優化策略

1. 電路佈局選擇

同一運算可有多種電路佈局。ZKML 優化器評估所有可能的佈局並選擇最優[1]：

優化目標 策略 影響
最小化證明時間 增加列數、減少行數 證明大小可能增加
最小化證明大小 固定最小列數 證明時間可能增加
最小化記憶體 減少 logrows 可能無法容納模型

2. 圖形轉換規則（ZKTorch）

ZKTorch 實現 7 種圖形轉換規則以降低證明開銷[2]：

規則 適用模型 效果
GeLU GPT-j CQ 數量從 6 降至 1
CustomCNN ResNet, 3D-UNet 消除形狀運算開銷
MultiHeadMatMul GPT-j 消除複製約束
RoPE GPT-j 消除複製約束
ReshapeTrans BERT Permute 從 2 降至 1

3. 成本估算模型

ZKML 使用成本估算模型快速評估配置，避免實際證明[1]：

$$C_{\text{total}} = C_{\text{FFT}} + C_{\text{MSM}} + C_{\text{lookup}} + C_{\text{field}}$$

估算器的 Kendall 等級相關係數達 0.89（KZG）和 0.88（IPA），能準確排序不同佈局的效能。
