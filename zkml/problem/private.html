隱私推理

核心概念

隱私推理（Private Inference）是 ZKML 的另一主要範式，目標是在不洩露敏感數據的前提下進行 ML 推理，並可選地證明推理結果的正確性[1]。

問題定義

隱私挑戰

場景：用戶想使用 ML 服務但不想洩露數據

傳統模式：
  用戶 → 發送原始數據 → [雲端模型] → 結果
  問題：服務商看到所有用戶數據

隱私風險：
  1. 醫療數據洩露
  2. 財務資訊曝光
  3. 生物識別資料濫用
  4. 敏感文件內容外流

隱私推理目標：
  服務商執行推理，但學不到用戶數據

保護對象

保護對象 範例 技術
輸入隱私 醫療影像、交易記錄 ZKP / MPC
模型隱私 專有算法、訓練數據 ZKP / TEE
輸出隱私 診斷結果、信用評分 加密 / ZKP

技術方案

純 ZKP 方案

方案：用戶本地計算 + ZKP 證明

流程：
  1. 用戶獲取（加密的）模型
  2. 用戶本地執行推理
  3. 用戶生成 ZKP 證明推理正確
  4. 提交輸出 + 證明

優點：
  - 數據完全不離開用戶
  - 密碼學安全保證

缺點：
  - 用戶需要計算資源
  - 模型可能需要保密處理

MPC 結合方案

方案：多方安全計算

流程：
  1. 用戶秘密分享輸入
  2. 多方共同計算推理
  3. 用戶獲得結果（或秘密分享）

優點：
  - 計算負擔分散
  - 可處理更大模型

缺點：
  - 需要多方參與
  - 通訊開銷大

TEE 結合方案

方案：可信執行環境

流程：
  1. 用戶發送加密數據到 TEE
  2. TEE 內解密並執行推理
  3. 加密結果返回用戶
  4. （可選）ZKP 證明 TEE 正確執行

優點：
  - 效能接近原生
  - 成熟技術

缺點：
  - 依賴硬體信任
  - 側信道攻擊風險

ZKP 隱私推理詳解

電路設計

隱私推理電路結構：

公開輸入：
  - 模型承諾 C_M
  - 輸入承諾 C_x（非原始輸入！）
  - 輸出 y

私密見證：
  - 輸入 x
  - 輸入隨機性 r_x
  - 模型權重 W（若需保密）

電路約束：
  1. Commit(x, r_x) = C_x（輸入承諾正確）
  2. Commit(W) = C_M（模型承諾正確）
  3. M(x) = y（推理正確）

ZK Relation 形式化

隱私推理的 ZK Relation 與可驗證推理的關鍵區別在於輸入也被承諾隱藏：

Relation 定義

$$R_{private}((C_x, y, C_M); (x, r_x, W, \text{aux})) = 1$$

當且僅當：

  1. \(\text{Commit}(x, r_x) = C_x\)（輸入承諾一致性）
  2. \(\text{Commit}(W) = C_M\)（模型承諾一致性）
  3. \(f_{quant}(\text{Quant}(x); W) = y_q\)（量化推理正確）
  4. \(y = \text{Dequant}(y_q)\)（輸出反量化）
符號 類型 說明
\(C_x\) 公開輸入 輸入的密碼學承諾（隱藏原始輸入）
\(y\) 公開輸入 推理輸出（或輸出承諾 \(C_y\)）
\(C_M\) 公開輸入 模型權重的密碼學承諾
\(x\) 私密見證 原始輸入（醫療影像、財務資料等）
\(r_x\) 私密見證 輸入承諾的隨機性
\(W\) 私密見證 模型權重
aux 私密見證 中間激活值等輔助資料
與可驗證推理的對比
項目可驗證推理 \(R_{verify}\)隱私推理 \(R_{private}\)
輸入公開 \(x\)隱藏（承諾 \(C_x\)）
輸出公開 \(y\)公開 \(y\) 或承諾
模型承諾 \(C_M\)承諾 \(C_M\)
見證大小\(|W| + |\text{aux}|\)\(|x| + |r_x| + |W| + |\text{aux}|\)

承諾方案選擇

輸入承諾選項：

Pedersen 承諾：
  C = g^x · h^r
  優點：加法同態
  缺點：只能承諾單一值

向量承諾：
  C = Commit(x_1, ..., x_n)
  適用：高維輸入

雜湊承諾：
  C = Hash(x || r)
  優點：簡單高效
  缺點：無同態性質

應用場景

醫療 AI

場景：遠程醫療診斷

問題：
  患者不想洩露醫療影像
  但需要專業 AI 診斷

解決方案：
  1. 患者本地持有醫療影像
  2. 使用隱私推理執行診斷模型
  3. 生成證明（可選：給保險公司驗證）

隱私保護：
  - 醫院/雲端不看到原始影像
  - 診斷結果可選擇性披露

金融信用評估

場景：隱私保護的信用評分

問題：
  用戶不想洩露完整財務資訊
  但需要獲得信用評估

解決方案：
  1. 用戶提供財務數據的承諾
  2. 證明數據滿足某些條件
  3. 機構驗證證明即可

範例：
  證明「收入 > 閾值」而非揭示實際收入
  證明「無不良記錄」而非揭示記錄詳情

生物識別

場景：隱私人臉識別

問題：
  用戶不想洩露生物特徵
  但需要身份驗證

解決方案：
  1. 用戶持有加密的人臉特徵
  2. 本地執行特徵匹配
  3. 證明匹配成功（無需揭示特徵）

安全性：
  - 即使資料庫洩露，攻擊者無法獲得原始特徵
  - 每次驗證不累積資訊

效能與權衡

成本比較

方案 計算成本 通訊成本 信任假設
純 ZKP 高（證明生成） 低 密碼學
MPC 中 高 誠實多數
TEE 低 低 硬體
ZKP + TEE 中 低 混合

隱私級別

隱私級別選擇：

完全隱私：
  - 輸入、輸出、模型全部隱藏
  - 成本最高
  - 適用：高敏感場景

部分隱私：
  - 隱藏輸入，公開輸出
  - 成本較低
  - 適用：一般隱私需求

可選隱私：
  - 用戶選擇揭示程度
  - 靈活配置
  - 適用：多場景

與可驗證推理的結合

完整隱私可驗證推理：

目標：
  1. 保護用戶數據隱私
  2. 證明推理正確性

實現：
  公開：模型承諾、輸入承諾、輸出
  證明：輸入符合承諾 ∧ 推理正確

應用：
  用戶可向第三方（如保險公司）
  證明「使用特定模型對我的數據分析得到此結果」
  而不洩露原始數據
