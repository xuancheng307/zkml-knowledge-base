可驗證推理

核心概念

可驗證推理（Verifiable Inference）是 ZKML 的主要應用範式，目標是證明「特定輸入經過特定模型確實產生特定輸出」，確保 ML 推理的正確性可被第三方驗證[1]。

問題定義

信任問題

場景：用戶使用雲端 ML 服務

傳統模式：
  用戶 → 輸入 → [雲端模型] → 輸出 → 用戶
  問題：用戶無法驗證服務商確實使用聲稱的模型

潛在風險：
  1. 使用更便宜的小模型
  2. 使用過時的模型版本
  3. 針對特定用戶修改輸出
  4. 完全偽造輸出

可驗證推理目標：
  用戶能確認輸出確實來自正確的計算過程

形式化定義

可驗證推理協議：

公開資訊：
  - 模型承諾 C_M（或完整模型）
  - 輸入 x
  - 輸出 y

證明者生成：
  π ← Prove(M, x, y)

驗證者檢查：
  Verify(C_M, x, y, π) → {accept, reject}

安全性質：
  完備性：正確計算總能通過驗證
  可靠性：錯誤結果無法通過驗證

ZK Relation 形式化

可驗證推理的 ZK Relation 定義如下：

Relation 定義

$$R_{verify}((x, y, C_M); (W, \text{aux})) = 1$$

當且僅當：

  1. \(\text{Commit}(W) = C_M\)（模型承諾一致性）
  2. \(f_{quant}(\text{Quant}(x); W) = y_q\)（量化推理正確）
  3. \(y = \text{Dequant}(y_q)\)（輸出反量化）
符號 類型 說明
\(x\) 公開輸入 模型輸入（影像、文字等）
\(y\) 公開輸入 推理輸出
\(C_M\) 公開輸入 模型權重的密碼學承諾
\(W\) 私密見證 模型權重（量化後的整數表示）
aux 私密見證 中間激活值、量化參數等輔助資料

安全性意涵：驗證者只需知道 \((x, y, C_M)\) 即可驗證，無需取得模型權重 \(W\)。這使得模型可保持私密，同時推理結果可被公開驗證。

技術實現

模型承諾

為何需要模型承諾：

問題：完整模型太大無法上鏈
解決：使用密碼學承諾

承諾方案：
  C_M = Hash(M) 或
  C_M = Commit(flatten(weights))

驗證關係：
  證明「存在 M 使得 Commit(M) = C_M 且 M(x) = y」

實務配置（EZKL）：
  // 生成模型承諾
  ezkl gen-witness --model model.onnx

  // 承諾包含在 verification key 中

電路設計

可驗證推理電路結構：

公開輸入：
  - 模型承諾 C_M
  - 輸入 x
  - 輸出 y

私密見證：
  - 模型權重 W（若模型需保密）
  - 中間激活值

電路約束：
  1. Commit(W) = C_M（承諾一致性）
  2. layer_1(x) = a_1（第一層計算）
  3. layer_2(a_1) = a_2（第二層計算）
  ...
  n. layer_n(a_{n-1}) = y（輸出匹配）

應用場景

雲端 ML 驗證

場景：企業使用雲端 AI 服務

流程：
  1. 服務商公布模型承諾
  2. 用戶提交推理請求
  3. 服務商返回結果 + 證明
  4. 用戶驗證證明

價值：
  - 確保服務品質（使用正確模型）
  - 責任歸屬（可審計）
  - 合規要求（如金融 AI）

區塊鏈應用

鏈上 AI 決策：

流程：
  1. 智能合約存儲模型承諾
  2. 鏈下執行 ML 推理
  3. 提交結果 + ZK 證明
  4. 合約驗證並執行

應用案例：
  - 預言機驗證
  - DAO 自動決策
  - 鏈上遊戲 AI
  - DeFi 風險評估

合規審計

監管合規：

需求：
  證明 AI 系統使用經批准的模型
  不需要公開模型細節

實現：
  1. 監管機構審核並簽署模型承諾
  2. 企業使用該模型進行推理
  3. 產生可驗證證明
  4. 審計時驗證證明匹配已批准承諾

效能考量

證明生成成本

模型規模 證明時間 記憶體 適用場景
小型（<1M 參數） 秒級 ~4 GB 即時驗證
中型（1-10M） 分鐘級 ~16 GB 批次驗證
大型（>100M） 小時級 ~64 GB+ 離線驗證

驗證成本

驗證是輕量的：

典型驗證時間：~10 ms
典型證明大小：~10-50 KB
鏈上驗證 gas：~300K-500K

適合：
  - 鏈上驗證
  - 大量用戶驗證同一證明
  - 資源受限設備

與隱私推理的區別

面向 可驗證推理 隱私推理
主要目標 正確性證明 數據保密
隱藏內容 模型權重（可選） 輸入數據
典型用戶 服務消費者 數據擁有者
信任假設 不信任服務商 不信任模型商

實務指南

EZKL 實現

# 1. 準備模型
ezkl gen-settings --model model.onnx

# 2. 校準（選擇量化參數）
ezkl calibrate --model model.onnx --data calibration.json

# 3. 生成電路
ezkl compile-circuit --model model.onnx

# 4. 設置（生成驗證密鑰）
ezkl setup --model model.onnx

# 5. 證明
ezkl prove --model model.onnx --input input.json

# 6. 驗證
ezkl verify --proof proof.json --vk vk.json
