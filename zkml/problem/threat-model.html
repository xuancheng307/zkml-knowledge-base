威脅模型與安全目標

安全基礎

理解 ZKML 的威脅模型是正確應用這項技術的基礎。本頁面定義 ZKML 系統中的參與者、攻擊者能力、以及系統需要達成的安全目標。

參與者角色

核心角色

角色 描述 持有資源
證明者 執行 ML 推理並生成證明 模型、輸入、計算資源
驗證者 驗證證明的正確性 驗證密鑰、公開輸入
數據擁有者 提供待推理的數據 私密輸入數據
模型擁有者 提供 ML 模型 模型權重

場景配置

場景一：雲端 ML 驗證
  證明者 = 服務商（模型 + 計算）
  驗證者 = 用戶
  目標：用戶驗證服務商誠實

場景二：隱私推理
  證明者 = 用戶（數據 + 本地計算）
  驗證者 = 服務商或第三方
  目標：用戶不洩露數據

場景三：區塊鏈整合
  證明者 = 鏈下執行者
  驗證者 = 智能合約
  目標：鏈上可驗證的 AI 決策

攻擊者模型

攻擊者能力

計算能力：
  - 標準假設：多項式時間（PPT）
  - 更強假設：無限計算（信息論安全）

觀察能力：
  - 可見公開輸入/輸出
  - 可見證明內容
  - 可能控制部分網路通訊

控制能力：
  - 惡意證明者：可偏離協議
  - 惡意驗證者：可選擇挑戰（互動式）
  - 外部攻擊者：被動觀察

攻擊目標

破壞可靠性（Soundness Attack）：
  攻擊者偽造錯誤計算的證明
  影響：接受錯誤的 ML 輸出

破壞零知識（Privacy Attack）：
  攻擊者從證明中提取私密資訊
  影響：洩露模型權重或輸入數據

拒絕服務（DoS Attack）：
  攻擊者阻止合法證明生成/驗證
  影響：系統不可用

安全目標

完備性（Completeness）

定義：
  誠實證明者的正確計算總能通過驗證

形式化：
  若 M(x) = y 且證明者誠實
  則 Verify(Prove(M, x, y)) = accept

ZKML 考量：
  - 量化誤差可能影響完備性
  - 需確保定點計算與浮點足夠接近

可靠性（Soundness）

定義：
  攻擊者無法偽造錯誤計算的證明

形式化：
  對任何 PPT 攻擊者 A：
  Pr[Verify(A(M, x, y')) = accept ∧ M(x) ≠ y'] ≤ negl(λ)

ZKML 考量：
  - 量化引入的鬆弛需納入分析
  - 溢出可能破壞 soundness

零知識性（Zero-Knowledge）

定義：
  驗證者從證明過程中學不到私密資訊

形式化：
  存在模擬器 S，對任何驗證者 V*：
  View_V*(Prove) ≈ S(public_info)

ZKML 隱私範圍：
  - 模型權重（模型即服務場景）
  - 輸入數據（隱私推理場景）
  - 中間激活值

威脅與防禦

常見攻擊類型

攻擊 描述 防禦
模型替換 使用不同於承諾的模型 模型承諾綁定
輸入篡改 聲稱使用不同輸入 輸入承諾綁定
證明偽造 不執行計算直接偽造 ZKP 可靠性保證
側信道洩露 從時間/功耗推斷資訊 恆定時間實作

安全假設

密碼學假設（依系統而異）：

SNARK (Groth16, PLONK)：
  - 離散對數假設
  - 配對相關假設（q-SDH, q-PKE）
  - 可信設置誠實（至少一方）

STARK：
  - 雜湊函數抗碰撞
  - 隨機預言機模型

IPA (Halo2)：
  - 離散對數假設
  - 無可信設置

實務建議

系統選擇指南

高安全場景：
  - 使用成熟的證明系統
  - 選擇經過審計的實作
  - 考慮後量子安全（STARK）

效能優先場景：
  - 可接受適度安全假設
  - 使用優化的 SNARK

隱私優先場景：
  - 確保零知識性質
  - 審慎處理輸入/模型承諾
