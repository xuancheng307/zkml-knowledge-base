威脅模型與安全目標

安全基礎

理解 ZKML 的威脅模型是正確應用這項技術的基礎。本頁面定義 ZKML 系統中的參與者、攻擊者能力、以及系統需要達成的安全目標。主要參考 Peng et al. 的綜述[1]與 ZKML (EuroSys 2024) 論文[2]。

形式化框架

系統模型定義

定義 1（ZKML 系統）

ZKML 系統是一個五元組 Π = (Setup, Commit, Prove, Verify, f)，其中：

  • Setup(1λ) → (pk, vk)：安全參數 λ 生成證明密鑰和驗證密鑰
  • Commit(W) → cW：對模型權重 W 生成承諾
  • Prove(pk, W, x, y) → π：生成 f(x; W) = y 的零知識證明
  • Verify(vk, cW, x, y, π) → {0, 1}：驗證證明有效性
  • f：神經網路推理函數
定義 2（可驗證推理關係）

可驗證推理的 NP 關係 R 定義為：

R = {((c_W, x, y), W) : Commit(W) = c_W ∧ f(x; W) = y}

其中公開陳述 (statement) 為 (cW, x, y)，私密見證 (witness) 為 W。

參與者角色

核心角色定義

角色 描述 持有資源 信任假設
證明者 (Prover) 執行 ML 推理並生成證明 模型 W、輸入 x、計算資源 可能惡意
驗證者 (Verifier) 驗證證明的正確性 驗證密鑰 vk、公開輸入 誠實但好奇
數據擁有者 提供待推理的數據 私密輸入數據 x 可能需隱私保護
模型擁有者 提供 ML 模型 模型權重 W、架構 可能需隱私保護
Setup 執行者 執行可信設置（若需要） Trusted Setup 參數 至少一方誠實（MPC）

應用場景配置

場景決定威脅模型

不同應用場景下，角色的重疊方式不同，導致威脅模型有根本差異。

場景一：雲端 ML 服務驗證 (MLaaS)

參與者配置：
  證明者 = 服務商（持有模型 + 計算資源）
  驗證者 = 用戶（接收推理結果）
  數據擁有者 = 用戶

威脅模型：
  - 服務商可能使用較弱的模型
  - 服務商可能偽造推理結果
  - 用戶數據傳輸時可能被服務商記錄

安全目標：
  - Soundness：服務商無法偽造推理結果
  - 模型承諾綁定：證明綁定到特定模型

隱私需求：
  - 模型權重對用戶保密（模型即資產）
  - 用戶輸入對服務商保密（可選）

場景二：隱私推理

參與者配置：
  證明者 = 用戶（持有私密數據 + 本地計算）
  驗證者 = 服務商或第三方
  模型擁有者 = 可能公開或服務商持有

威脅模型：
  - 驗證者試圖從證明中推斷用戶數據
  - 惡意證明者可能偽造推理結果

安全目標：
  - Zero-Knowledge：驗證者學不到 x 的資訊
  - Soundness：無法偽造錯誤計算的證明

典型應用：
  - 醫療診斷（患者數據隱私）
  - 金融徵信（財務資料隱私）

場景三：區塊鏈整合

參與者配置：
  證明者 = 鏈下執行者
  驗證者 = 智能合約（確定性執行）
  數據來源 = 鏈上或預言機

威脅模型：
  - 執行者完全不可信
  - 所有鏈上數據公開可見
  - Gas 成本是關鍵限制

安全目標：
  - Soundness：保護區塊鏈狀態完整性
  - 證明大小最小化（降低 gas 成本）
  - 驗證時間最小化

特殊考量：
  - 模型架構必須公開（電路公開）
  - 權重可保密（作為見證）

攻擊者模型

計算能力假設

定義 3（PPT 攻擊者）

多項式時間 (Probabilistic Polynomial Time, PPT) 攻擊者 A 是一個隨機演算法，其運行時間在安全參數 λ 上是多項式的。

攻擊者類型 計算能力 安全模型 適用系統
PPT 攻擊者 多項式時間 計算安全 SNARK、PLONK、Halo2
無限計算能力 不受限制 信息論安全 部分 STARK 構造
量子攻擊者 量子多項式時間 後量子安全 STARK（雜湊基礎）

攻擊者能力模型

觀察能力：
  Level 0：僅見公開輸出
    - 證明 π
    - 公開輸入 x（若公開）
    - 公開輸出 y

  Level 1：可見通訊內容
    - 所有網路傳輸
    - 可能的時間資訊

  Level 2：可控制部分輸入
    - 選擇性輸入攻擊
    - 適應性查詢

控制能力：
  惡意證明者：
    - 可偏離協議
    - 可選擇任意見證
    - 可生成任意「證明」

  惡意驗證者：
    - 可選擇挑戰值（互動式協議）
    - 可多次驗證同一證明
    - 可嘗試提取私密資訊

  中間人攻擊者：
    - 可攔截、修改、重放訊息
    - 可進行時間分析

攻擊目標分類

攻擊類型 目標 影響 防禦機制
Soundness Attack 偽造錯誤計算的證明 接受錯誤的 ML 輸出 ZKP 健全性保證
Privacy Attack 從證明提取私密資訊 洩露模型或數據 ZK 性質保證
Model Extraction 透過查詢重建模型 智慧財產權損失 查詢限制、差分隱私
Model Substitution 使用不同於承諾的模型 服務不誠實 模型承諾綁定
Replay Attack 重用舊證明 服務不誠實 時間戳/Nonce

安全目標形式化

完備性 (Completeness)

定義 4（完備性）

ZKML 系統滿足完備性，若對所有 (W, x)：

Pr[Verify(vk, Commit(W), x, f(x;W), Prove(pk, W, x, f(x;W))) = 1] = 1

其中機率來自 Setup 和 Prove 的隨機性。

ZKML 考量：量化誤差可能影響完備性。若定點運算結果 f_q(x; W_q) 與浮點結果 f(x; W) 差距過大，誠實證明者可能無法生成有效證明。需要：

  • 嚴格的量化誤差界限
  • 適當的容差 (tolerance) 設定
  • 電路設計時預留誤差空間

健全性 (Soundness)

定義 5（計算健全性）

ZKML 系統滿足計算健全性，若對任何 PPT 攻擊者 A：

Pr[(c_W, x, y*, π*) ← A(pk, vk) :
    Verify(vk, c_W, x, y*, π*) = 1 ∧
    ∄W. (Commit(W) = c_W ∧ f(x;W) = y*)] ≤ negl(λ)
定義 6（知識健全性 / 可提取性）

更強的知識健全性要求存在提取器 E，使得：若 A 能生成有效證明，則 E 能從 A 提取見證 W。

Pr[(c_W, x, y, π) ← A(pk, vk), W ← E^A(pk, vk) :
    Verify(vk, c_W, x, y, π) = 1 ∧
    (Commit(W) ≠ c_W ∨ f(x;W) ≠ y)] ≤ negl(λ)

ZKML 考量：

  • 量化引入的鬆弛需納入分析
  • 有限域溢位可能破壞 soundness
  • 查表範圍不足可能允許作弊

零知識性 (Zero-Knowledge)

定義 7（計算零知識）

ZKML 系統滿足零知識，若存在 PPT 模擬器 S，對任何 PPT 驗證者 V* 和所有 (W, x)：

View_V*(Prove(pk, W, x, f(x;W))) ≈_c S(vk, Commit(W), x, f(x;W))

其中 ≈c 表示計算不可區分。

ZKML 隱私範圍：

保護對象 場景 實現方式
模型權重 W MLaaS、模型即資產 W 作為見證，僅公開 Commit(W)
輸入數據 x 隱私推理、醫療/金融 x 作為見證，輸入承諾公開
中間激活值 防止模型逆向 所有中間計算為見證
模型架構 需額外機制 通用電路（zkVM）

安全假設

密碼學假設

證明系統 主要假設 Trusted Setup 後量子安全
Groth16 q-SDH, q-PKE, DLOG 電路專屬 否
PLONK DLP, AGM 通用 SRS 否
Halo2 (KZG) DLP, AGM 通用 SRS 否
Halo2 (IPA) DLP 無 否
STARK 雜湊抗碰撞 無（透明） 是

可信設置假設

Trusted Setup 安全模型：

單方設置（不建議）：
  - 單一方執行 Setup
  - 若該方保留「trapdoor」，可偽造證明
  - 完全信任單一實體

MPC 設置（推薦）：
  - 多方參與 Setup
  - 只要有一方誠實銷毀秘密，系統安全
  - Powers of Tau 儀式

透明設置：
  - 無需信任假設
  - 從公開隨機性生成參數
  - STARK 和 IPA 採用此方式

ZKML 特有安全考量

量化相關威脅

量化誤差攻擊：
  問題：量化引入的誤差可能被惡意利用

  攻擊場景：
    1. 攻擊者找到 x 使得 f_q(x) ≠ f(x)
    2. 聲稱量化結果是「正確」的
    3. 誤差範圍內的偽造

  防禦：
    - 嚴格的誤差界限證明
    - 與浮點結果的一致性驗證
    - 適當的容差設定

溢位攻擊：
  問題：有限域運算可能溢位

  攻擊場景：
    1. 構造導致溢位的輸入
    2. 溢位後約束可能被繞過

  防禦：
    - 範圍檢查約束
    - 足夠大的域和位寬
    - 詳見 溢位風險

模型承諾安全

承諾綁定性：
  需求：攻擊者無法找到兩個不同的 W₁, W₂ 使得 Commit(W₁) = Commit(W₂)

  實現方式：
    - Poseidon/Pedersen 雜湊
    - Merkle 樹承諾
    - KZG 多項式承諾

承諾隱藏性：
  需求：從 Commit(W) 無法推斷 W 的資訊

  應用：模型權重保密

  實現：使用 hiding commitment scheme（如 Pedersen）

威脅緩解策略

威脅 緩解策略 實現複雜度
模型替換 模型承諾綁定到證明 低
輸入篡改 輸入承諾或簽名 低
證明偽造 選用安全的 ZKP 系統 依賴底層系統
重放攻擊 Nonce 或時間戳 低
側信道洩露 恆定時間實作 高
模型提取 查詢限制、差分隱私 中
量化攻擊 嚴格誤差界限 中

部署檢查清單

安全部署檢查：

□ 密碼學參數
  - 安全參數 λ ≥ 128 bits
  - 選用經過審計的實作
  - 正確執行 Trusted Setup（若需要）

□ 電路設計
  - 所有運算有範圍檢查
  - 量化誤差在可接受範圍
  - 無未約束的見證值

□ 承諾機制
  - 模型承諾使用安全雜湊
  - 輸入承諾（若需隱私）
  - 時間戳/Nonce 防重放

□ 運行時安全
  - 恆定時間實作（若需）
  - 安全的隨機數生成
  - 錯誤訊息不洩露敏感資訊
