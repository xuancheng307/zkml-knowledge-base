ZK 專用量化

論文章節

本頁對應論文 §4「量化配置與 ZK 成本」

概述

量化（Quantization）是將神經網路從 32 位元浮點數轉換為低位元整數表示的技術。在 ZKML 系統中，量化不僅是壓縮技術，更是必要的前處理步驟，因為 ZK-SNARK 證明系統在有限域（Finite Field）上運算，無法直接處理浮點數[1]。

關鍵差異

傳統量化優化目標是延遲與準確率的權衡；ZKML 量化則需要額外考量證明時間、記憶體使用、證明大小等 ZK 特有成本。

量化基礎

仿射量化方案

標準的仿射量化方案定義實數值 r 與整數量化碼 qint 之間的對應關係[2]：

量化（Quantization）：實數 → 整數碼

$$q_{\text{int}} = \text{clamp}\left(\text{round}\left(\frac{r}{S}\right) + Z;\; q_{\min},\; q_{\max}\right)$$

其中：

  • \(\text{round}(\cdot)\)：四捨五入，tie-break 採用 round-half-away-from-zero（0.5 → 1, -0.5 → -1）
    註：tie-break 規則是實作選擇，用於確保電路 deterministic；Jacob 原論文[2]未強制指定此規則。
  • \(\text{clamp}(x; a, b) = \max(a, \min(b, x))\)：將 \(x\) 夾至 \([a, b]\) 區間
  • \(q_{\min} = 0\)，\(q_{\max} = 2^b - 1\)（無符號 \(b\)-bit 量化）

反量化（Dequantization）：整數碼 → 近似實數

$$r' = S(q_{\text{int}} - Z)$$

其中：

  • S（Scale）：縮放因子，正實數，決定量化步長
  • Z（Zero-point）：零點，整數（使 r=0 對應到整數範圍內的某值）
  • qint：量化後的整數碼，範圍 \([q_{\min}, q_{\max}]\)
  • r'：反量化後的近似實數（≈ r，存在量化誤差）
  • b：位元寬度（8-bit 時 b=8，對應 \(q_{\max} = 255\)）

量化格點函數

另一種表述是直接輸出落在量化格點上的實數值（非整數碼）[2]：

$$s(a, b, n) = \frac{b - a}{n - 1}$$

$$\tilde{r}(r; a, b, n) = \left\lfloor \frac{\text{clamp}(r; a, b) - a}{s(a, b, n)} \right\rceil \cdot s(a, b, n) + a$$

此處 \(\tilde{r}\) 輸出為實數（量化格點值），而非整數碼。對於 8 位元量化，n = 28 = 256。

ZK 專用量化考量

位元寬度選擇

在 ZKML 中，位元寬度（bit_width）直接影響：

位元寬度查表大小精度證明時間適用場景
4-bit16 rows低最快小型模型、低精度需求
6-bit64 rows中較快平衡選擇
8-bit256 rows高較慢高精度需求
查表約束

非線性激活函數（ReLU 外）需要 lookup tables 實作。位元寬度決定查表大小：n-bit 需要 2n 行。查表大小受限於電路總行數（必須為 2 的冪次）。

Per-Tensor vs Per-Channel 量化

量化粒度影響準確率與 ZK 成本：

模式說明準確率ZK 成本
Per-Tensor 整個張量共用一組 (S, Z) 較低 較低（參數少）
Per-Channel 每個輸出通道各有 (S, Z) 較高 較高（多組參數）

Per-channel 量化能處理不同通道權重範圍差異大（可達 100×）的情況，避免小範圍通道的相對誤差過大[2]。

校準方法

校準（Calibration）決定量化範圍 [a, b]：

MinMax 校準

直接使用觀測到的最小/最大值：

$$a = \min(x), \quad b = \max(x)$$

簡單但對離群值敏感。

Percentile 校準

使用百分位數（如 99.9%）排除離群值：

$$a = \text{percentile}(x, 1-p), \quad b = \text{percentile}(x, p)$$

更穩健，但需要額外參數調整。

ZKML 系統的量化實作

ZKML (EuroSys 2024)

ZKML 使用定點數（fixed-point）表示，關鍵設計[1]：

  • Scale Factor (SF)：全域縮放因子，由優化器選擇
  • 整數運算：所有計算在有限域 Fp 中完成
  • 溢位處理：必須確保中間結果不超過域大小

矩陣乘法量化

考慮矩陣乘法 r3 = r1r2，量化後[2]：

$$q_3^{(i,k)} = Z_3 + M \sum_{j=1}^{N} (q_1^{(i,j)} - Z_1)(q_2^{(j,k)} - Z_2)$$

其中乘數 M = S1S2/S3。M 可表示為：

$$M = 2^{-n} M_0, \quad M_0 \in [0.5, 1)$$

M0 用定點數表示（如 int32），乘以 2-n 用位元位移實現，保持純整數運算。

偏差向量量化

偏差（bias）使用 32 位元整數量化，因為[2]：

  • 偏差僅佔參數極小比例
  • 每個偏差影響多個輸出，量化誤差會形成系統性偏移
  • 較高精度有助維持端到端準確率

ezkl 的量化方案

ezkl 使用類似方法，關鍵參數[3]：

  • scale：定點數小數位元數
  • bits：總位元寬度
  • lookup_bits：查表精度

量化對 ZK 成本的影響

證明時間

位元寬度增加導致：

  • 查表大小指數增長
  • 更多 lookup constraints
  • 電路行數增加

記憶體使用

主要影響因素：

  • 查表儲存（2n 行）
  • 中間累加器大小（通常 32-bit）
  • 見證（witness）大小

準確率影響

ZKML 實驗顯示量化對準確率影響極小[1]：

模型FP32 準確率量化準確率差異
MNIST99.06%99.06%0%
VGG1690.36%90.37%+0.01%
ResNet-1891.88%91.87%-0.01%

高品質量化通常在 0.1% 準確率內，ZKML 的 0.01% 差異表現優異。

量化感知訓練 vs 訓練後量化

訓練後量化（Post-Training Quantization, PTQ）

直接量化已訓練的浮點模型：

  • 優點：簡單、快速、無需重新訓練
  • 缺點：小模型可能準確率下降明顯
  • 失敗模式：通道間權重範圍差異大、離群值權重

量化感知訓練（Quantization-Aware Training, QAT）

訓練時模擬量化效果[2]：

  • 前向傳播模擬量化推理
  • 反向傳播使用浮點梯度
  • 權重和偏差以浮點儲存以便微調

對小型模型特別有效，能恢復接近原始準確率。

ZK-Friendly 量化設計指南

位元寬度選擇

  1. 首選 8-bit：平衡精度與效能
  2. 考量查表限制：確保 2n 不超過電路行數
  3. 測試低位元：對特定模型，6-bit 或 4-bit 可能足夠

激活函數考量

  • ReLU6 優於 ReLU：固定範圍 [0, 6] 更易量化
  • 避免無界激活函數
  • 考慮 ZK-friendly 替代（如多項式近似）

Batch Normalization 處理

推理時將 BatchNorm 摺疊（fold）入卷積層[2]：

$$w_{\text{fold}} = \frac{\gamma w}{\sqrt{\sigma_B^2 + \epsilon}}$$

這樣避免在 ZK 電路中實作除法運算。

配置空間

ZKML Auto-Tuning 的量化相關參數：

參數範圍預設值說明
bit_width{4, 6, 8}8量化位元寬度
mode{per_tensor, per_channel}per_channel量化粒度
calibration{minmax, percentile}minmax校準方法
percentile[99.0%, 99.99%]99.9%百分位數（若使用 percentile 校準）

這些參數與證明器參數（logrows, lookup_bits）共同構成 ZKML 配置空間，需要系統性調參以達到最佳效能。
