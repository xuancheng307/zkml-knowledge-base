Cost Function 設計

論文章節

本頁對應論文 §5.3「Cost Function 設計」，整合 ZKML (EuroSys 2024) 的成本估算方法與多目標貝葉斯優化 (MOBO) 的理論基礎。

概述

ZKML 系統的配置優化本質上是一個多目標最佳化問題。與傳統機器學習調參僅關注模型準確度不同，ZKML 必須同時考量多個可能衝突的目標[1]：

  • 最小化：證明時間、記憶體使用、證明大小、鏈上 gas 成本
  • 最大化：模型準確度
  • 滿足：硬性約束（如記憶體上限、準確度門檻）

設計良好的 Cost Function 是自動調優框架的核心，它將多維目標空間映射為單一可比較的數值，引導優化器找到最佳配置。

單目標 Cost Function

基本形式

最簡單的 Cost Function 形式是加權線性組合[1]：

$$C(\mathbf{c}) = \alpha \cdot T_{\text{prove}}(\mathbf{c}) + \beta \cdot M_{\text{RAM}}(\mathbf{c}) + \gamma \cdot S_{\text{proof}}(\mathbf{c}) + \delta \cdot (1 - \text{Acc}(\mathbf{c}))$$

其中：

  • \(\mathbf{c}\) 為配置向量（包含 logrows、lookup_bits、bit_width 等）
  • \(T_{\text{prove}}\) 為證明時間（秒）
  • \(M_{\text{RAM}}\) 為峰值記憶體使用（GB）
  • \(S_{\text{proof}}\) 為證明大小（KB）
  • \(\text{Acc}\) 為模型準確度
  • \(\alpha, \beta, \gamma, \delta\) 為權重係數

帶懲罰項的 Cost Function

實務上常需處理硬性約束，使用懲罰項實現[1]：

$$C(\mathbf{c}) = T_{\text{prove}}(\mathbf{c}) + \lambda_1 \cdot \mathbb{1}[\text{Acc}(\mathbf{c}) < \theta_{\text{acc}}] + \lambda_2 \cdot \mathbb{1}[M_{\text{RAM}}(\mathbf{c}) > M_{\max}]$$

其中：

  • \(\mathbb{1}[\cdot]\) 為指示函數，條件成立時為 1，否則為 0
  • \(\theta_{\text{acc}}\) 為準確度門檻（如 90%）
  • \(M_{\max}\) 為可用記憶體上限
  • \(\lambda_1, \lambda_2\) 為懲罰係數（通常設為很大的值）
懲罰係數選擇

懲罰係數 \(\lambda\) 需足夠大以確保違反約束的配置永遠不會被選中。實務上可設為目標函數可能值的 10-100 倍。

應用場景導向的權重

不同應用場景對各成本指標的重視程度不同[1]：

應用場景 主要關注 建議權重分配
區塊鏈驗證 證明大小、gas 成本 高 \(\gamma\)，中 \(\alpha\)
即時推理 證明時間 高 \(\alpha\)，低 \(\gamma\)
資源受限環境 記憶體使用 高 \(\beta\)，中 \(\alpha\)
高精度需求 模型準確度 高 \(\delta\)，寬鬆其他
批次處理 總吞吐量 平衡 \(\alpha\) 和 \(\beta\)

多目標最佳化

Pareto 最優

當目標相互衝突時，不存在單一最優解。取而代之的是 Pareto 前沿（Pareto Frontier）——所有無法在不犧牲某一目標的前提下改善其他目標的解集合[2]。

定義：配置 \(\mathbf{c}\) Pareto 支配（dominates）配置 \(\mathbf{c}'\) 若且唯若：

$$\forall i: f_i(\mathbf{c}) \leq f_i(\mathbf{c}') \quad \text{and} \quad \exists j: f_j(\mathbf{c}) < f_j(\mathbf{c}')$$

其中 \(f_i\) 為第 \(i\) 個目標函數（假設都是最小化問題）。

Pareto 前沿：所有不被任何其他解支配的解的集合：

$$\mathcal{P} = \{\mathbf{c} \in \mathcal{C} : \nexists \mathbf{c}' \in \mathcal{C}, \mathbf{c}' \text{ dominates } \mathbf{c}\}$$

Hypervolume 指標

Hypervolume 是評估 Pareto 前沿品質的常用指標[2]。給定參考點 \(\mathbf{r}\)，hypervolume 定義為 Pareto 前沿與參考點之間的空間體積：

$$\text{HV}(\mathcal{P}, \mathbf{r}) = \text{Vol}\left(\bigcup_{\mathbf{c} \in \mathcal{P}} [\mathbf{f}(\mathbf{c}), \mathbf{r}]\right)$$

Hypervolume 越大，表示 Pareto 前沿品質越好（覆蓋更多目標空間）。

Expected Hypervolume Improvement (EHVI)

多目標貝葉斯優化 (MOBO) 使用 EHVI 作為獲取函數[2]：

$$\text{EHVI}(\mathbf{c}) = \mathbb{E}[\text{HV}(\mathcal{P} \cup \{\mathbf{c}\}, \mathbf{r}) - \text{HV}(\mathcal{P}, \mathbf{r})]$$

EHVI 衡量新配置對現有 Pareto 前沿的預期改善程度。選擇 EHVI 最大的配置進行下一次評估。

可微分 EHVI

傳統 EHVI 計算複雜度較高。Daulton et al. (2020) 提出可微分的 qEHVI，支援批次選擇多個配置並利用 GPU 加速[2]。

ZKML 成本估算模型

FFT 成本估算

證明時間的主要組成是 FFT 運算。ZKML 使用以下公式估算[1]：

$$C_{\text{FFT}} = n_{\text{FFT}} \cdot t_{\text{FFT}}(k) + n'_{\text{FFT}} \cdot t_{\text{FFT}}(k')$$

其中：

  • \(k = \log_2(\text{rows})\) 為行數的對數
  • \(k' = k + \log_2(d_{\max} - 1)\)，\(d_{\max}\) 為約束最大次數
  • \(t_{\text{FFT}}(k)\) 為大小為 \(2^k\) 的 FFT 時間（預先測量）

FFT 數量計算：

$$n_{\text{FFT}} = N_i + N_a + 3 \cdot N_{\text{lk}} + \left\lceil \frac{N_{\text{pm}} + d_{\max} - 3}{d_{\max} - 2} \right\rceil$$

其中 \(N_i\) 為實例列數、\(N_a\) 為建議列數、\(N_{\text{lk}}\) 為查表數量、\(N_{\text{pm}}\) 為置換約束數量。

MSM 成本估算

多純量乘法 (MSM) 是另一主要成本來源[1]：

承諾方案 MSM 數量 單次 MSM 大小
KZG \(n_{\text{FFT}} + d_{\max} - 1\) \(2^k\)
IPA \(n_{\text{FFT}} + d_{\max}\) \(2^k\)

估算準確性

ZKML 成本估算器的準確性以 Kendall 等級相關係數衡量[1]：

後端 Kendall τ 說明
KZG 0.89 高度相關
IPA 0.88 高度相關

這意味著估算器能準確排序不同配置的相對效能，即使絕對值可能有誤差。

實務設計考量

階段式優化

實務上建議採用階段式優化策略[1]：

  1. 可行性篩選：排除違反硬性約束的配置（logrows 不足、記憶體超限）
  2. 準確度篩選：排除準確度低於門檻的配置
  3. Pareto 分析：在可行配置中找出 Pareto 前沿
  4. 最終選擇：根據應用需求從 Pareto 前沿選擇

def staged_optimization(configs, model, constraints):
    """階段式優化策略"""

    # 階段 1: 可行性篩選
    feasible = [c for c in configs
                if check_feasibility(c, constraints)]

    # 階段 2: 準確度篩選
    accurate = [c for c in feasible
                if evaluate_accuracy(model, c) >= constraints['min_acc']]

    # 階段 3: 評估所有目標
    evaluated = [(c, evaluate_all_objectives(model, c))
                 for c in accurate]

    # 階段 4: 找出 Pareto 前沿
    pareto_front = find_pareto_front(evaluated)

    return pareto_front

快速可行性檢查

在進行昂貴的完整評估前，可使用快速檢查排除不可行配置[1]：

檢查項目 方法 成本
logrows 足夠性 估算最小行數需求 毫秒級
記憶體需求 根據 logrows 估算 毫秒級
約束滿足 Mock prove（不生成證明） 秒級
量化準確度 校準資料集評估 秒級

歸一化處理

不同目標的尺度差異大（秒 vs GB vs KB），需要歸一化[2]：

$$\tilde{f}_i(\mathbf{c}) = \frac{f_i(\mathbf{c}) - f_i^{\min}}{f_i^{\max} - f_i^{\min}}$$

其中 \(f_i^{\min}\) 和 \(f_i^{\max}\) 可從歷史觀測估計，或使用領域知識設定。

與 TPE 的整合

Tree-structured Parzen Estimator (TPE) 是 ZKML 使用的優化演算法[3]。Cost Function 設計需考慮與 TPE 的配合：

單目標 TPE

TPE 透過建模 \(p(x|y)\) 而非 \(p(y|x)\) 進行優化：

$$p(x|y) = \begin{cases} \ell(x) & \text{if } y < y^* \\ g(x) & \text{if } y \geq y^* \end{cases}$$

其中 \(y^*\) 通常取為觀測值的 \(\gamma = 0.15\) 分位數。TPE 選擇 \(\ell(x)/g(x)\) 比值高的配置。

多目標 TPE（MOTPE）

對於多目標問題，可擴展 TPE[3]：

  1. 計算每個配置的 Pareto 支配數
  2. 選擇支配數最少的 \(\gamma\) 比例配置作為「好」樣本
  3. 分別對每個目標建模 \(\ell(x)\) 和 \(g(x)\)
  4. 使用乘積 \(\prod_i \ell_i(x) / \prod_i g_i(x)\) 選擇配置

ZKML 優化器效益

良好的 Cost Function 設計對優化效益至關重要[1]：

模型 ZKML 優化 固定配置 改善
VGG-16 637.1 s 1474.0 s 131%
MobileNet 1225.5 s 2407.8 s 96%
MNIST 2.5 s 4.4 s 76%
GPT-2 3651.7 s 5952.0 s 63%

優化器執行時間相比窮舉搜索快約 5900 倍（以 GPT-2 為例：185.3 秒 vs 估計 1,078,449 秒）。
