ZK 關係式定義

核心概念

本頁說明零知識證明中「關係式 (Relation)」的形式化定義，以及如何在 ZKML 中建構可驗證的電路約束。主要整合 Peng et al. 的綜述[1]與 ZKML (EuroSys 2024)[2] 的相關內容。

ZK 關係式的形式化定義

在零知識證明系統中，關係式 (Relation) R 是一個二元謂詞 R(x, w)，其中 x 為公開輸入 (Public Input / Statement)，w 為私密見證 (Private Witness)。證明者 (Prover) 的目標是向驗證者 (Verifier) 證明「存在某個 w 使得 R(x, w) = 1」，同時不洩露 w 的任何資訊[1]。

形式化定義如下：

對於語言 L = { x : ∃w, R(x, w) = 1 }

零知識證明系統 (P, V) 需滿足：
  1. 完備性：若 R(x, w) = 1，誠實證明者總能說服驗證者
  2. 健全性：若 x ∉ L，任何作弊證明者被接受的機率可忽略
  3. 零知識：驗證者無法從證明中學到關於 w 的額外資訊

NP 關係與計算複雜度

ZK 證明系統特別適合 NP 關係，即給定見證 w 可在多項式時間內驗證 R(x, w) = 1 的問題。對於 ZKML 而言，神經網路推理屬於 NP 問題：給定模型參數 w 和輸入 x，驗證輸出 y = f(x; w) 可在多項式時間完成[1]。

複雜度類別 定義 與 ZKP 的關係
P 可在多項式時間內解決的問題 可生成 ZK 證明，但通常不需要
NP 解可在多項式時間內驗證的問題 ZK 證明的主要應用範圍
IP 交互式證明可解決的問題 ZK 是 IP 的變體，附加零知識屬性

ZKML 中的關係式結構

在可驗證推理 (Verifiable Inference) 場景中，ZKML 關係式可形式化為[1]： 

R_inference(x, y, w) = 1  ⟺  f(x; w) = y

其中：
  x = 輸入資料（可為公開或私密）
  y = 推理輸出（通常為公開）
  w = 模型參數（通常為私密見證）
  f = 神經網路推理函數

公開輸入與私密見證的劃分

根據應用場景，ZKML 系統可採用不同的隱私設定[1]：

場景 公開輸入 (x) 私密見證 (w) 典型應用
模型私密 輸入 x、輸出 y 模型參數 MLaaS 服務驗證
輸入私密 輸出 y、模型承諾 輸入 x 隱私推理（醫療診斷）
雙重私密 輸出 y 輸入 x、模型參數 完全隱私計算

算術電路表示

要生成 ZK 證明，關係式 R 必須轉換為算術電路 (Arithmetic Circuit)。算術電路由加法閘和乘法閘組成，在有限域 F_p 上執行運算[2]。

R1CS 表示

Rank-1 Constraint System (R1CS) 是最常見的算術化方法，將電路約束表示為： 

(A · z) ○ (B · z) = C · z

其中：
  z = (1, x, w)  為包含常數、公開輸入、私密見證的向量
  A, B, C        為稀疏矩陣，定義電路結構
  ○              為逐元素乘法

每個約束形如：(∑ aᵢzᵢ) · (∑ bⱼzⱼ) = ∑ cₖzₖ，可表達一個乘法閘的計算[1]。

PLONKish 表示

現代 ZKML 系統（如 EZKL、ZKML）多採用 PLONKish 算術化，相較 R1CS 具有以下優勢[2]：

  • Custom Gates：可定義任意形式的閘約束，不限於簡單乘法
  • Lookup Arguments：支援查表操作，適合非線性函數
  • Copy Constraints：處理線路連接 (wiring) 更高效

PLONKish 約束的一般形式：

Q_L(X)·a(X) + Q_R(X)·b(X) + Q_O(X)·c(X)
  + Q_M(X)·a(X)·b(X) + Q_C(X) = 0

其中 Q_* 為選擇器多項式，a, b, c 為線路多項式

神經網路層的關係式

不同類型的神經網路層對應不同的 ZK 關係式[2]：

線性層 (Linear Layer)

R_linear: y = Wx + b

約束數量：O(n·m)，其中 n 為輸入維度，m 為輸出維度
實作方式：矩陣乘法分解為逐元素乘法和累加

卷積層 (Convolution Layer)

R_conv: y[i,j] = ∑ₖ ∑ₗ x[i+k, j+l] · w[k, l]

約束數量：O(H·W·C_in·C_out·K²)
優化策略：im2col 展開、FFT 加速（zkCNN）

激活函數 (Activation Function)

非線性挑戰

ReLU、GELU 等非線性函數無法直接在有限域算術中表達，需要特殊處理。

常見處理策略[2]：

策略 ReLU 實作 約束開銷
位元分解 分解 x 為位元，檢查符號位 O(b) 約束/元素，b 為位寬
查表 預計算 ReLU(x) 查表 O(1) 約束 + lookup
範圍證明 證明 x ∈ [0, 2^k) 或 x ∈ [-2^k, 0) O(k) 約束

量化與關係式轉換

由於 ZK 電路在有限域上運算，浮點數必須量化為定點數表示。量化過程引入近似，需要在關係式中正確處理[2]： 

原始浮點運算：y_float = W_float · x_float

量化關係式：
  x_q = round(x_float / S_x)           // 量化輸入
  W_q = round(W_float / S_W)           // 量化權重
  y_acc = W_q · x_q                    // 整數累積
  y_q = round(y_acc · S_W · S_x / S_y) // 重新量化輸出

ZK 電路需證明上述整數運算的正確性

安全性保證

正確定義的 ZK 關係式需滿足以下安全屬性[1]：

完備性 (Completeness)

若誠實證明者確實執行了正確的推理計算，則必然能生成有效證明。這要求電路約束能完整捕捉推理邏輯，不會誤判正確計算。

健全性 (Soundness)

惡意證明者無法為錯誤的計算生成有效證明。這要求電路約束足夠嚴格，不允許任何「作弊」的計算路徑。

在 ZKML 中，量化誤差可能引入額外的健全性考量：如果量化後的電路允許的輸出範圍過寬，可能存在攻擊者利用誤差區間的風險。詳見 Soundness 分析。

零知識性 (Zero-Knowledge)

驗證者除了「陳述為真」這個事實外，無法從證明中獲得任何關於見證的資訊。對於模型私密場景，這意味著驗證者無法從證明反推模型參數。
