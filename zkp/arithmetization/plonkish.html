PLONKish 算術化

核心概念

PLONKish 是 PLONK 及其變體（如 Halo2、UltraPLONK）使用的算術化格式，透過自定義門（custom gates）和查表（lookup arguments）提供比 R1CS 更靈活的約束表達能力[1]。相關的 STARK 算術化格式請參見 AIR 算術化。

形式化定義

Definition 1：PLONKish 算術化

PLONKish 算術化是一個元組 \(\mathcal{C} = (n, k, \mathbf{f}, \mathbf{q}, \mathcal{G}, \sigma)\)：

  • \(n\)：表格行數（\(n = 2^\ell\) 為 2 的冪次，其中 \(\ell\) 為 logrows 參數）
  • \(k\)：列數，分為 advice columns \(k_a\)、instance columns \(k_i\)、fixed columns \(k_f\)
  • \(\mathbf{f} = (f_1, \ldots, f_{k_f})\)：固定列的值
  • \(\mathbf{q} = (q_1, \ldots, q_s)\)：選擇器多項式
  • \(\mathcal{G} = \{G_1, \ldots, G_g\}\)：門約束多項式集合（共 \(g\) 個門類型）
  • \(\sigma\)：複製約束排列
Definition 2：門約束（Gate Constraint）

門約束 \(G\) 是一個多變量多項式：

\[G(a_1(X), \ldots, a_{k_a}(X), q_1(X), \ldots, q_s(X)) = 0\]

其中 \(a_i(X)\) 是 advice 多項式，\(q_j(X)\) 是選擇器多項式。約束在所有 \(\omega^i\)（\(i \in [0, n)\)）處必須成立。

Definition 3：Rotation

Rotation 允許門約束存取相鄰行的值。對於 advice 多項式 \(a(X)\)：

  • \(\text{Rotation}(0)\)：當前行，\(a(\omega^i)\)
  • \(\text{Rotation}(1)\)：下一行，\(a(\omega^{i+1})\)
  • \(\text{Rotation}(-1)\)：前一行，\(a(\omega^{i-1})\)

驗證時透過 \(a(\omega \cdot X)\) 或 \(a(\omega^{-1} \cdot X)\) 實現。

Definition 4：複製約束（Copy Constraint）

複製約束是一組等式 \(\{(i_1, j_1) = (i_2, j_2)\}\)，表示 row \(i_1\) 的 column \(j_1\) 必須等於 row \(i_2\) 的 column \(j_2\)。這些約束透過排列 \(\sigma: [N] \to [N]\) 編碼，其中 \(N := n \cdot k_a\) 為總位置數，\([N] := \{0, 1, \ldots, N-1\}\)。

Definition 5：選擇器多項式（Selector Polynomial）

選擇器 \(q(X)\) 是一個固定多項式，值域為 \(\{0, 1\}\)（或更一般的 \(\mathbb{F}\)）。在 row \(i\)：

  • \(q(\omega^i) = 1\)：門約束在該行啟用
  • \(q(\omega^i) = 0\)：門約束在該行禁用

這允許同一電路包含多種不同的門類型。

Definition 6：Vanishing 多項式

給定域 \(H = \{\omega^0, \omega^1, \ldots, \omega^{n-1}\}\)，Vanishing 多項式定義為：

\[Z_H(X) := \prod_{i=0}^{n-1}(X - \omega^i) = X^n - 1\]

門約束 \(G(X) = 0 \mod Z_H(X)\) 等價於 \(G(\omega^i) = 0\) 對所有 \(i\) 成立。

PLONKish 基礎

表格結構

PLONKish 將計算組織為二維表格[1]：

表格結構：
  行（rows）：n 行，對應電路的 n 個「門」
  列（columns）：k 列，包含不同類型的值

列類型：
  - Advice columns：私密見證值
  - Instance columns：公開輸入/輸出
  - Fixed columns：電路定義的常數（選擇器）
  - Selector columns：啟用/禁用特定門

範例表格（3 列 advice，2 列 selector）：
  Row | a    | b    | c    | s_mul | s_add
  ----|------|------|------|-------|-------
  0   | x    | y    | z    | 1     | 0
  1   | z    | w    | out  | 0     | 1
  ...

門約束（Gate Constraints）

PLONKish 允許定義任意多項式約束[1]：

標準 PLONK 門：
  q_L · a + q_R · b + q_O · c + q_M · (a·b) + q_C = 0

其中：
  a, b, c：當前行的 advice 值
  q_L, q_R, q_O, q_M, q_C：選擇器（fixed 值）

門配置範例：
  乘法門：q_M = 1, q_O = -1, 其他 = 0
    → a · b - c = 0 → a · b = c

  加法門：q_L = 1, q_R = 1, q_O = -1, 其他 = 0
    → a + b - c = 0 → a + b = c

  常數門：q_L = 1, q_C = -k, 其他 = 0
    → a - k = 0 → a = k

自定義門（Custom Gates）

門設計原則

PLONKish 擴展允許更複雜的門[2]：

門設計考量：

1. 門次數（Gate Degree）：
   - 門約束是多項式，其次數影響證明效率
   - 次數越高 → 需要更大的求值域 → 證明更慢
   - 典型限制：次數 ≤ 5-7

2. 寬度（Width）：
   - 門使用的 column 數量
   - 更寬的門需要更多 column commitment
   - 權衡：寬度 vs 深度（行數）

3. Rotation 使用：
   - 存取相鄰行增加靈活性
   - 但也增加約束複雜度
   - 典型限制：Rotation ∈ [-2, 2]

Halo2 自定義門範例

// 三元乘法門：a · b · c = d
meta.create_gate("triple_mul", |meta| {
    let a = meta.query_advice(advice[0], Rotation::cur());
    let b = meta.query_advice(advice[1], Rotation::cur());
    let c = meta.query_advice(advice[2], Rotation::cur());
    let d = meta.query_advice(advice[3], Rotation::cur());
    let s = meta.query_selector(s_triple);

    vec![s * (a * b * c - d)]
});

// 條件選擇門：out = cond ? a : b
meta.create_gate("conditional_select", |meta| {
    let cond = meta.query_advice(advice[0], Rotation::cur());
    let a = meta.query_advice(advice[1], Rotation::cur());
    let b = meta.query_advice(advice[2], Rotation::cur());
    let out = meta.query_advice(advice[3], Rotation::cur());
    let s = meta.query_selector(s_cond);

    // out = cond * a + (1 - cond) * b
    // 展開：out - cond*a - b + cond*b = 0
    //       out - b - cond*(a - b) = 0
    vec![s * (out - b - cond * (a.clone() - b.clone()))]
});

// 跨行累加門（用於 MAC 操作）
meta.create_gate("accumulate", |meta| {
    let prev = meta.query_advice(acc, Rotation::prev());
    let curr = meta.query_advice(acc, Rotation::cur());
    let a = meta.query_advice(input_a, Rotation::cur());
    let b = meta.query_advice(input_b, Rotation::cur());
    let s = meta.query_selector(s_acc);

    // curr = prev + a * b
    vec![s * (curr - prev - a * b)]
});

複製約束（Copy Constraints）

排列論證

PLONKish 使用排列論證確保值一致性[1]：

問題：確保不同位置的值相等
  例如：row 0 的輸出 = row 1 的輸入

排列定義（N := n · k_a，[N] := {0, 1, ..., N-1}）：
  σ: [N] → [N]
  σ(i) = j 表示位置 i 和 j 必須有相同值

排列論證：
  1. 構造累積多項式 Z(X)
  2. Z 從 1 開始，經過所有位置回到 1
  3. 若排列滿足，Z 的軌跡一致

多項式約束：
  Z(ω·X) · (a(X) + β·X + γ) · (b(X) + β·k₁·X + γ) · (c(X) + β·k₂·X + γ)
  = Z(X) · (a(X) + β·σ_a(X) + γ) · ...

排列論證詳細推導

Theorem 1：排列論證正確性

設 \(\sigma: [N] \to [N]\) 是位置集合 \([N] = \{0, 1, \ldots, N-1\}\) 上的排列，其中 \(N = n \cdot k_a\)。向量 \(\mathbf{w} = (w_0, w_1, \ldots, w_{N-1})\) 滿足 \(\sigma\) 當且僅當對隨機 \(\beta, \gamma \in \mathbb{F}\)：

\[\prod_{i=0}^{N-1} (w_i + \beta \cdot i + \gamma) = \prod_{i=0}^{N-1} (w_i + \beta \cdot \sigma(i) + \gamma)\]

以壓倒性機率成立。

累積多項式 Z(X) 構造：

1. 定義位置編碼：
   位置 (row i, col j) → id = i + j · n
   使用互不相同的係數 k_j 區分不同列

2. 構造累積項：
   Z(ω⁰) = 1（起始值）

   Z(ω^{i+1}) = Z(ωⁱ) · ∏ⱼ [(w_j(ωⁱ) + β·k_j·ωⁱ + γ) /
                            (w_j(ωⁱ) + β·σ_j(ωⁱ) + γ)]

3. 驗證約束：
   - 起始：Z(ω⁰) = 1
   - 遞迴：如上述累積關係
   - 終止：Z(ω^n) = 1（因為是合法排列）

4. 多項式形式：
   L_0(X) · (Z(X) - 1) = 0
   Z(ωX) · ∏ⱼ(w_j(X) + β·k_j·X + γ)
     = Z(X) · ∏ⱼ(w_j(X) + β·σ_j(X) + γ)

佈線視覺化

電路佈線範例：
  計算 z = (x + y) · w

  Row | a    | b    | c    | 操作
  ----|------|------|------|------
  0   | x    | y    | t    | 加法：x + y = t
  1   | t    | w    | z    | 乘法：t · w = z
       ↑
       └── 複製約束：row0.c = row1.a

PLONKish 透過排列表示：
  σ(row0, col_c) = (row1, col_a)

排列循環表示：
  原始位置：(0,a), (0,b), (0,c), (1,a), (1,b), (1,c)
  排列 σ：  (0,a), (0,b), (1,a), (0,c), (1,b), (1,c)
                          └─┬─┘ └─┬─┘
                     位置交換，值必須相等

選擇器多項式（Selector Polynomials）

選擇器的作用

選擇器多項式控制門約束的啟用/禁用[1]：

選擇器機制：

門約束形式：
  s(X) · G(a(X), b(X), c(X), ...) = 0

當 s(ωⁱ) = 0 時：
  - 約束在 row i 被「關閉」
  - 0 · G(...) = 0 恆成立

當 s(ωⁱ) = 1 時：
  - 約束在 row i 被「啟用」
  - 必須滿足 G(...) = 0

範例：混合電路
  Row | a  | b  | c  | s_mul | s_add | 操作
  ----|----|----|----| ------|-------|------
  0   | 3  | 4  | 12 | 1     | 0     | 乘法
  1   | 5  | 7  | 12 | 0     | 1     | 加法
  2   | 2  | 2  | 4  | 1     | 0     | 乘法

選擇器壓縮

選擇器壓縮技術：

問題：多個選擇器增加 commitment 數量

方法 1：二進位編碼
  使用 ⌈log₂(m)⌉ 個選擇器編碼 m 種門
  例如 4 種門只需 2 個選擇器列

方法 2：線性組合
  若選擇器值不僅限於 {0,1}
  q(X) = Σᵢ αᵢ · qᵢ(X)
  單一多項式包含多個選擇器資訊

方法 3：表達式合併
  將多個門合併為單一複合約束
  G_combined = s₁·G₁ + s₂·G₂ + ...
  但需注意次數限制

選擇器最佳化範例

Halo2 選擇器組合：

// 未優化：每種門一個選擇器
let s_mul = meta.selector();
let s_add = meta.selector();
let s_const = meta.selector();

// 優化：使用組合選擇器
// s = 0: 無操作
// s = 1: 乘法
// s = 2: 加法
// s = 3: 常數

meta.create_gate("combined", |meta| {
    let s = meta.query_selector(s_combined);
    let a = meta.query_advice(col_a, Rotation::cur());
    let b = meta.query_advice(col_b, Rotation::cur());
    let c = meta.query_advice(col_c, Rotation::cur());

    // 使用拉格朗日基函數選擇約束
    // L₁(s) = s(s-2)(s-3)/((1-0)(1-2)(1-3)) 在 s=1 時為 1
    // 約束：L₁(s)·(a·b - c) + L₂(s)·(a+b - c) + ...
    vec![...]
});

Plookup 查表論證

Plookup 概述

查表是 PLONKish 的關鍵擴展[3]：

Definition 7：查表問題（Lookup Problem）

給定表格 \(T = \{t_1, \ldots, t_d\} \subset \mathbb{F}\) 和查詢向量 \(\mathbf{f} = (f_1, \ldots, f_n)\)，查表論證證明：

\[\forall i \in [n] : f_i \in T\]

即每個查詢值都存在於表格中。

Plookup 協議

Plookup 協議步驟：

輸入：
  - 表格 T = (t_1, ..., t_d)（sorted）
  - 查詢 f = (f_1, ..., f_n)

1. 合併與排序：
   s := sort(f ⊎ T)  // ⊎ 為多重集合聯集（multiset union），保留重複元素
   其中 m = n + d（查詢數 + 表格大小）
   實作時需選擇 N = 2^k ≥ m 並對 f, T, s 進行 padding

2. 關鍵觀察：
   若 f ⊆ T，則 s 中每對相鄰元素 (sᵢ, sᵢ₊₁) 要麼：
   - sᵢ = sᵢ₊₁（重複元素）
   - (sᵢ, sᵢ₊₁) 是 T 中的相鄰對

3. 構造累積多項式 Z(X)：
   Z(ω⁰) = 1

   Z(ω^{i+1}) = Z(ωⁱ) · [(1 + β)(γ + fᵢ)(γ(1+β) + tᵢ + βtᵢ₊₁)] /
                          [(γ(1+β) + sᵢ + βsᵢ₊₁)(γ(1+β) + sᵢ₊₁ + βsᵢ₊₂)]

4. 驗證：
   - Z(ω⁰) = 1
   - Z(ωⁿ⁺ᵈ) = 1
   - 上述遞迴關係成立

Plookup 複雜度

操作 複雜度 說明
排序 \(O((n+d) \log(n+d))\) 一次性預處理
證明者 \(O(n + d)\) 構造 Z(X) 和 commitment
驗證者 \(O(\log(n+d))\) 多項式開啟驗證
額外空間 \(O(1)\) 常數個多項式

ZKML 查表應用

ReLU 查表：
  T_relu = {(i, max(0, i)) : i ∈ [-2^k, 2^k]}

查詢：(input, output) ∈ T_relu

複雜度比較：
  - R1CS 位元分解：~254 約束/ReLU
  - PLONKish 查表：~1 約束/ReLU
  - 效率提升：~250 倍

其他常見查表：
  - Sigmoid/Tanh：預計算值
  - 範圍檢查：[0, 2^k)
  - 位元運算：XOR, AND
  - 除法/開根號：預計算表

多列查表

單列 vs 多列查表：

單列查表：
  證明 fᵢ ∈ T
  適用：範圍檢查、單輸入函數

多列查表（Halo2 風格）：
  證明 (f₁ᵢ, f₂ᵢ, ..., fₖᵢ) ∈ T
  適用：多輸入/輸出函數

實現方式：
  1. 隨機線性組合
     將 (f₁, f₂, ..., fₖ) 壓縮為 f₁ + θf₂ + θ²f₃ + ...
     單列查表壓縮後的值

  2. 多維 Plookup
     直接處理多列關係
     更高效但實現複雜

Halo2 查表實作

Halo2 查表配置：

// 定義查表列
let table = meta.lookup_table_column();

// 定義查表約束
meta.lookup("range_check", |meta| {
    let value = meta.query_advice(advice, Rotation::cur());
    let enable = meta.query_selector(s_lookup);

    // (表達式, 表格列) 對
    vec![(enable * value, table)]
});

// 多列查表
meta.lookup("relu", |meta| {
    let input = meta.query_advice(col_input, Rotation::cur());
    let output = meta.query_advice(col_output, Rotation::cur());
    let s = meta.query_selector(s_relu);

    vec![
        (s.clone() * input, table_input),
        (s * output, table_output)
    ]
});

// 填充表格
layouter.assign_table(|| "range", |mut table| {
    for i in 0..256 {
        table.assign_cell(
            || format!("row {}", i),
            self.table,
            i,
            || Value::known(F::from(i as u64)),
        )?;
    }
    Ok(())
})?;

AIR 與 PLONKish 比較

AIR（Algebraic Intermediate Representation）是 STARK 使用的算術化格式，與 PLONKish 有相似之處但也有關鍵差異。詳細的 AIR 介紹請參見 AIR 算術化頁面。

特性 AIR PLONKish
結構 執行軌跡 + 轉換約束 表格 + 自定義門 + 排列
跨行存取 自然支援（轉換約束） 透過 Rotation 支援
約束形式 任意多項式 任意多項式
查表 需要額外擴展 原生 Plookup 支援
複製約束 較弱（需顯式追蹤） 強大的排列論證
代表系統 STARK, Cairo, RISC Zero PLONK, Halo2
後量子安全 是（基於 FRI） 取決於 PCS
可信設置 不需要 取決於 PCS

ZKML 中的應用

模型層級電路設計

全連接層 PLONKish 設計：

// y = Wx + b，其中 W ∈ F^{m×n}

配置：
  - advice columns：輸入 x、輸出 y、中間累積
  - fixed columns：權重 W、偏置 b
  - selectors：啟用 MAC 操作

約束策略：
  1. 逐元素 MAC（Multiply-Accumulate）
  2. 使用自定義門優化
  3. 批次處理多個輸出

門定義：
  s_mac · (acc_new - acc_old - w · x) = 0

卷積層設計

卷積 PLONKish 策略：

方法 1：Im2col 展開
  - 將卷積轉為矩陣乘法
  - 使用全連接層電路
  - 需要大量複製約束

方法 2：直接卷積
  - 自定義卷積門
  - 利用 Rotation 存取相鄰像素
  - 更緊湊但設計複雜

方法 3：混合策略
  - 小核直接計算
  - 大核使用 Im2col

激活函數電路

ReLU PLONKish 實作：

// 策略 1：查表（推薦）
meta.lookup("relu", |meta| {
    let input = meta.query_advice(a, Rotation::cur());
    let output = meta.query_advice(b, Rotation::cur());
    vec![
        (input, table_input),
        (output, table_output)
    ]
});

// 策略 2：分解（無查表時）
// 證明 output = input · sign
// 其中 sign ∈ {0, 1} 且 sign=1 ⟺ input≥0

GeLU / Softmax：
  - 使用多項式近似
  - 或預計算查表
  - 精度與電路大小權衡

效能優化技術

行重用（Row Reuse）

觀察：許多操作可共享行

範例：a·b + c·d = e
標準方式：2 行（2 乘法 + 1 加法）
優化：自定義門，1 行完成

meta.create_gate("double_mac", |meta| {
    let a = meta.query_advice(col_a, Rotation::cur());
    let b = meta.query_advice(col_b, Rotation::cur());
    let c = meta.query_advice(col_c, Rotation::cur());
    let d = meta.query_advice(col_d, Rotation::cur());
    let e = meta.query_advice(col_e, Rotation::cur());

    vec![s * (a*b + c*d - e)]
});

列壓縮（Column Compression）

問題：列數影響證明大小

技術：
  1. 值打包：將多個小值放入一個域元素
  2. 共享列：不同區域使用同一列
  3. 階段化：分階段填充，減少同時活躍的列

範例：位元打包
  // 8 個 bit 打包成 1 個域元素
  packed = b0 + 2·b1 + 4·b2 + ... + 128·b7
