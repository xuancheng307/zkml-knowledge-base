IPA 內積論證

核心概念

IPA（Inner Product Argument）是一種不需要可信設置的多項式承諾方案，源自 Bulletproofs 協議[1]。透過遞迴折疊技術，IPA 實現了 O(log n) 的證明大小，是 Halo 和 Halo2 證明系統的核心組件[2]。

數學基礎

Pedersen 向量承諾

IPA 建立在 Pedersen 向量承諾之上。給定向量 \(\mathbf{a} = (a_1, \ldots, a_n)\) 和隨機生成元 \(\mathbf{G} = (G_1, \ldots, G_n)\)[1]：

$$C = \langle \mathbf{a}, \mathbf{G} \rangle = \sum_{i=1}^{n} a_i \cdot G_i$$

可選地加入遮罩值 \(r\) 以獲得隱藏性：

$$C = \langle \mathbf{a}, \mathbf{G} \rangle + r \cdot H$$

內積關係

IPA 的目標是證明[1]：

給定承諾 \(P\)、向量 \(\mathbf{G}, \mathbf{H}\)，以及公開值 \(c\)，
存在向量 \(\mathbf{a}, \mathbf{b}\) 使得：
1. \(P = \langle \mathbf{a}, \mathbf{G} \rangle + \langle \mathbf{b}, \mathbf{H} \rangle + \langle \mathbf{a}, \mathbf{b} \rangle \cdot U\)
2. \(\langle \mathbf{a}, \mathbf{b} \rangle = c\)

與多項式的聯繫

多項式求值可以表示為內積。對於多項式 \(f(X) = \sum_{i=0}^{n-1} c_i X^i\) 在點 \(z\) 的求值：

$$f(z) = \langle \mathbf{c}, (1, z, z^2, \ldots, z^{n-1}) \rangle = \langle \mathbf{c}, \mathbf{z} \rangle$$

這將多項式承諾問題轉化為內積論證。

IPA 協議

遞迴折疊

IPA 的核心是一個遞迴折疊過程，每輪將向量長度減半[1]：

IPA_Prove(G, H, U, P, a, b):
  n = len(a)
  if n == 1:
    return (a[0], b[0])  // 基礎情況

  n' = n / 2

  // 分割向量
  a_L, a_R = a[:n'], a[n':]
  b_L, b_R = b[:n'], b[n':]
  G_L, G_R = G[:n'], G[n':]
  H_L, H_R = H[:n'], H[n':]

  // 計算交叉項
  L =  +  +  · U
  R =  +  +  · U

  // Fiat-Shamir 挑戰
  x = Hash(transcript, L, R)

  // 折疊
  a' = a_L + x · a_R
  b' = x^(-1) · b_L + b_R
  G' = G_L + x^(-1) · G_R
  H' = x · H_L + H_R
  P' = L · x² + P + R · x^(-2)

  // 遞迴
  return (L, R) ++ IPA_Prove(G', H', U, P', a', b')

驗證過程

  // proof = [(L_1, R_1), ..., (L_k, R_k), (a, b)]
  // 其中 k = log₂(n)

複雜度分析

操作 時間複雜度 空間複雜度 說明
Setup O(n) O(n) 生成隨機生成元（透明）
Commit O(n) O(1) 多標量乘法
Prove O(n) O(log n) log n 輪，每輪 O(n/2^i)
Verify O(n) O(log n) 需計算 s 向量
驗證時間是主要缺點

IPA 的驗證時間為 O(n)，這是相比 KZG 的 O(1) 驗證的主要劣勢。在 ZKML 中，這意味著驗證大型模型電路需要更長時間。

Halo 優化：累積方案

Halo 引入了累積方案（accumulation scheme）來攤銷 IPA 驗證成本[2]：

延遲驗證

核心思想：
  不立即執行完整驗證，而是累積多個證明到單一"累積器"
  最終只需一次完整驗證

累積過程：
  1. 收到新證明 π
  2. 提取挑戰值 x_1, ..., x_k
  3. 計算部分承諾 P_partial
  4. 與現有累積器合併

最終驗證：
  - 對合併後的累積器執行一次 O(n) 驗證
  - 若有 m 個證明，攤銷成本為 O(n/m) 每個

遞迴證明

Halo2 利用 IPA 的結構實現高效遞迴[3]：

遞迴構造：
  1. 內層證明 π_inner 證明計算正確性
  2. 外層證明 π_outer 證明「π_inner 的驗證是正確的」

IPA 遞迴優勢：
  - 不需要配對電路（相比 KZG）
  - 驗證電路複雜度：O(log n) 群運算
  - 適合橢圓曲線循環（如 Pasta curves）

透明設置的意義

無可信設置

IPA 的設置完全透明[1]：

TransparentSetup(security_param, n):
  // 使用公開隨機性生成生成元
  seed = Hash("IPA-Setup")
  G = [HashToGroup(seed, i) for i in 1..n]
  H = [HashToGroup(seed, n+i) for i in 1..n]
  U = HashToGroup(seed, 2n+1)

  return (G, H, U)

安全性：
  - 無 toxic waste
  - 無需信任任何人
  - 設置可公開驗證

優化技術

批次驗證

多個 IPA 證明可以批次驗證[1]：

BatchVerify(proofs):
  // 使用隨機線性組合
  r_1, ..., r_m = Random(m)

  // 合併承諾
  P_combined = Σ r_i · P_i
  G_combined = same G (若使用相同設置)

  // 合併證明組件
  for each round k:
    L_k = Σ r_i · L_{i,k}
    R_k = Σ r_i · R_{i,k}

  // 單次驗證
  return Verify(P_combined, combined_proof)

效益：
  - m 個證明的驗證成本 ≈ 1.5 × 單個證明
  - 大幅攤銷 O(n) 驗證成本

預計算優化

標量向量 s 的預計算：

s_j = Π_{i: bit(j,i)=1} x_i · Π_{i: bit(j,i)=0} x_i^(-1)

優化：
  1. 計算 x_i · x_i^(-1) 對
  2. 使用二進制分解結構
  3. 並行計算 s 的各分量

複雜度：O(n) → O(n) 但常數因子更小

安全性分析

安全假設

IPA 的安全性基於離散對數假設[1]：

  • 離散對數假設（DL）：給定 \(G\) 和 \(aG\)，難以計算 \(a\)
  • 向量離散對數：給定 \(\{G_i\}\) 和 \(\sum a_i G_i\)，難以計算 \(\{a_i\}\)

綁定性證明

若攻擊者能找到兩組不同的 \((\mathbf{a}, \mathbf{b})\) 和 \((\mathbf{a}', \mathbf{b}')\) 對應同一承諾，則可提取離散對數。

知識可靠性

使用 Fiat-Shamir 變換時，需要隨機預言機模型。遞迴折疊過程確保攻擊者無法找到滿足驗證的假證明。

實作考量

曲線選擇

常用曲線：
  - Pasta curves (Pallas/Vesta)：Halo2 預設
  - Curve25519：高效能實現
  - secp256k1：與比特幣相容

選擇因素：
  - 遞迴需求 → Pasta curves
  - 效能優先 → Curve25519
  - 區塊鏈相容 → 原生曲線

記憶體管理

IPA 證明過程的記憶體需求：
  - 向量 a, b：O(n)
  - 生成元 G, H：O(n)（可能預計算）
  - 遞迴過程：O(log n) 個 (L, R) 對

優化策略：
  - 流式計算 s 向量
  - 延遲載入生成元
  - 並行折疊運算
