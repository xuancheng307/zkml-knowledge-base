IPA 內積論證

核心概念

IPA（Inner Product Argument）是一種不需要可信設置的多項式承諾方案，源自 Bulletproofs 協議[1]。透過遞迴折疊技術，IPA 實現了 O(log n) 的證明大小，是 Halo 和 Halo2 證明系統的核心組件[2]。其核心創新在於將 O(n) 的見證壓縮為 O(log n) 的證明，同時保持透明設置。

形式定義

定義 1：Pedersen 向量承諾

IPA 建立在 Pedersen 向量承諾之上[1]：

定義：Pedersen 向量承諾（Pedersen Vector Commitment）

給定橢圓曲線群 G，階為 p。
設 G = (G₁, G₂, ..., G_n) 和 H = (H₁, H₂, ..., H_n) 為獨立隨機生成元。

對向量 a = (a₁, a₂, ..., a_n) ∈ F_p^n：

Commit(G, a) = Σᵢ aᵢ · Gᵢ = ⟨a, G⟩

帶遮罩版本（Hiding）：
Commit(G, H, a, r) = ⟨a, G⟩ + r · H_blind

其中 r ←$ F_p 是隨機遮罩，H_blind 是獨立生成元。

性質：
  - 計算綁定：基於離散對數假設
  - 完美隱藏：r 隨機時，統計隱藏
  - 加法同態：Commit(a) + Commit(b) = Commit(a + b)

定義 2：內積關係

IPA 證明的核心目標[1]：

定義：內積關係（Inner Product Relation）

關係 R_IP 定義為：

R_IP = {
  (P, c; a, b) :
    P = ⟨a, G⟩ + ⟨b, H⟩ + c · U
    ∧ ⟨a, b⟩ = c
}

其中：
  - P ∈ G：承諾點
  - c ∈ F_p：內積值（公開）
  - a, b ∈ F_p^n：見證向量（私密）
  - G, H ∈ G^n：生成元向量
  - U ∈ G：內積綁定生成元

目標：
  證明者知道 (a, b) 使得：
  1. P 由 a, b 正確計算
  2. ⟨a, b⟩ = c

證明大小目標：O(log n) 而非 O(n)

定義 3：多項式求值作為內積

多項式求值可轉化為內積：

定義：多項式求值的內積表示

多項式 f(X) = Σᵢ cᵢ Xⁱ，次數 < n。
求值點 z ∈ F_p。

定義向量：
  a = (c₀, c₁, ..., c_{n-1})  // 係數
  b = (1, z, z², ..., z^{n-1}) // 冪次

則：
  f(z) = ⟨a, b⟩

多項式承諾應用：
  1. 承諾 C = Commit(G, a) = ⟨a, G⟩
  2. 證明 f(z) = y，即 ⟨a, b⟩ = y
  3. 使用 IPA 證明內積關係

轉換：
  P = C + ⟨b, H⟩ + y · U
  證明 (P, y; a, b) ∈ R_IP

定義 4：遞迴折疊

IPA 的核心技術[1]：

定義：向量折疊（Vector Folding）

給定挑戰 x ∈ F_p 和向量 a = (a_L, a_R)，|a_L| = |a_R| = n/2。

折疊操作：
  a' = a_L + x · a_R

性質：
  - |a'| = n/2（長度減半）
  - 若 a_L, a_R 固定，a' 唯一確定

生成元折疊：
  G' = G_L + x⁻¹ · G_R

折疊後承諾一致性：
  若 P = ⟨a, G⟩ 且 x 正確選取
  則 ⟨a', G'⟩ 與 P 相關（經過調整）

遞迴應用：
  k = log₂(n) 輪後，向量長度變為 1

定義 5：離散對數假設

IPA 的安全基礎：

定義：離散對數假設（Discrete Logarithm Assumption）

給定循環群 G，階為 p，生成元 g。

離散對數問題：
  給定 g 和 h = g^a，計算 a。

DL 假設：對任何 PPT 敵手 A：
  Pr[A(g, g^a) = a] ≤ negl(λ)

IPA 依賴的變體：

向量 DL（Vector DL）：
  給定 (G₁, ..., G_n) 和 C = Σ aᵢGᵢ
  難以找到 (a₁, ..., a_n)

與配對假設對比：
  - IPA：僅需 DL（較弱假設）
  - KZG：需 q-SDH + 配對（較強假設）

設計動機

IPA 設計動機：

1. 消除可信設置
   問題：KZG 需要 Powers of Tau 儀式
         - 組織成本高
         - 需信任至少一個參與者誠實
   IPA 解決方案：
         - 設置僅需公開隨機性
         - 無 toxic waste
         - 完全透明

2. 壓縮見證大小
   問題：樸素方法需發送整個向量 O(n)
   IPA 解決方案：
         - 遞迴折疊壓縮
         - O(log n) 證明大小
         - 每輪發送 2 個群元素

3. 支援高效遞迴
   問題：KZG 驗證需配對運算
         - 配對電路複雜
         - 遞迴成本高
   IPA 解決方案：
         - 驗證僅需群運算
         - 電路友好
         - 適合 2-cycle 曲線

與 Bulletproofs 的關係

Bulletproofs 與 IPA：

Bulletproofs 協議[1]：
  - 用於範圍證明和算術電路
  - IPA 是其核心子協議

IPA 在 Bulletproofs 中的角色：
  1. 範圍證明歸約到內積
     證明 v ∈ [0, 2^n)
     → 證明 ⟨a, b⟩ = δ 對特定 a, b

  2. 算術電路歸約
     電路滿足性
     → 內積關係

  3. 聚合證明
     多個範圍證明
     → 批次內積論證

Bulletproofs 創新：
  - O(log n) 範圍證明
  - 無可信設置
  - 機密交易應用

演化：
  Bulletproofs (2018) → Halo (2019) → Halo2 (2020+)

完整協議

IPA.Setup 演算法

演算法：IPA.Setup(1^λ, n)

輸入：
  - 安全參數 λ
  - 向量長度 n（通常為 2 的冪次）

輸出：
  - pp：公共參數

步驟：

1. 選擇橢圓曲線
   (G, p, g) ← CurveSetup(1^λ)
   確保 |G| = p 為大素數

2. 生成隨機生成元（使用 nothing-up-my-sleeve）
   seed ← "IPA-Setup-v1"

   對 i = 1, ..., n：
     G_i ← HashToGroup(seed || "G" || i)
     H_i ← HashToGroup(seed || "H" || i)

   U ← HashToGroup(seed || "U")

3. 輸出
   pp = (G, H, U)
   其中 G = (G₁, ..., G_n)，H = (H₁, ..., H_n)

透明性保證：
  - 任何人可重現相同的 pp
  - 無秘密參數
  - 可公開驗證

複雜度：
  - 時間：O(n) 雜湊到群運算
  - 空間：O(n) 群元素

IPA.Commit 演算法

演算法：IPA.Commit(pp, a)

輸入：
  - pp = (G, H, U)：公共參數
  - a = (a₁, ..., a_n)：向量

輸出：
  - C：承諾

步驟：

1. 計算向量承諾
   C = Σᵢ aᵢ · Gᵢ = ⟨a, G⟩

2. （可選）添加遮罩
   若需要隱藏性：
     r ←$ F_p
     C = ⟨a, G⟩ + r · H_blind

3. 輸出
   return C

多項式承諾變體：
  對多項式 f(X) = Σᵢ cᵢXⁱ：
  C = Commit(pp, (c₀, c₁, ..., c_{n-1}))

複雜度：
  - 時間：O(n) 群運算（MSM）
  - 空間：O(1) 輸出

IPA.Prove 演算法

演算法：IPA.Prove(pp, P, a, b, c)

輸入：
  - pp = (G, H, U)：公共參數
  - P = ⟨a, G⟩ + ⟨b, H⟩ + c · U：承諾
  - a, b：見證向量
  - c = ⟨a, b⟩：內積值

輸出：
  - π：IPA 證明

步驟：

初始化：
  n ← len(a)
  k ← log₂(n)
  transcript ← []
  proof ← []

遞迴折疊（共 k 輪）：

FOR round = 1 TO k:
  n' ← n / 2

  // 分割向量
  a_L, a_R ← a[0:n'], a[n':n]
  b_L, b_R ← b[0:n'], b[n':n]
  G_L, G_R ← G[0:n'], G[n':n]
  H_L, H_R ← H[0:n'], H[n':n]

  // 計算交叉項
  c_L ← ⟨a_L, b_R⟩
  c_R ← ⟨a_R, b_L⟩

  L ← ⟨a_L, G_R⟩ + ⟨b_R, H_L⟩ + c_L · U
  R ← ⟨a_R, G_L⟩ + ⟨b_L, H_R⟩ + c_R · U

  proof.append((L, R))

  // Fiat-Shamir 挑戰
  transcript.append((L, R))
  x ← Hash(transcript)
  x_inv ← x⁻¹ mod p

  // 折疊向量
  a ← a_L + x · a_R
  b ← x_inv · b_L + b_R

  // 折疊生成元
  G ← G_L + x_inv · G_R
  H ← x · H_L + H_R

  // 更新承諾（隱式）
  // P' = x² · L + P + x⁻² · R

  n ← n'

// 最終值
proof.append((a[0], b[0]))

return π = proof

IPA.Verify 演算法

演算法：IPA.Verify(pp, P, c, π)

輸入：
  - pp = (G, H, U)：公共參數
  - P：承諾
  - c：聲稱的內積值
  - π = [(L₁, R₁), ..., (L_k, R_k), (a_final, b_final)]：證明

輸出：
  - {accept, reject}

步驟：

1. 解析證明
   k ← len(π) - 1
   n ← 2^k

   LR_pairs ← π[0:k]
   (a_final, b_final) ← π[k]

2. 重建挑戰
   transcript ← []
   x ← []

   FOR i = 1 TO k:
     (L_i, R_i) ← LR_pairs[i-1]
     transcript.append((L_i, R_i))
     x[i] ← Hash(transcript)

3. 計算最終生成元
   // 標量向量 s
   s ← [1] * n
   FOR i = 1 TO k:
     FOR j = 0 TO n-1:
       IF bit(j, k-i) == 1:
         s[j] *= x[i]
       ELSE:
         s[j] *= x[i]⁻¹

   G_final ← ⟨s, G⟩
   H_final ← ⟨s⁻¹, H⟩

4. 計算調整後的承諾
   P' ← P
   FOR i = 1 TO k:
     P' ← x[i]² · L_i + P' + x[i]⁻² · R_i

5. 驗證
   expected ← a_final · G_final + b_final · H_final + (a_final · b_final) · U

   IF P' == expected AND a_final · b_final == c:
     return accept
   ELSE:
     return reject

複雜度分析：
  - 步驟 3（計算 s）：O(n)（瓶頸）
  - 步驟 3（計算 G_final）：O(n) MSM
  - 步驟 4：O(k) = O(log n)
  - 總驗證時間：O(n)

遞迴折疊詳解

折疊正確性

遞迴折疊正確性證明：

初始狀態：
  P = ⟨a, G⟩ + ⟨b, H⟩ + c · U
  其中 c = ⟨a, b⟩

分割後：
  P = ⟨a_L, G_L⟩ + ⟨a_R, G_R⟩ + ⟨b_L, H_L⟩ + ⟨b_R, H_R⟩ + c · U

定義交叉項：
  L = ⟨a_L, G_R⟩ + ⟨b_R, H_L⟩ + ⟨a_L, b_R⟩ · U
  R = ⟨a_R, G_L⟩ + ⟨b_L, H_R⟩ + ⟨a_R, b_L⟩ · U

給定挑戰 x，定義折疊：
  a' = a_L + x · a_R
  b' = x⁻¹ · b_L + b_R
  G' = G_L + x⁻¹ · G_R
  H' = x · H_L + H_R

計算 ⟨a', G'⟩：
  = ⟨a_L + x·a_R, G_L + x⁻¹·G_R⟩
  = ⟨a_L, G_L⟩ + x⁻¹⟨a_L, G_R⟩ + x⟨a_R, G_L⟩ + ⟨a_R, G_R⟩

類似地計算其他項...

最終：
  P' = x²·L + P + x⁻²·R
     = ⟨a', G'⟩ + ⟨b', H'⟩ + c' · U

其中 c' = ⟨a', b'⟩（可驗證）

折疊過程視覺化

IPA 折疊過程示例（n=8）：

第 0 輪（初始）：
  a = [a₀, a₁, a₂, a₃, a₄, a₅, a₆, a₇]  長度 8
  G = [G₀, G₁, G₂, G₃, G₄, G₅, G₆, G₇]

第 1 輪（x₁ 挑戰後）：
  a' = [a₀+x₁a₄, a₁+x₁a₅, a₂+x₁a₆, a₃+x₁a₇]  長度 4
  輸出 (L₁, R₁)

第 2 輪（x₂ 挑戰後）：
  a'' = [a'₀+x₂a'₂, a'₁+x₂a'₃]  長度 2
  輸出 (L₂, R₂)

第 3 輪（x₃ 挑戰後）：
  a''' = [a''₀+x₃a''₁]  長度 1
  輸出 (L₃, R₃, a_final)

證明結構：
  π = [(L₁,R₁), (L₂,R₂), (L₃,R₃), a_final, b_final]
  大小：2k + 2 = 2log₂(n) + 2 群元素

Halo 累積方案

延遲驗證

Halo 引入累積方案攤銷驗證成本[2]：

累積方案（Accumulation Scheme）：

問題：IPA 驗證需 O(n)，遞迴時成本累積

Halo 解決方案：延遲 O(n) 部分

觀察：IPA 驗證可分為兩部分
  1. O(log n) 部分：計算挑戰、驗證 LR 結構
  2. O(n) 部分：計算 G_final、H_final

累積策略：
  - 立即執行 O(log n) 部分
  - 累積 O(n) 部分到「累積器」
  - 最終只執行一次 O(n) 計算

累積器結構：
  Acc = (P_acc, challenges_acc)

累積步驟：
  Acc' = Accumulate(Acc, new_proof)
  使用隨機線性組合合併

最終驗證：
  - 對累積器執行單次 O(n) 驗證
  - m 個證明攤銷後：O(n/m) 每個

遞迴證明結構

Halo2 遞迴結構：

內層證明：
  π_inner 證明「計算 f(x) = y 正確」

外層證明：
  π_outer 證明「π_inner 的驗證正確」

IPA 遞迴優勢：
  驗證電路 = O(log n) 群運算 + O(n) MSM

  但 MSM 可累積！

  外層電路僅需：
  1. 重建挑戰 x₁, ..., x_k  — O(k) 雜湊
  2. 驗證 LR 結構 — O(k) 群運算
  3. 更新累積器 — O(1)

  不需在電路內執行 O(n) MSM

對比 KZG 遞迴：
  KZG 驗證 = 2 配對
  配對電路 ≈ 數百萬約束

  IPA 驗證電路 ≈ 數萬約束
  → IPA 更適合深度遞迴

操作 時間複雜度 空間複雜度 具體時間（n=2²⁰）

證明大小分析

IPA 證明結構：

證明組成：
  - k = log₂(n) 對 (L, R)
  - 1 個最終 a 值
  - 1 個最終 b 值

每個群元素大小：
  - Pasta curves：32 bytes（壓縮）
  - Curve25519：32 bytes

每個域元素大小：
  - 32 bytes

總證明大小：
  |π| = 2k × 32 + 2 × 32
      = 64(k + 1) bytes
      = 64(log₂(n) + 1) bytes

範例：
  n = 2¹⁰ (1K)：  |π| = 64 × 11 = 704 bytes
  n = 2¹⁶ (65K)： |π| = 64 × 17 = 1088 bytes
  n = 2²⁰ (1M)：  |π| = 64 × 21 = 1344 bytes
  n = 2²⁴ (16M)： |π| = 64 × 25 = 1600 bytes

安全性分析

完備性

定理：IPA 完備性

若證明者誠實執行協議，驗證者總是接受。

證明：歸納法

基礎情況（n=1）：
  P = a · G + b · H + (a·b) · U
  驗證者檢查：P == a·G + b·H + (a·b)·U ✓

歸納步驟：
  假設 n/2 時成立

  證明者計算 L, R 正確
  折疊後 P' = x²L + P + x⁻²R
  由折疊正確性，(P', a', b') 滿足關係

  由歸納假設，n/2 時驗證通過
  因此 n 時也通過 ✓

可靠性

定理：IPA 可靠性

若敵手能產生被接受的假證明，則可破解離散對數。

證明概要（歸約）：

假設敵手 A 可產生假證明：
  ∃ (P, c, π) 使 Verify 接受但 (P, c) ∉ L_IP

構造 DL 解題器 B：
  B 模擬 IPA 驗證過程
  使用 A 的證明提取矛盾

關鍵觀察：
  若 ⟨a, b⟩ ≠ c 但證明通過
  則可提取兩組不同的 a, b 表示
  → 離散對數關係

Soundness error：
  ≤ k · |F|⁻¹ + negl(λ)

  其中 k = log₂(n)，|F| = 群的階

對於 256-bit 曲線：
  soundness error ≤ 2⁻²⁵⁰ （可忽略）

零知識性

IPA 零知識分析：

基本 IPA 不是零知識的：
  - (L, R) 洩露部分 a, b 資訊
  - 最終 (a_final, b_final) 直接暴露

添加零知識（Bulletproofs 方法）：

1. 添加遮罩
   a' = a + r_a
   b' = b + r_b

   選擇 r_a, r_b 使：
   ⟨a', b'⟩ = ⟨a, b⟩ + 調整項

2. 交叉項遮罩
   L, R 也添加隨機化

3. 統計隱藏
   最終揭示的值被隨機化

定理（ZK-IPA）：
  帶遮罩的 IPA 是完美零知識的。

Halo2 應用：
  PLONK 層面處理零知識
  IPA 層面可不需額外遮罩

實作考量

曲線選擇

IPA 常用曲線：

1. Pasta Curves（Halo2 預設）
   Pallas: y² = x³ + 5 over F_p
   Vesta: y² = x³ + 5 over F_q

   特性：
   - 2-cycle：p = |Vesta|, q = |Pallas|
   - 適合高效遞迴
   - ~128-bit 安全

2. Curve25519
   y² = x³ + 486662x² + x

   特性：
   - 極高效能
   - 廣泛實現
   - 不形成 2-cycle

3. secp256k1
   y² = x³ + 7

   特性：
   - 比特幣/以太坊相容
   - 良好實現支援

選擇指南：
  - 遞迴應用 → Pasta curves
  - 最高效能 → Curve25519
  - 區塊鏈相容 → secp256k1

MSM 優化

多標量乘法優化（驗證瓶頸）：

問題：
  計算 G_final = ⟨s, G⟩ 需 O(n) 群運算

Pippenger 算法：
  - 將標量分組（窗口大小 w）
  - 預計算桶
  - 時間：O(n/log n)

Straus 算法：
  - 類似同時雙倍法
  - 適合小 n

並行化：
  - MSM 天然可並行
  - GPU 加速：10-100x

預計算生成元：
  若 G 固定，可預計算倍點表
  空間換時間

實際效能：
  CPU (單核)：~200 ms (n=2²⁰)
  CPU (8 核)：~40 ms
  GPU (RTX 4090)：~5 ms
