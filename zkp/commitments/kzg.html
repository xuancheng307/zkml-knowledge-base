KZG 多項式承諾

核心概念

KZG（Kate-Zaverucha-Goldberg）多項式承諾是一種基於配對的密碼學原語，允許證明者承諾一個多項式，並在之後證明該多項式在特定點的求值正確，而無需揭示整個多項式[1]。

數學基礎

雙線性配對

KZG 依賴於雙線性配對（bilinear pairing）的存在。給定三個群 \(\mathbb{G}_1, \mathbb{G}_2, \mathbb{G}_T\)，配對函數 \(e: \mathbb{G}_1 \times \mathbb{G}_2 \rightarrow \mathbb{G}_T\) 滿足[1]：

  • 雙線性：\(e(aP, bQ) = e(P, Q)^{ab}\) 對所有 \(a, b \in \mathbb{Z}_p\)
  • 非退化性：若 \(P \neq 0\) 且 \(Q \neq 0\)，則 \(e(P, Q) \neq 1\)
  • 可計算性：存在有效算法計算 \(e(P, Q)\)

常用配對友好曲線

曲線 安全級別 特點 應用
BN254 ~100 bits EVM 預編譯支援 以太坊智能合約驗證
BLS12-381 ~128 bits 更高安全性 Zcash、Ethereum 2.0
BLS12-377 ~128 bits 遞迴友好 Aleo

KZG 協議

可信設置（Trusted Setup）

KZG 需要一次性的可信設置，生成結構化參考字串（SRS）[1]：

Setup(1^λ, d) → SRS:
  1. 選取秘密 τ ∈ F_p（toxic waste）
  2. 計算 SRS = (
       [1]_1, [τ]_1, [τ²]_1, ..., [τ^d]_1,
       [1]_2, [τ]_2
     )
  3. 銷毀 τ（若 τ 洩露，協議不安全）

其中：
  [x]_1 = x · G_1（G_1 的生成元）
  [x]_2 = x · G_2（G_2 的生成元）
  d = 支援的最大多項式次數
可信設置的安全性

若任何參與者保留 τ，他們可以偽造證明。因此，實務上使用多方計算（MPC）儀式，只要有一個參與者誠實銷毀其貢獻，協議即安全。著名的 Powers of Tau 儀式有數千名參與者。

承諾（Commit）

對多項式 \(f(X) = \sum_{i=0}^{d} c_i X^i\) 進行承諾[1]：

$$C = \text{Commit}(f) = \sum_{i=0}^{d} c_i [\tau^i]_1 = [f(\tau)]_1$$

承諾 \(C\) 是 \(\mathbb{G}_1\) 中的單一群元素（BN254 上為 32 bytes）。

開啟證明（Open/Prove）

證明 \(f(z) = y\) 的過程[1]：

Open(f, z) → π:
  1. 計算商多項式 q(X) = (f(X) - y) / (X - z)
     （若 f(z) = y，則 (X - z) 整除 (f(X) - y)）

  2. 計算證明 π = [q(τ)]_1 = Commit(q)

證明大小：1 個 G_1 元素 = O(1)

驗證（Verify）

驗證者檢查配對等式[1]：

$$e(C - [y]_1, [1]_2) = e(\pi, [\tau]_2 - [z]_2)$$

展開驗證邏輯：

Verify(C, z, y, π) → {0, 1}:
  左側 = e(C - [y]_1, [1]_2)
       = e([f(τ) - y]_1, [1]_2)
       = e([f(τ) - y]_1, G_2)

  右側 = e(π, [τ - z]_2)
       = e([q(τ)]_1, [τ - z]_2)

  由雙線性：
    e([f(τ) - y]_1, G_2) = e([(τ-z)·q(τ)]_1, G_2)
                         = e([q(τ)]_1, [τ-z]_2)

  驗證通過 ⟺ f(τ) - y = (τ - z) · q(τ)
            ⟺ f(z) = y（多項式除法性質）

複雜度分析

操作 時間複雜度 空間複雜度 說明
Setup O(d) O(d) 一次性，可重用於所有次數 ≤ d 的多項式
Commit O(d) O(1) 多標量乘法（MSM）
Open O(d) O(1) 商多項式計算 + MSM
Verify O(1) O(1) 2 次配對運算

關鍵優勢：O(1) 驗證時間與O(1) 證明大小，這使 KZG 成為區塊鏈驗證的理想選擇。

批次驗證

KZG 支援高效的批次驗證，可同時驗證多個開啟證明[2]：

同一多項式多點開啟

驗證 \(f(z_1) = y_1, f(z_2) = y_2, \ldots, f(z_k) = y_k\)：

BatchOpen(f, {(z_i, y_i)}) → π:
  1. 定義零化多項式 Z(X) = ∏(X - z_i)
  2. 使用拉格朗日插值構造 I(X)，使 I(z_i) = y_i
  3. 計算 q(X) = (f(X) - I(X)) / Z(X)
  4. 返回 π = [q(τ)]_1

BatchVerify：
  e(C - [I(τ)]_1, [1]_2) = e(π, [Z(τ)]_2)

多個多項式單點開啟

使用隨機線性組合：

給定 (C_1, z, y_1), ..., (C_k, z, y_k) 和證明 π_1, ..., π_k
驗證者選取隨機 r ∈ F_p
檢查：
  e(∑ r^i(C_i - [y_i]_1), [1]_2) = e(∑ r^i π_i, [τ-z]_2)

在 ZKML 中的應用

ZKTorch 的使用

ZKTorch 選擇 KZG 作為預設承諾方案[3]：

考量 KZG 優勢
證明大小 ~9 KB（固定），適合鏈上驗證
驗證時間 ~3 ms，比 IPA 快 10-100 倍
證明聚合 高效的批次驗證支援並行累積

Halo2 with KZG

Halo2 證明系統支援 KZG 後端[4]：

ZKML 配置選項：
  backend = "halo2"
  commitment_scheme = "kzg"  # 或 "ipa"

KZG 後端特點：
  - 需要可信設置（使用現有 Powers of Tau）
  - 證明較小（~10-20 KB）
  - 驗證較快（~10 ms）
  - 適合需要鏈上驗證的應用

安全性分析

安全假設

KZG 的安全性基於以下困難問題[1]：

  • q-SDH（q-Strong Diffie-Hellman）假設： 給定 \((g, g^\tau, g^{\tau^2}, \ldots, g^{\tau^q})\)，難以計算 \((c, g^{1/(\tau+c)})\) 對任意 \(c\)
  • 配對假設：離散對數問題在 \(\mathbb{G}_1, \mathbb{G}_2, \mathbb{G}_T\) 中均困難

綁定性（Binding）

承諾具有計算綁定性：攻擊者無法找到兩個不同的多項式 \(f \neq g\) 使得 \(\text{Commit}(f) = \text{Commit}(g)\)。

隱藏性（Hiding）

基本 KZG 不具備隱藏性（承諾是確定性的）。若需隱藏性，可使用 Pedersen 變體：

$$C = [f(\tau)]_1 + r \cdot [h(\tau)]_1$$

其中 \(r\) 是隨機遮罩值，\(h\) 是另一組 SRS。

實作考量

多標量乘法（MSM）優化

承諾計算的瓶頸是 MSM。常用優化技術：

  • Pippenger 算法：將 O(n) 次獨立群運算降至 O(n/log n)
  • 並行化：MSM 天然可並行
  • GPU 加速：現代 GPU 可實現 10-100 倍加速

SRS 管理

常用 Powers of Tau 儀式：
  - Zcash Powers of Tau：支援 2^28 次
  - Ethereum KZG Ceremony：支援 2^16 次
  - Perpetual Powers of Tau：持續擴展

使用建議：
  - 下載預計算的 SRS（避免重複計算）
  - 根據電路大小選擇適當的 SRS 規模
  - 驗證 SRS 的正確性（使用配對檢查）
