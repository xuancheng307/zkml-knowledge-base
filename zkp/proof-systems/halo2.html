Halo2 證明系統

核心概念

Halo2 是由 Zcash 基金會開發的先進零知識證明系統，結合了 Halo 論文[1]的無需可信設置遞迴證明技術與 PLONK[2]的靈活算術化。Halo2 的核心創新包括：(1) 基於內積論證（IPA）的多項式承諾，消除可信設置需求；(2) 巢狀攤銷（Nested Amortization）策略實現高效遞迴；(3) PLONKish 表格系統支援自定義門和查表。這些特性使 Halo2 成為 ZKML 框架（如 EZKL）的首選後端。

形式化定義

定義 1（Pedersen 向量承諾）

給定生成元向量 G = (G₁, ..., G_n) ∈ G^n 和獨立生成元 H ∈ G，對向量 a = (a₁, ..., a_n) ∈ F^n 的 Pedersen 承諾定義為：

C = ⟨a, G⟩ + r·H = Σᵢ aᵢ·Gᵢ + r·H

其中：
  ⟨·,·⟩ 表示內積
  r ∈ F 是隨機遮罩值（提供隱藏性）
定義 2（內積關係）

IPA 證明的核心關係：給定承諾 P、生成元 G, H, U 和公開值 c，存在向量 a, b 使得：

P = ⟨a, G⟩ + ⟨b, H⟩ + ⟨a, b⟩·U
⟨a, b⟩ = c

其中 U 是與內積值關聯的特殊生成元。
定義 3（多項式承諾與開啟）

多項式承諾將多項式 f(X) 編碼為群元素，開啟證明 f(z) = y：

關鍵觀察：
  f(z) = ⟨coeffs(f), (1, z, z², ..., z^{n-1})⟩
       = ⟨a, z⟩  (視為內積)

因此：
  Commit(f) = ⟨coeffs(f), G⟩
  Open(f, z) = IPA 證明 ⟨a, z⟩ = f(z)
定義 4（橢圓曲線 2-cycle）

曲線對 (E₁, E₂) 形成 2-cycle，若：

|E₁(F_p)| = q  （E₁ 在 F_p 上的群階）
|E₂(F_q)| = p  （E₂ 在 F_q 上的群階）

意義：
  E₁ 上的計算可以表示為 E₂ 上的電路，反之亦然。
  這使得無限深度的遞迴成為可能。
定義 5（PLONKish 約束系統）

PLONKish 電路由以下組成：

電路結構 C = (n, m, k, {qᵢ}, σ, {Tⱼ})

其中：
  n = 行數（2 的冪次）
  m = advice 列數
  k = fixed 列數
  {qᵢ} = 門約束多項式
  σ = 複製約束排列
  {Tⱼ} = 查表定義

門約束：
  對每行 i：qᵢ(a₁[i], ..., aₘ[i], f₁[i], ..., fₖ[i]) = 0

複製約束：
  σ 定義哪些單元格必須相等
定義 6（累積方案）

累積方案 (A, D, V) 允許延遲驗證[1]：

Accumulate(acc, π) → acc'
  將新證明 π 與累積器 acc 合併

Decide(acc) → {0, 1}
  最終驗證累積器

性質：
  若任一 π 無效，則最終 Decide 失敗
  攤銷：n 個證明的驗證成本 ≈ 1 個證明
定義 7（Lookup Argument）

查表論證證明向量 f 的每個元素都在表格 T 中：

給定：
  查詢向量 f = (f₁, ..., fₙ)
  表格 T = (t₁, ..., tₐ)

證明：
  ∀i ∈ [n]: fᵢ ∈ T

Plookup 方法：
  1. 排序 f ∪ T 得到 s
  2. 證明 s 是有效排序
  3. 證明相鄰差異合法

IPA 多項式承諾詳解

遞迴折疊協議

IPA_Prove(G, H, U, P, a, b, c)：

輸入：
  G, H ∈ G^n：生成元向量
  U ∈ G：內積生成元
  P ∈ G：承諾（P = ⟨a,G⟩ + ⟨b,H⟩ + c·U）
  a, b ∈ F^n：被承諾的向量
  c = ⟨a, b⟩：宣稱的內積值

協議（log n 輪）：

if n == 1:
  return (a[0], b[0])  // 基礎情況

// 分割向量為左右兩半
n' = n / 2
a_L, a_R = a[0:n'], a[n':n]
b_L, b_R = b[0:n'], b[n':n]
G_L, G_R = G[0:n'], G[n':n]
H_L, H_R = H[0:n'], H[n':n]

// 計算交叉項承諾
c_L = ⟨a_L, b_R⟩
c_R = ⟨a_R, b_L⟩

L = ⟨a_L, G_R⟩ + ⟨b_R, H_L⟩ + c_L · U
R = ⟨a_R, G_L⟩ + ⟨b_L, H_R⟩ + c_R · U

// Fiat-Shamir 挑戰
x = Hash(transcript, L, R)

// 折疊
a' = a_L + x · a_R
b' = x⁻¹ · b_L + b_R
G' = G_L + x⁻¹ · G_R
H' = x · H_L + H_R
P' = x² · L + P + x⁻² · R
c' = c_L · x² + c + c_R · x⁻²

// 遞迴
return [(L, R)] ++ IPA_Prove(G', H', U, P', a', b', c')

驗證演算法

IPA_Verify(G, H, U, P, c, proof)：

輸入：
  G, H, U：公開參數
  P：承諾
  c：宣稱的內積值
  proof = [(L₁,R₁), ..., (Lₖ,Rₖ), (a,b)]：證明

// 重建挑戰序列
transcript = []
x = []
for i = 1 to k:
  xᵢ = Hash(transcript, Lᵢ, Rᵢ)
  x.append(xᵢ)
  transcript.append(xᵢ)

// 計算折疊後的生成元（關鍵步驟）
s = compute_s_vector(x)  // O(n) 計算
G_final = ⟨s, G⟩
H_final = ⟨s⁻¹, H⟩

// 計算折疊後的承諾
P_final = P
for i = 1 to k:
  P_final = xᵢ² · Lᵢ + P_final + xᵢ⁻² · Rᵢ

// 最終檢查
return P_final == a · G_final + b · H_final + (a·b) · U
   AND a · b == c

compute_s_vector(x)：
  // s_j = ∏_{i: bit(j,i)=1} xᵢ · ∏_{i: bit(j,i)=0} xᵢ⁻¹
  s = [1] * n
  for j = 0 to n-1:
    for i = 0 to k-1:
      if bit(j, k-1-i) == 1:
        s[j] *= x[i]
      else:
        s[j] *= x[i]⁻¹
  return s

複雜度分析

操作 證明者 驗證者 證明大小
時間 O(n) O(n) -
群運算 ~6n ~2n + 2k -
通訊 - - 2k + 2 元素

其中 k = log₂(n)。證明大小為 O(log n) 群元素。

驗證複雜度是主要缺點

IPA 的驗證需要 O(n) 時間來計算 G_final = ⟨s, G⟩，這是相比 KZG O(1) 驗證的主要劣勢。Halo 的巢狀攤銷技術正是為了解決這個問題。

巢狀攤銷（Nested Amortization）

核心問題

遞迴驗證的挑戰：

在電路內驗證 IPA 證明需要計算：
  G_final = ⟨s, G⟩ = s₁·G₁ + s₂·G₂ + ... + sₙ·Gₙ

這是一個 n 項 MSM（多標量乘法）。

電路成本：
  每個標量乘法 ≈ 256 個約束（bit-by-bit）
  n = 2^17 → ≈ 33M 約束

問題：
  遞迴電路比原始電路還大！
  無法實際使用

巢狀攤銷解決方案

Halo 的關鍵洞察：

不在當前電路中完成 MSM，而是：
  1. 將 MSM 計算「推遲」到外層
  2. 在當前電路只做「累積」
  3. 最外層一次性完成所有累積的 MSM

累積器結構：
  acc = (P, s_acc)

  P = 當前承諾
  s_acc = 累積的 s 向量信息

累積步驟（電路內）：
  1. 接收內層證明 πᵢₙₙₑᵣ
  2. 驗證除 MSM 外的所有檢查
  3. 將 MSM 信息合併到累積器
  4. 輸出新累積器

最終驗證（電路外）：
  一次完成所有累積的 MSM
  驗證累積的正確性

形式化描述

累積方案協議：

Accumulate(accₒₗₐ, π_new) → acc_new：

  // 從 π_new 提取
  (L, R, challenges) = π_new
  x = challenges

  // 計算部分折疊
  P_partial = compute_partial_fold(L, R, x)
  s_partial = compute_s_structure(x)

  // 隨機線性組合合併
  ρ ← Random()
  acc_new.P = accₒₗₐ.P + ρ · P_partial
  acc_new.s = accₒₗₐ.s ⊕ᵨ s_partial

  return acc_new

Decide(acc) → {0, 1}：
  // 最終執行累積的 MSM
  G_acc = ⟨acc.s, G⟩

  // 驗證累積器有效性
  return acc.P == expected_from_G_acc

電路內成本：
  每次累積 ≈ O(log n) 約束
  （而非 O(n · 256) 約束）

Pasta 曲線（橢圓曲線 2-cycle）

曲線定義

Pasta 曲線對（由 Zcash 設計）：

Pallas 曲線：
  方程式：y² = x³ + 5
  定義域：F_p，其中 p = 2^254 + 45560315531506369815346746415080538113
  群階：q = 2^254 + 45560315531419706090280762371685220353

  安全性：~126 bits (Pollard rho)

Vesta 曲線：
  方程式：y² = x³ + 5
  定義域：F_q（使用 Pallas 的群階作為基域）
  群階：p（即 Pallas 的基域大小）

  安全性：~126 bits (Pollard rho)

2-cycle 性質：
  |Pallas| = q = |F_Vesta|
  |Vesta| = p = |F_Pallas|

  → Pallas 上的運算可表示為 Vesta 電路
  → Vesta 上的運算可表示為 Pallas 電路
  → 無限遞迴成為可能

遞迴構造

使用 Pasta 的遞迴證明：

層級結構：
  Level 0：原始計算（在 Pallas 上）
  Level 1：驗證 Level 0 證明（在 Vesta 上）
  Level 2：驗證 Level 1 證明（在 Pallas 上）
  Level 3：驗證 Level 2 證明（在 Vesta 上）
  ...

交替使用兩條曲線：
  Pallas → Vesta → Pallas → Vesta → ...

每層的電路：
  1. 計算新的語句
  2. 驗證前一層的證明
  3. 生成當前層的證明

最終證明：
  - 一個簡潔的累積器
  - 可在任一曲線上驗證

PLONKish 算術化

表格結構

Halo2 電路表格：

  Row | Advice (私密)  | Instance (公開) | Fixed (常數)  | Selector
  ----|----------------|-----------------|---------------|----------
  0   | a[0], b[0]     | x[0]           | q_L, q_R, ... | s_mul
  1   | a[1], b[1]     | x[1]           | ...           | s_add
  2   | a[2], b[2]     |                | ...           | s_mul
  ... | ...            | ...            | ...           | ...
  n-1 | a[n-1], b[n-1] |                | ...           | ...

列類型：
  Advice：證明者填入的私密見證值
  Instance：公開輸入/輸出
  Fixed：電路定義時固定的常數
  Selector：啟用/禁用特定門的開關

行數 n：必須是 2 的冪次（用於 FFT）

門約束系統

標準 PLONK 門：

q_L·a + q_R·b + q_O·c + q_M·(a·b) + q_C = 0

Halo2 擴展：

1. 自定義門：任意多項式約束
   meta.create_gate("custom", |meta| {
       let a = meta.query_advice(col_a, Rotation::cur());
       let b = meta.query_advice(col_b, Rotation::cur());
       let c = meta.query_advice(col_c, Rotation::cur());
       let s = meta.query_selector(s_custom);

       // 可以是任意多項式
       vec![s * (a.clone() * a.clone() - b)]  // a² = b
   });

2. 跨行存取：Rotation
   Rotation::cur()   // 當前行
   Rotation::prev()  // 前一行
   Rotation::next()  // 下一行
   Rotation(n)       // 第 n 行

3. 多項式約束：
   可使用高次多項式
   門的度數影響證明效率

複製約束

排列論證（Permutation Argument）：

目標：證明不同位置的值相等

範例：
  Row 0, Col a：值 v
  Row 5, Col b：值 v（必須相等）
  Row 8, Col c：值 v（必須相等）

排列定義：
  σ(0, a) = (5, b)
  σ(5, b) = (8, c)
  σ(8, c) = (0, a)  // 形成循環

多項式編碼：
  1. 將位置編碼為域元素
  2. 構造累積多項式 Z(X)
  3. Z 在域上形成閉環

驗證：
  ∏(wᵢ + β·position_i + γ) = ∏(wᵢ + β·σ(position_i) + γ)

Halo2 實現：
  layouter.assign_advice_from_instance(...)  // 連接 instance 到 advice
  region.constrain_equal(cell1, cell2)        // 強制相等

Lookup Arguments（查表）

Plookup 協議

Plookup 目標：

證明查詢向量 f 的每個元素都在表格 T 中：
  f = (f₁, f₂, ..., fₙ)  ← 需要查詢的值
  T = (t₁, t₂, ..., tₐ)  ← 預定義的表格

協議步驟：

1. 合併與排序
   s = sort(f ∪ T)

   排序後相鄰元素要麼相等，要麼來自表格的相鄰位置

2. 構造輔助多項式
   f(X), t(X)：查詢和表格的多項式表示
   s(X)：排序後的多項式
   h(X)：輔助多項式

3. 驗證排序正確性
   使用累積論證證明：
   (1 + β)^n · ∏(γ + fᵢ) · ∏(γ(1+β) + tᵢ + β·tᵢ₊₁)
   = ∏(γ(1+β) + sᵢ + β·sᵢ₊₁)

4. 隨機挑戰壓縮
   使用 Fiat-Shamir 生成 β, γ

Halo2 查表實現

// 定義查表（在配置階段）
fn configure(meta: &mut ConstraintSystem) -> Self::Config {
    let advice = meta.advice_column();
    let table = meta.lookup_table_column();

    // 定義查表約束
    meta.lookup("range_check", |meta| {
        let value = meta.query_advice(advice, Rotation::cur());
        let selector = meta.query_selector(s_lookup);

        // (input_expression, table_column)
        vec![(selector * value, table)]
    });

    Config { advice, table, s_lookup }
}

// 填充表格（在合成階段）
fn synthesize(...) {
    layouter.assign_table(|| "8-bit range table", |mut table| {
        for i in 0u64..256 {
            table.assign_cell(
                || format!("row {}", i),
                self.config.table,
                i as usize,
                || Value::known(F::from(i)),
            )?;
        }
        Ok(())
    })?;
}

安全性分析

安全假設

定義 8（離散對數假設，DL）

給定群生成元 G 和群元素 P = [x]G，計算 x 是計算不可行的。

DL 假設強度層級：

弱 ← DL ← CDH ← DDH → 強

Halo2 僅需 DL 假設
（比 KZG 需要的 q-SDH 更保守）

安全性質

定理（Halo2 安全性）：

在 DL 假設和隨機預言機模型下，Halo2 證明系統滿足：

1. 完備性（Perfect Completeness）
   誠實證明者總能生成有效證明

2. 知識可靠性（Knowledge Soundness）
   若證明有效，則存在提取器可提取見證
   ε_sound ≤ negl(λ)

3. 零知識（Perfect Zero-Knowledge）
   存在模擬器 S，使得 Real 和 Simulated 分布相同

證明框架：

知識可靠性論證：
  IPA 的可靠性來自內積論證的綁定性
  折疊過程的正確性由 Schwartz-Zippel 保證

零知識論證：
  隨機遮罩值 r 使承諾均勻分布
  挑戰來自隨機預言機

Fiat-Shamir 安全性

互動到非互動轉換：

原始協議：互動式（需要驗證者隨機性）
Fiat-Shamir：用雜湊替代隨機性

安全性要求：
  1. 雜湊函數 H 建模為隨機預言機
  2. transcript 包含所有先前消息
  3. 攻擊者無法預測 H 的輸出

實現注意：
  - 必須正確構造 transcript
  - 包含所有公開輸入
  - 按正確順序加入消息

Halo2 實現：
  use halo2_proofs::transcript::{Blake2bRead, Blake2bWrite};
  // 使用 Blake2b 作為隨機預言機

ML 層電路設計

全連接層 Halo2 實現：

// y = Wx + b

struct FCConfig {
    advice: [Column; 3],  // input, weight, output
    fixed: Column,          // bias
    s_mac: Selector,               // MAC 操作選擇器
}

fn configure(meta: &mut ConstraintSystem) -> FCConfig {
    let [input, weight, output] = [0; 3].map(|_| meta.advice_column());
    let bias = meta.fixed_column();
    let s_mac = meta.selector();

    meta.create_gate("MAC", |meta| {
        let inp = meta.query_advice(input, Rotation::cur());
        let wgt = meta.query_advice(weight, Rotation::cur());
        let out = meta.query_advice(output, Rotation::cur());
        let b = meta.query_fixed(bias, Rotation::cur());
        let s = meta.query_selector(s_mac);

        // 累加約束：out_new = out_old + inp * wgt
        // 最終加 bias
        vec![s * (out - inp * wgt - b)]
    });

    FCConfig { advice: [input, weight, output], fixed: bias, s_mac }
}

配置參數調優

參數 影響 推薦值
k (logrows) 電路容量 = 2^k 行 根據模型大小選擇
lookup_bits 查表精度，影響非線性近似 8-16（通常 12）
scale 定點數縮放因子 2^scale，通常 scale=7-15
bits 數值表示位寬 16-32

實現考量

EVM 相容性

問題：Pasta 曲線與 EVM 不相容

EVM 原生支援：BN254 曲線
Halo2 (IPA)：Pasta 曲線（Pallas/Vesta）

解決方案：

1. 遞迴包裝（推薦）
   Halo2 證明 → Groth16/KZG 包裝 → EVM 驗證

   流程：
   a. 生成 Halo2 (IPA) 證明
   b. 創建 BN254 電路驗證 Halo2 證明
   c. 生成 Groth16 證明
   d. EVM 驗證 Groth16

   優點：最終證明小、驗證便宜
   缺點：額外證明時間

2. KZG 後端
   使用 Halo2 + KZG (BN254)

   EZKL 配置：
   { "commitment": "kzg" }

   優點：直接 EVM 相容
   缺點：需要可信設置

3. 自定義驗證合約
   在 EVM 中實現 Pasta 曲線運算

   優點：無需包裝
   缺點：Gas 成本高（~2-5M gas）

記憶體優化

大型電路的記憶體挑戰：

問題：
  k=24（16M 行）需要 ~256 GB RAM
  超出普通機器能力

優化策略：

1. 列拆分
   將寬電路拆分為多個窄電路
   分別證明後聚合

2. 流式見證生成
   不一次生成所有見證
   按需計算和釋放

3. GPU 加速
   將 MSM/FFT 卸載到 GPU
   減少 CPU 記憶體壓力

4. 磁盤交換
   將不活躍數據交換到磁盤
   犧牲速度換取容量

  - 支援模型拆分
