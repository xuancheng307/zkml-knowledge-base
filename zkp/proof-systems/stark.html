STARK

核心概念

STARK（Scalable Transparent ARgument of Knowledge）是一種不需要可信設置的證明系統，由 Eli Ben-Sasson 等人於 2018 年提出[1]。STARK 僅依賴雜湊函數的安全性，具備後量子安全性，適合大規模計算的驗證。

核心特性

特性 STARK 說明
透明設置 是 無需可信第三方
後量子安全 是 僅依賴雜湊函數
證明大小 O(log² n) ~50-200 KB
驗證時間 O(log² n) ~10-50 ms
證明時間 O(n log n) 準線性

系統架構

STARK 流程

STARK 證明流程：

1. 算術化（Arithmetization）
   計算 → AIR（Algebraic Intermediate Representation）
   - 定義執行軌跡
   - 定義多項式約束

2. 軌跡生成
   執行計算，記錄每步狀態
   軌跡 T: n × w 矩陣

3. 低度擴展（LDE）
   將軌跡編碼為多項式
   擴展到更大的評估域

4. FRI 承諾
   使用 FRI 證明多項式是低度的
   Merkle 樹承諾

5. 查詢與驗證
   隨機查詢點
   驗證約束滿足 + FRI 證明

AIR 約束

AIR（Algebraic Intermediate Representation）：

軌跡結構：
  T[i, j] = 第 i 步的第 j 個寄存器

約束類型：

1. 邊界約束（Boundary Constraints）
   指定特定位置的值
   T[0, 0] = input_0
   T[n-1, 1] = output

2. 轉換約束（Transition Constraints）
   定義相鄰步驟的關係
   例如：T[i+1, 0] = T[i, 0] + T[i, 1]

多項式表示：
   軌跡多項式：t_j(X) 插值第 j 列
   約束多項式：C(t_0(X), t_1(X), ..., t_0(ωX), t_1(ωX), ...)

   若約束滿足，C 在所有軌跡點為零

FRI 協議

核心機制

FRI（Fast Reed-Solomon Interactive Oracle Proof）是 STARK 的核心[2]：

FRI 目標：證明函數接近低度多項式

協議步驟：

1. 承諾階段
   - 對多項式 f(X) 在擴展域 D 上求值
   - 建立 Merkle 樹承諾

2. 折疊階段（log d 輪）
   - 收到隨機挑戰 α
   - 折疊：f'(X) = f_even(X) + α · f_odd(X)
   - 次數減半
   - 提交新多項式

3. 查詢階段
   - 隨機選取查詢點
   - 提供 Merkle 證明
   - 驗證折疊一致性

複雜度：
  證明大小：O(λ · log² d)
  驗證時間：O(λ · log² d)
  其中 λ = 安全參數

FRI 詳解

FRI 折疊過程：

初始：f(X) 次數 d

第 1 輪：
  f(X) = f_even(X²) + X · f_odd(X²)
  f₁(X) = f_even(X) + α₁ · f_odd(X)
  次數：d/2

第 k 輪：
  f_k(X) = f_{k-1,even}(X) + α_k · f_{k-1,odd}(X)
  次數：d/2^k

最終：
  f_final = 常數

驗證者檢查：
  每輪的折疊關係正確
  最終值為常數

安全性

安全假設

STARK 安全基於：

1. 抗碰撞雜湊函數
   用於 Merkle 樹承諾

2. 隨機預言機模型
   Fiat-Shamir 變換

安全論證：
  - 若 f 不是低度多項式
  - 則 f 與任何低度多項式有顯著距離
  - FRI 驗證會以高機率拒絕

soundness error ≈ (ρ + ε)^λ
  ρ = 碼率
  ε = 接近性參數
  λ = 查詢次數

後量子安全

量子安全分析：

STARK 使用的原語：
  - 雜湊函數（SHA-256, BLAKE3）
  - 有限域算術

量子攻擊影響：
  - Grover 算法：碰撞查找 O(2^{n/2}) → O(2^{n/3})
  - 需增加雜湊輸出長度（256 → 384 bits）

對比 SNARK：
  - SNARK 基於橢圓曲線
  - Shor 算法可破解
  - 不具後量子安全

效能分析

證明大小

STARK 證明組成：

1. 軌跡承諾
   ~32 bytes × log(trace_length)

2. 約束承諾
   ~32 bytes × log(constraint_degree)

3. FRI 證明
   ~32 bytes × λ × log² d
   λ ≈ 64（128-bit 安全）

典型大小：
  小電路（~10K 約束）：~50 KB
  中電路（~1M 約束）：~100 KB
  大電路（~100M 約束）：~200 KB

與 SNARK 比較：
  SNARK：~200 bytes（固定）
  STARK：隨電路規模對數增長

效能基準

電路規模 證明時間 驗證時間 證明大小
2²⁰ (~1M) ~5 秒 ~20 ms ~80 KB
2²⁴ (~16M) ~30 秒 ~30 ms ~120 KB
2²⁸ (~256M) ~5 分鐘 ~50 ms ~180 KB

與 SNARK 結合

STARK → SNARK 包裝：

動機：
  - STARK 證明太大無法直接上鏈
  - SNARK 驗證更便宜

方法：
  1. 生成 STARK 證明（鏈下）
  2. SNARK 電路驗證 STARK 證明
  3. 生成 SNARK 證明
  4. 鏈上驗證 SNARK

工具：
  - Groth16 包裝（~200 bytes 最終證明）
  - 複雜度：額外證明時間

應用：
  - StarkNet（STARK → Groth16）
  - Polygon zkEVM

實現細節

域選擇

STARK 常用域：

1. 小素數域
   - p = 2^64 - 2^32 + 1（Goldilocks）
   - 效率高，適合 64-bit CPU

2. 擴展域
   - F_p² 或更高次擴展
   - 增加安全性

3. 二進位域
   - F_{2^n}
   - 硬體友好

ZKML 考量：
  - 域大小需容納激活值範圍
  - 量化後通常 8-16 bit 足夠

優化技術

STARK 優化：

1. 並行 FFT
   - 多核 CPU 加速
   - GPU FFT 實現

2. 批次 Merkle
   - 減少雜湊計算

3. 遞迴證明
   - 分段並行證明
   - 最終聚合

4. 硬體加速
   - FPGA/ASIC
   - 專用雜湊硬體

效能提升：
  單核 → 多核：4-8x
  CPU → GPU：10-50x
