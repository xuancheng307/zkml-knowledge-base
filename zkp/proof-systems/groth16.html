Groth16

核心概念

Groth16 是目前最高效的 zk-SNARK 證明系統之一，由 Jens Groth 於 2016 年提出[1]。它具有最小的證明大小（3 個群元素，~192 bytes）和最快的驗證時間（3 次配對），是區塊鏈應用的首選方案。

系統特性

特性 Groth16 說明
證明大小 192 bytes 3 個群元素（2G₁ + 1G₂）
驗證時間 ~3 ms 3 次配對運算
證明時間 O(n log n) n = 電路大小
可信設置 電路特定 每個電路需獨立設置
安全假設 q-PKE + 配對 強假設

數學基礎

R1CS 到 QAP

Groth16 基於 QAP（Quadratic Arithmetic Program）[1]：

從 R1CS 到 QAP：

R1CS 約束：(Aw) ∘ (Bw) = Cw

QAP 轉換：
  1. 選取 m 個點 {r₁, ..., rₘ}
  2. 對每列 j，插值多項式：
     uⱼ(X), vⱼ(X), wⱼ(X)
  3. 定義：
     A(X) = Σ wⱼ · uⱼ(X)
     B(X) = Σ wⱼ · vⱼ(X)
     C(X) = Σ wⱼ · wⱼ(X)
  4. 零化多項式：t(X) = ∏(X - rᵢ)

QAP 關係：
  A(X) · B(X) - C(X) = h(X) · t(X)
  對某個商多項式 h(X)

配對群結構

雙線性群設置：

群：G₁, G₂, G_T（同階 p）
配對：e: G₁ × G₂ → G_T
生成元：G₁ 的 g₁，G₂ 的 g₂

雙線性性質：
  e(aP, bQ) = e(P, Q)^{ab}

符號約定：
  [x]₁ = x · g₁ ∈ G₁
  [x]₂ = x · g₂ ∈ G₂

協議細節

可信設置

Groth16 Setup(R1CS, τ, α, β, γ, δ):

輸入：R1CS 實例，隨機秘密 τ, α, β, γ, δ

輸出：
  證明密鑰 pk = (
    [α]₁, [β]₁, [β]₂, [δ]₁, [δ]₂,
    {[τⁱ]₁}ᵢ₌₀ⁿ⁻¹,
    {[(β·uⱼ(τ) + α·vⱼ(τ) + wⱼ(τ))/δ]₁}ⱼ∈private,
    {[τⁱ·t(τ)/δ]₁}ᵢ₌₀ⁿ⁻²
  )

  驗證密鑰 vk = (
    [α]₁, [β]₂, [γ]₂, [δ]₂,
    {[(β·uⱼ(τ) + α·vⱼ(τ) + wⱼ(τ))/γ]₁}ⱼ∈public
  )

安全要求：
  τ, α, β, γ, δ 必須銷毀（toxic waste）

證明生成

Groth16 Prove(pk, w):

輸入：證明密鑰，見證向量 w = (1, x, w_private)

隨機值：r, s ← F_p

計算：
  A = [α + Σ wⱼ·uⱼ(τ) + r·δ]₁

  B = [β + Σ wⱼ·vⱼ(τ) + s·δ]₂

  C = [Σⱼ∈private wⱼ·(β·uⱼ(τ) + α·vⱼ(τ) + wⱼ(τ))/δ
       + h(τ)·t(τ)/δ
       + s·A + r·B - r·s·δ]₁

輸出：π = (A, B, C) ∈ G₁ × G₂ × G₁

驗證

Groth16 Verify(vk, x, π):

輸入：驗證密鑰，公開輸入 x，證明 π = (A, B, C)

計算公開輸入的線性組合：
  L = Σⱼ∈public xⱼ · [(β·uⱼ(τ) + α·vⱼ(τ) + wⱼ(τ))/γ]₁

驗證配對等式：
  e(A, B) = e([α]₁, [β]₂) · e(L, [γ]₂) · e(C, [δ]₂)

複雜度：
  - 3 次配對運算
  - 1 次 G₁ 多標量乘法（公開輸入）

安全性分析

安全假設

Groth16 安全基於：

1. q-PKE（q-Power Knowledge of Exponent）
   給定 (g, g^α, g^τ, ..., g^{τ^q}, g^{ατ}, ..., g^{ατ^q})
   任何能輸出 (c, ĉ) 使 ĉ = c^α 的算法
   必須「知道」某個 a₀, ..., aₙ 使 c = g^{Σaᵢτⁱ}

2. d-SDH（Strong Diffie-Hellman）
   給定 (g, g^τ, ..., g^{τ^d})
   難以計算 (c, g^{1/(τ+c)}) 對任意 c

3. 雙線性配對假設
   離散對數在 G₁, G₂, G_T 中均困難

Toxic Waste 風險

可信設置的危險：

若攻擊者知道 τ, α, β, γ, δ：
  - 可以偽造任意證明
  - 證明系統完全失效

緩解措施：
  1. MPC 儀式（如 Zcash Powers of Tau）
  2. 多方參與，只需一人誠實
  3. 公開可驗證的儀式

Groth16 vs 通用設置：
  - Groth16：每個電路需獨立設置
  - PLONK：通用設置，可重用

ZKML 應用

為何 ZKML 較少使用 Groth16

Groth16 在 ZKML 的限制：

1. 電路特定設置
   - 每個模型需要獨立設置
   - 模型更新需重新設置
   - 設置時間長（大模型可能數小時）

2. 非線性函數困難
   - 純 R1CS 無查表支援
   - ReLU 需要位元分解（~254 約束/ReLU）

3. 大電路問題
   - 設置隨電路線性增長
   - 大型 ML 模型設置成本高

ZKML 偏好：
  - PLONK/Halo2：查表支援 + 通用設置
  - STARK：透明設置 + 大電路友好

適用場景

Groth16 仍適合：

1. 小型固定模型
   - 模型不常更新
   - 電路規模可控

2. 極致驗證效率需求
   - 鏈上驗證成本敏感
   - 每次驗證都上鏈

3. 最小證明大小
   - 儲存成本敏感
   - 傳輸頻寬受限

範例應用：
  - 固定的欺詐檢測模型
  - 嵌入式 ML 驗證
  - 極簡區塊鏈整合

使用範例

// Circom + snarkjs 範例

// circuit.circom
template Multiply() {
    signal input a;
    signal input b;
    signal output c;
    c <== a * b;
}

component main = Multiply();

// 命令行使用
$ circom circuit.circom --r1cs --wasm
$ snarkjs groth16 setup circuit.r1cs pot12.ptau circuit_0.zkey
$ snarkjs groth16 prove circuit_0.zkey witness.wtns proof.json
$ snarkjs groth16 verify verification_key.json public.json proof.json
