Groth16

核心概念

Groth16 是目前最高效的 zk-SNARK 證明系統之一，由 Jens Groth 於 2016 年提出[1]。它具有最小的證明大小（固定 3 個群元素：2G₁ + 1G₂）和最快的驗證時間（3 次配對），是區塊鏈應用的首選方案。實際證明位元組數取決於橢圓曲線與序列化格式：BN254 壓縮約 128 bytes、非壓縮約 256 bytes；BLS12-381 壓縮約 192 bytes（如 Zcash Sapling）。其核心創新在於將 QAP（Quadratic Arithmetic Program）直接編碼到配對群結構中，實現了理論上最優的證明簡潔性。

歷史背景與定位

Groth16 是 SNARK 發展史上的里程碑。在此之前，GGPR13、Pinocchio 等系統的證明包含 7-8 個群元素，而 Groth16 將其壓縮至理論最小的 3 個元素[1]。

形式化定義

定義 1（雙線性群）

雙線性群是一個三元組 (G₁, G₂, G_T)，配備雙線性映射 e: G₁ × G₂ → G_T，滿足：

  • 雙線性：∀a,b ∈ Z_p, P ∈ G₁, Q ∈ G₂: e([a]P, [b]Q) = e(P, Q)^{ab}
  • 非退化性：若 P ≠ 0 且 Q ≠ 0，則 e(P, Q) ≠ 1
  • 可計算性：存在多項式時間算法計算 e(P, Q)
定義 2（R1CS 表示）

Rank-1 Constraint System 由三個矩陣 A, B, C ∈ F^{m×n} 定義，滿足：

(A · w) ∘ (B · w) = C · w

其中 w = (1, x₁, ..., x_ℓ, w₁, ..., w_{n-ℓ-1}) 是見證向量，∘ 表示 Hadamard 積。

定義 3（QAP - Quadratic Arithmetic Program）

給定 R1CS (A, B, C)，QAP 定義為多項式集合 {u_j(X), v_j(X), w_j(X)}_{j=0}^{n-1} 及目標多項式 t(X)，滿足：

對所有有效見證 w：
  A(X) · B(X) - C(X) ≡ 0 (mod t(X))

其中：
  A(X) = Σ_{j=0}^{n-1} w_j · u_j(X)
  B(X) = Σ_{j=0}^{n-1} w_j · v_j(X)
  C(X) = Σ_{j=0}^{n-1} w_j · w_j(X)
  t(X) = ∏_{i=1}^{m} (X - r_i)  [零化多項式]
定義 4（QAP 轉換）

從 R1CS 到 QAP 的轉換過程：

輸入：R1CS 矩陣 A, B, C ∈ F^{m×n}

1. 選取互異評估點 Ω = {r₁, ..., r_m} ⊂ F
2. 對每列 j ∈ [0, n-1]：
   u_j(X) ← 插值多項式使 u_j(r_i) = A_{i,j}
   v_j(X) ← 插值多項式使 v_j(r_i) = B_{i,j}
   w_j(X) ← 插值多項式使 w_j(r_i) = C_{i,j}
3. 定義 t(X) = ∏_{i=1}^{m} (X - r_i)

輸出：QAP = ({u_j, v_j, w_j}_{j=0}^{n-1}, t(X))
定義 5（知識可靠性）

證明系統具有知識可靠性，若存在多項式時間提取器 E，對任何產生有效證明的證明者 P*：

Pr[E^{P*}(x) = w : Verify(vk, x, P*(pk, w)) = 1] ≥ 1 - negl(λ)

即：能產生有效證明的證明者必定「知道」有效見證。

定義 6（q-PKE 假設）

q-Power Knowledge of Exponent 假設：給定

(g, g^α, g^τ, g^{τ²}, ..., g^{τ^q}, g^{ατ}, g^{ατ²}, ..., g^{ατ^q})

任何 PPT 算法若能輸出 (c, ĉ) 使得 ĉ = c^α，則必定「知道」多項式係數 (a₀, ..., a_q) 使得 c = g^{Σᵢ aᵢτⁱ}。

定義 7（零知識性）

證明系統具有完美零知識性，若存在模擬器 S，對所有敵手 A：

View_A(Real(x, w)) ≡ View_A(Simulated(x))

其中 ≡ 表示分布相同（非計算不可區分）。

配對群結構

群元素表示

雙線性群設置：

群：G₁, G₂, G_T（同階 p，素數）
配對：e: G₁ × G₂ → G_T
生成元：g₁ ∈ G₁, g₂ ∈ G₂

符號約定（方括號記法）：
  [x]₁ = x · g₁ ∈ G₁  （G₁ 中 x 的標量乘法）
  [x]₂ = x · g₂ ∈ G₂  （G₂ 中 x 的標量乘法）
  [x]_T = e(g₁, g₂)^x ∈ G_T

配對性質：
  e([a]₁, [b]₂) = e(g₁, g₂)^{ab} = [ab]_T

常用曲線：
  - BN254：~100-bit 安全，EVM 預編譯支援
  - BLS12-381：~128-bit 安全，較大但更安全

Phase 1: 可信設置（Trusted Setup）

算法 1：Setup(R1CS, 1^λ) 
輸入：
  - R1CS 實例 (A, B, C) ∈ F^{m×n}
  - 安全參數 λ

隨機取樣（toxic waste）：
  τ, α, β, γ, δ ←$ F_p*

計算 QAP：
  {u_j(X), v_j(X), w_j(X)}_{j=0}^{n-1} ← QAP(A, B, C)
  t(X) ← 零化多項式

計算 τ 的冪次（Powers of Tau）：
  對 i = 0, 1, ..., m-1:
    [τⁱ]₁, [τⁱ]₂

計算證明密鑰（Proving Key）：
  pk = (
    [α]₁,
    [β]₁, [β]₂,
    [δ]₁, [δ]₂,
    {[τⁱ]₁}_{i=0}^{m-1},
    {[τⁱ]₂}_{i=0}^{m-1},
    {[(β·u_j(τ) + α·v_j(τ) + w_j(τ))/δ]₁}_{j∈I_priv},
    {[τⁱ·t(τ)/δ]₁}_{i=0}^{m-2}
  )

計算驗證密鑰（Verification Key）：
  vk = (
    [α]₁,
    [β]₂,
    [γ]₂,
    [δ]₂,
    {[(β·u_j(τ) + α·v_j(τ) + w_j(τ))/γ]₁}_{j∈I_pub}
  )

銷毀：τ, α, β, γ, δ（必須！）

輸出：(pk, vk)
Toxic Waste 安全性

若任何人知道 τ、α、β、γ 或 δ 中的任一個，即可偽造任意語句的證明。因此：

  • 實務上使用多方計算（MPC）儀式產生 SRS
  • 只要有一位參與者誠實銷毀其隨機性，系統即安全
  • 著名儀式：Zcash Powers of Tau（87 位參與者）

Phase 2: 證明生成（Prove）

算法 2：Prove(pk, x, w) 
輸入：
  - 證明密鑰 pk
  - 公開輸入 x = (x₁, ..., x_ℓ)
  - 私密見證 w = (w₁, ..., w_{n-ℓ-1})

構造完整見證向量：
  w_full = (1, x₁, ..., x_ℓ, w₁, ..., w_{n-ℓ-1})

隨機取樣（零知識盲化因子）：
  r, s ←$ F_p

計算多項式：
  A(X) = Σ_{j=0}^{n-1} w_full[j] · u_j(X)
  B(X) = Σ_{j=0}^{n-1} w_full[j] · v_j(X)
  C(X) = Σ_{j=0}^{n-1} w_full[j] · w_j(X)

計算商多項式：
  h(X) = (A(X)·B(X) - C(X)) / t(X)
  [注：若見證有效，必整除]

計算證明元素 A：
  [A]₁ = [α]₁ + Σ_{j=0}^{n-1} w_full[j]·[u_j(τ)]₁ + r·[δ]₁
       = [α + A(τ) + r·δ]₁

計算證明元素 B：
  [B]₂ = [β]₂ + Σ_{j=0}^{n-1} w_full[j]·[v_j(τ)]₂ + s·[δ]₂
       = [β + B(τ) + s·δ]₂

  [B]₁ = [β]₁ + Σ_{j=0}^{n-1} w_full[j]·[v_j(τ)]₁ + s·[δ]₁
       = [β + B(τ) + s·δ]₁  [用於計算 C]

計算證明元素 C：
  [C]₁ = Σ_{j∈I_priv} w_full[j]·[(β·u_j(τ) + α·v_j(τ) + w_j(τ))/δ]₁
       + Σ_{i=0}^{m-2} h_i·[τⁱ·t(τ)/δ]₁
       + s·[A]₁ + r·[B]₁ - r·s·[δ]₁
       = [(私密部分 + h(τ)·t(τ) + sA(τ) + rB(τ) + (s·α + r·β - rs·δ))/δ]₁

輸出：π = ([A]₁, [B]₂, [C]₁) ∈ G₁ × G₂ × G₁

Phase 3: 驗證（Verify）

算法 3：Verify(vk, x, π) 
輸入：
  - 驗證密鑰 vk
  - 公開輸入 x = (x₁, ..., x_ℓ)
  - 證明 π = ([A]₁, [B]₂, [C]₁)

計算公開輸入的線性組合：
  [L]₁ = Σ_{j=0}^{ℓ} x_j · [(β·u_j(τ) + α·v_j(τ) + w_j(τ))/γ]₁
       （其中 x₀ = 1）

驗證配對等式：
  e([A]₁, [B]₂) ?= e([α]₁, [β]₂) · e([L]₁, [γ]₂) · e([C]₁, [δ]₂)

等價於驗證：
  A·B = α·β + L·γ + C·δ  (在指數上)

展開：
  (α + A(τ) + r·δ)(β + B(τ) + s·δ)
  = α·β
  + (Σ_{j∈I_pub} w_j·(β·u_j(τ) + α·v_j(τ) + w_j(τ)))
  + (私密部分 + h(τ)·t(τ) + sA(τ) + rB(τ) + sα + rβ - rsδ)

輸出：1（接受）或 0（拒絕）

配對等式推導

為何配對等式成立？

設：
  a = α + A(τ) + rδ
  b = β + B(τ) + sδ

則 a·b 展開為：
  a·b = αβ + αB(τ) + αsδ + A(τ)β + A(τ)B(τ) + A(τ)sδ
      + rδβ + rδB(τ) + rsδ²

利用 QAP 性質 A(τ)B(τ) - C(τ) = h(τ)t(τ)：
  A(τ)B(τ) = C(τ) + h(τ)t(τ)
           = Σw_j·w_j(τ) + h(τ)t(τ)

分離公開/私密部分：
  Σw_j·w_j(τ) = Σ_{j∈pub}... + Σ_{j∈priv}...

重組得：
  a·b = αβ
      + γ · (公開輸入線性組合/γ)
      + δ · (私密見證 + h(τ)t(τ) + 盲化項)/δ

這正是驗證等式的結構！

安全性分析

安全假設

定義 8（d-SDH 假設）

d-Strong Diffie-Hellman 假設：給定

(g, g^τ, g^{τ²}, ..., g^{τ^d})

對任何 PPT 算法，計算 (c, g^{1/(τ+c)}) 對任意 c ∈ F_p 是計算不可行的。

安全性定理

定理（Groth16 安全性）[1]：

在以下假設下，Groth16 證明系統是：
  1. 完備的（Perfect Completeness）
  2. 具有知識可靠性（Knowledge Soundness）
  3. 完美零知識的（Perfect Zero-Knowledge）

假設：
  (a) q-PKE（Generic Group Model 中可證明）
  (b) d-SDH（標準密碼學假設）
  (c) 雙線性配對群的安全性

安全性歸約：
  若存在 PPT 敵手 A 能偽造證明
  → 存在 PPT 算法 B 能打破 q-PKE 或 d-SDH
  → 矛盾

完備性證明

完備性論證：

設 (x, w) 是有效的語句-見證對，即 (A·w) ∘ (B·w) = C·w

則：
  A(X)·B(X) - C(X) = h(X)·t(X)  對某 h(X)

證明者計算的 [A]₁, [B]₂, [C]₁ 滿足：
  e([A]₁, [B]₂) = e([α + A(τ) + rδ]₁, [β + B(τ) + sδ]₂)
                = [αβ + αB(τ) + ... + A(τ)B(τ) + ...]_T

由 QAP 性質和 C 的構造：
  = [(αβ) + (公開部分)·γ + (私密部分 + h(τ)t(τ) + 盲化)·δ]_T
  = e([α]₁, [β]₂) · e([L]₁, [γ]₂) · e([C]₁, [δ]₂)

因此誠實證明者總能通過驗證。 ∎

知識可靠性論證

知識可靠性論證框架：

在代數群模型（AGM）中：
  任何能輸出有效證明的算法
  必定是對 SRS 元素的線性組合

提取器構造：
  1. 監控算法對 SRS 的使用
  2. 記錄每個輸出群元素的「係數」
  3. 從係數還原見證 w

安全歸約：
  若提取失敗 → 算法輸出與 SRS 線性無關的元素
              → 違反 q-PKE 假設

形式化：
  Pr[Verify(vk, x, π) = 1 ∧ (x, w) ∉ R] ≤ negl(λ)

零知識性證明

零知識模擬器構造：

Simulator(vk, x, τ*, α*, β*, γ*, δ*)：  [知道 trapdoor]

  1. 隨機取樣：a, b ←$ F_p

  2. 計算模擬證明：
     [A]₁ = [a]₁
     [B]₂ = [b]₂
     [C]₁ = [(a·b - αβ - L·γ) / δ]₁
          = [a]₁ · b/δ - [αβ/δ]₁ - [L·γ/δ]₁

  3. 輸出：π* = ([A]₁, [B]₂, [C]₁)

驗證模擬證明有效：
  e([a]₁, [b]₂) = [ab]_T
  e([α]₁,[β]₂) · e([L]₁,[γ]₂) · e([(ab-αβ-Lγ)/δ]₁,[δ]₂)
  = [αβ + Lγ + ab - αβ - Lγ]_T = [ab]_T ✓

分布不可區分性：
  真實證明：[A]₁ = [α + A(τ) + rδ]₁，r 隨機
  模擬證明：[A]₁ = [a]₁，a 隨機
  兩者分布相同（均為 G₁ 上均勻分布）∎

設計動機（Why 區塊）

為何證明只有 3 個群元素？

Groth16 的關鍵創新：

問題：如何最小化證明大小？

洞察：
  1. 驗證等式必須是配對等式（利用雙線性）
  2. 配對等式每邊需要 G₁ × G₂ 輸入
  3. 理論下界：至少需要 1 個 G₁ + 1 個 G₂ 元素

Groth16 解決方案：
  - 使用 α, β 將公開輸入「嵌入」到 vk 中
  - 使用 δ 將私密見證「隱藏」在 C 中
  - 使用 γ 分離公開/私密部分

結果：
  證明 = (A ∈ G₁, B ∈ G₂, C ∈ G₁) = 3 元素
  這是 QAP-based SNARK 的理論最優！

代價：
  - 電路特定 SRS（每個電路需重新設置）
  - 較強的安全假設（q-PKE）

為何需要電路特定設置？

電路特定 vs 通用設置：

Groth16 設置包含：
  {[(β·u_j(τ) + α·v_j(τ) + w_j(τ))/δ]₁}_j

這些元素依賴於具體電路的 QAP 多項式 u_j, v_j, w_j。

為何不能通用？
  若 SRS 獨立於電路
  → 證明者可「選擇」對自己有利的電路
  → 安全性失效

PLONK 如何實現通用設置：
  - 不在 SRS 中編碼電路
  - 在證明中發送電路承諾
  - 代價：證明較大（~10 群元素）

權衡：
  Groth16：小證明 + 快驗證，但電路特定
  PLONK：通用設置，但證明較大

為何 r, s 盲化因子？

盲化因子的作用：

問題：若無 r, s，證明是否洩露見證？

分析：
  不盲化時：
    [A]₁ = [α + A(τ)]₁
    [B]₂ = [β + B(τ)]₂

  給定相同見證的多個證明：
    敵手可能推斷 A(τ), B(τ) 的結構

盲化後：
  [A]₁ = [α + A(τ) + r·δ]₁
  每次 r 不同 → A 每次不同
  即使相同見證，證明也完全隨機

安全性：
  r, s 提供完美零知識性
  不僅計算隱藏，而是信息論隱藏

ZKML 應用分析

為何 ZKML 較少使用 Groth16

Groth16 在 ZKML 的限制：

1. 電路特定設置
   - 每個 ML 模型需要獨立設置
   - 模型更新（fine-tuning）需重新設置
   - 設置時間可能比證明時間更長

   範例：ResNet-50 電路
     - 約 2500 萬約束
     - 設置時間：~2 小時
     - 證明時間：~20 分鐘
     - 模型更新 → 重做 2 小時設置

2. 無查表支援
   - R1CS 無法高效表達非線性函數
   - ReLU 需位元分解：~254 約束/次
   - Softmax 更加昂貴

   對比 PLONKish：
     ReLU 查表：~1 約束/次
     效率差 100-200 倍

3. 大電路問題
   - 設置記憶體：O(n)
   - 大型模型（如 BERT）：數十億約束
   - 設置可能需要 TB 級記憶體

Groth16 仍適用的場景

適合使用 Groth16 的 ZKML 場景：

1. 小型固定模型
   - 模型穩定不常更新
   - 電路規模 < 1M 約束
   - 可接受一次性設置成本

   範例：
     - 欺詐檢測模型（固定規則）
     - 嵌入式 ML（資源受限）

2. 極致鏈上成本敏感
   - 每次驗證都上鏈
   - Gas 成本是主要考量
   - 證明大小差異顯著

   成本對比（以太坊 ~30 gwei）：
     Groth16：~200K gas，~$5
     PLONK：~300K gas，~$7.5
     STARK：~500K gas，~$12

3. 最小證明大小需求
   - 儲存成本敏感
   - 傳輸頻寬受限
   - 需要長期存檔

   大小對比（壓縮格式）：
     Groth16：128-192 bytes（依曲線）
     PLONK：~400 bytes
     STARK：~50 KB

支援 Groth16 的 ZKML 工具：

   - 結合兩者優勢

變體與改進

Groth16 變體

1. Groth16 with Aggregation
   - 聚合多個 Groth16 證明
   - 技術：SnarkPack [Gailly et al., 2021]
   - n 個證明 → O(log n) 聚合證明

2. LegoSNARK
   - 模塊化證明組合
   - 可將多個 Groth16 證明連接
   - 適合複雜多階段計算

3. 遞迴 Groth16
   - 在 Groth16 電路中驗證 Groth16
   - 挑戰：配對電路非常大（~百萬約束）
   - 實現：Nova + Groth16 混合

4. Marlin
   - 通用設置變體
   - 保持類似效率
   - 略大證明（~10 群元素）

實現優化

MSM 優化技術：

1. Pippenger 算法
   - 標準 MSM：O(n) 群運算
   - Pippenger：O(n / log n) 群運算
   - 實際加速：5-10 倍

2. 並行化
   - MSM 天然可並行
   - 多核 CPU：4-8 倍加速
   - GPU：10-100 倍加速

3. 預計算
   - 對固定生成元預計算窗口表
   - 時間-空間權衡

FFT 優化：
  - NTT（有限域 FFT）
  - 並行蝴蝶運算
  - Cache-oblivious 實現

使用範例

// Circom + snarkjs 完整流程

// 1. 定義電路 (circuit.circom)
template Multiply() {
    signal input a;
    signal input b;
    signal output c;
    c <== a * b;
}
component main = Multiply();

// 2. 編譯電路
$ circom circuit.circom --r1cs --wasm --sym

// 3. Powers of Tau 儀式（或使用現有）
$ snarkjs powersoftau new bn128 12 pot12_0000.ptau
$ snarkjs powersoftau contribute pot12_0000.ptau pot12_0001.ptau
$ snarkjs powersoftau prepare phase2 pot12_0001.ptau pot12_final.ptau

// 4. 電路特定設置（Phase 2）
$ snarkjs groth16 setup circuit.r1cs pot12_final.ptau circuit_0.zkey
$ snarkjs zkey contribute circuit_0.zkey circuit_final.zkey
$ snarkjs zkey export verificationkey circuit_final.zkey vk.json

// 5. 計算見證
$ node generate_witness.js circuit.wasm input.json witness.wtns

// 6. 生成證明
$ snarkjs groth16 prove circuit_final.zkey witness.wtns proof.json public.json

// 7. 驗證
$ snarkjs groth16 verify vk.json public.json proof.json

// 8. 生成 Solidity 驗證器
$ snarkjs zkey export solidityverifier circuit_final.zkey verifier.sol
