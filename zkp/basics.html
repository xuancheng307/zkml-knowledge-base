ZKP 基礎概念

核心概念

零知識證明（Zero-Knowledge Proof, ZKP）是一種密碼學協議，允許證明者（Prover）向驗證者（Verifier）證明某陳述為真，同時不洩露任何除「陳述為真」之外的資訊[1]。

直觀理解

經典比喻：阿里巴巴洞穴

場景設置：
  - 環形洞穴有兩條路徑 A 和 B
  - 中間有一道需要密碼的門
  - Peggy（證明者）聲稱知道密碼
  - Victor（驗證者）想確認但不想學到密碼

協議：
  1. Victor 在洞口等待
  2. Peggy 隨機選擇 A 或 B 進入
  3. Victor 喊出要求 Peggy 從 A 或 B 出來
  4. 若 Peggy 知道密碼，總能從指定路徑出來
  5. 若不知道，有 50% 機率失敗

重複 n 次後：
  - 成功機率（若不知密碼）：(1/2)^n
  - n = 20 時，約百萬分之一

數位世界的類比

數學版本：

陳述：「我知道方程式 f(x) = y 的解 x」

傳統證明：
  展示 x，讓驗證者計算 f(x) = y ✓
  問題：x 被洩露

零知識證明：
  證明「我知道 x」而不透露 x
  驗證者確信 x 存在，但無法得知 x

形式化定義

互動式證明系統

定義：互動式證明系統 (P, V) 對於語言 L

參與者：
  P（Prover）：計算能力無限
  V（Verifier）：多項式時間

互動：
  P 和 V 交換訊息
  最終 V 輸出 accept 或 reject

性質：
  1. 完備性（Completeness）
  2. 可靠性（Soundness）
  3. 零知識性（Zero-Knowledge）

NP 關係

定義：NP 關係 R ⊆ {0,1}* × {0,1}*

對於 (x, w) ∈ R：
  - x 是陳述（statement）
  - w 是見證（witness）
  - 可在多項式時間內驗證

語言 L_R = {x : ∃w, (x, w) ∈ R}

範例：
  R = {(G, 3-coloring) : 3-coloring 是圖 G 的合法三著色}
  x = 圖 G
  w = 著色方案

ZKML 中：
  x = (電路描述, 公開輸入, 公開輸出)
  w = (私密輸入, 私密權重)

ZKP 類型

互動式 vs 非互動式

類型 互動式 非互動式
通訊輪數 多輪 單輪
驗證者 需要在線 可離線
可重用性 每次需新互動 證明可轉發
假設 標準模型 CRS 或 ROM

Fiat-Shamir 變換

將互動式轉為非互動式：

原理：
  用雜湊函數替代驗證者的隨機挑戰

互動式協議：
  P → V: commitment c
  V → P: challenge e（隨機）
  P → V: response z

非互動式（Fiat-Shamir）：
  e = Hash(c, statement)
  證明 π = (c, e, z)

安全模型：
  隨機預言機模型（ROM）
  假設 Hash 是理想隨機函數

常見 ZKP 系統分類

zk-SNARK：
  - Succinct：證明簡短
  - Non-interactive：非互動
  - ARgument of Knowledge：知識論證
  代表：Groth16, PLONK

zk-STARK：
  - Scalable：可擴展
  - Transparent：透明設置
  代表：RISC Zero, Cairo

其他：
  - Bulletproofs：範圍證明
  - MPC-in-the-head：Ligero, Aurora

核心組件

承諾方案

定義：將值「鎖定」而不揭示

兩階段協議：
  1. Commit(m, r) → c
     承諾訊息 m，使用隨機性 r

  2. Open(c, m, r) → {0, 1}
     驗證 c 確實承諾 m

性質：
  - 隱藏性：c 不洩露 m
  - 綁定性：無法改變已承諾的值

範例：
  Pedersen 承諾：C = g^m · h^r
  KZG 承諾：C = [f(τ)]_1

算術電路

ZKP 的計算表示：

電路結構：
  - 輸入線（公開 + 私密）
  - 加法門、乘法門
  - 輸出線

範例電路：z = x² + y

  x ──┬──[×]──┐
      └───────┤
              [+]── z
  y ─────────┘

電路滿足 ⟺ 存在合法的線路賦值

ZKML 連結

ML 推理作為 ZKP 陳述

ZKML 問題設定：

公開：
  - 模型承諾 C_M（或完整模型 M）
  - 輸入 x（或輸入承諾）
  - 輸出 y

私密（可選）：
  - 模型權重 w
  - 中間激活值

陳述：
  「存在合法的推理過程使得 M(x) = y」

電路：
  將神經網路層轉換為算術電路
  ReLU 等非線性使用查表

為何 ZKML 需要 ZKP

應用場景：

1. 可驗證推理
   證明：「這是正確的模型輸出」
   不洩露：模型權重

2. 隱私推理
   證明：「輸入確實產生此輸出」
   不洩露：輸入內容

3. 公平性證明
   證明：「模型對所有輸入一視同仁」
   不洩露：內部邏輯

學習路徑

建議學習順序：

1. 基礎理論
   → 完備性、可靠性、零知識性

2. 承諾方案
   → KZG, IPA, FRI

3. 算術化
   → R1CS, PLONKish

4. 證明系統
   → Groth16, PLONK, STARK

5. ZKML 應用
   → 模型到電路的轉換
