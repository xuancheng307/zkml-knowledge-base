機器學習總覽

導讀說明

本區塊說明 ZKML 相關的機器學習概念。重點在於理解為什麼 ML 推理對 ZK 證明系統構成挑戰，以及如何克服這些挑戰。

機器學習推理流程

機器學習推理 (Inference) 是使用訓練好的模型對新輸入進行預測的過程。對於神經網路而言，推理本質上是一連串的矩陣運算和非線性變換[1]： 

神經網路推理：y = f(x; W)

前向傳播過程：
  h₀ = x                           // 輸入
  h₁ = σ(W₁ · h₀ + b₁)            // 隱藏層 1
  h₂ = σ(W₂ · h₁ + b₂)            // 隱藏層 2
  ...
  y = softmax(Wₙ · hₙ₋₁ + bₙ)      // 輸出層

其中：
  Wᵢ = 權重矩陣
  bᵢ = 偏差向量
  σ  = 激活函數（ReLU, GELU 等）

為什麼 ML 對 ZK 是挑戰？

ML 推理與 ZK 證明系統之間存在根本性的不匹配[1]：

特性 機器學習 ZK 證明 衝突
數值表示 32/16-bit 浮點數 有限域元素 需要量化轉換
非線性 ReLU, GELU, Softmax 線性算術約束 需要查表或近似
計算規模 數十億次運算 每次運算產生約束 巨大電路規模
除法 頻繁使用 需要模逆運算 高約束成本
核心挑戰

一個 ResNet-18 模型包含約 1100 萬參數，單次推理涉及數億次乘法和加法。若直接轉換為 ZK 電路，證明生成可能需要數小時甚至更久[1]。

ZKML 相關的 ML 概念

1. 神經網路層類型

不同類型的層在 ZK 電路中有不同的成本特徵[1]：

層類型 運算 ZK 成本 處理方式
全連接層 y = Wx + b O(n·m) 約束 直接矩陣乘法
卷積層 y = W ∗ x + b O(H·W·C·K²) im2col 展開或 FFT
ReLU max(0, x) O(n) lookups 符號位檢查或查表
Softmax exp(xᵢ)/Σexp(xⱼ) 極高 通常省略或近似
BatchNorm (x-μ)/σ·γ+β - 摺疊入前層權重
Pooling max/avg O(n) 比較或累加

2. 激活函數

激活函數引入非線性，是 ML 模型表達能力的關鍵，但對 ZK 是重大挑戰：

激活函數 定義 ZK 友好度 處理策略
ReLU max(0, x) 中 符號位分解或查表
ReLU6 min(max(0, x), 6) 較高 有界，更易量化
Sigmoid 1/(1+e⁻ˣ) 低 查表或多項式近似
GELU x·Φ(x) 低 查表或 ReLU 替代
SiLU/Swish x·σ(x) 低 查表

3. 常見模型架構

ZKML 系統支援的主流架構[1]：

架構 參數量 主要運算 ZKML 支援
MLP ~1M 全連接 完整支援
CNN (ResNet, VGG) 11-138M 卷積、BatchNorm ZKML、EZKL 支援
MobileNet ~3M 深度可分離卷積 輕量級首選
Transformer 數百M~數十B 注意力、FFN 部分支援（zkLLM）
RNN/LSTM ~10M 遞迴、門控 ZKTorch 支援

量化 (Quantization)

量化是將浮點數模型轉換為低位元整數表示的技術，對 ZKML 至關重要[2]：

量化（Quantization）：浮點數 → 整數碼
  q = clamp(round(r / S) + Z, q_min, q_max)

反量化（Dequantization）：整數碼 → 近似浮點數
  r' = S · (q - Z)

其中：
  r  = 原始浮點值
  q  = 量化整數碼
  S  = 縮放因子 (scale)
  Z  = 零點 (zero-point)
  r' = 反量化後的近似值（r' ≈ r，存在量化誤差）

常見位寬：
  INT8:  最常用，準確率損失小
  INT4:  激進量化，小模型可用
  INT16: 高精度需求

量化方法

方法 說明 優缺點
PTQ 訓練後量化 快速但可能損失精度
QAT 量化感知訓練 精度最佳但需重新訓練
Per-tensor 整個張量共用 S, Z 簡單但精度較低
Per-channel 每通道獨立 S, Z 精度高但參數多

模型表示格式

ONNX

Open Neural Network Exchange (ONNX) 是機器學習模型的開放標準格式，被 EZKL 和 ZKML 等框架廣泛使用：

  • 支援主流框架匯出（PyTorch、TensorFlow、Keras）
  • 定義標準運算符集 (opset)
  • 圖形化表示計算流程
  • ZKML 框架解析 ONNX 生成電路
ONNX 工作流程：
  PyTorch Model → torch.onnx.export() → model.onnx → EZKL/ZKML → ZK Circuit

推理優化技術

除了量化，還有其他技術可降低 ZKML 成本：

剪枝 (Pruning)

移除不重要的權重或神經元，減少計算量：

  • 非結構化剪枝：移除單個權重（稀疏矩陣）
  • 結構化剪枝：移除整個通道或層（更易加速）

知識蒸餾 (Knowledge Distillation)

用小模型（學生）模仿大模型（教師）的行為，獲得更高效的推理模型。

運算符融合 (Operator Fusion)

將多個連續運算合併為單一運算，減少中間結果儲存：

融合前：Conv → BatchNorm → ReLU（3 個運算）
融合後：Conv_BN_ReLU（1 個運算）

ZKML 的 ML 設計建議

設計 ZK 友好的 ML 模型時應考慮[1]：

  1. 使用 ReLU 而非 GELU：ReLU 的分段線性特性更易電路化
  2. 優先使用 ReLU6：有界激活函數更易量化
  3. 避免 Softmax：使用 argmax 或省略最終層正規化
  4. BatchNorm 摺疊：推理時將 BN 參數併入權重
  5. 限制模型深度：每層都增加電路約束
  6. 考慮 MobileNet：深度可分離卷積更高效
