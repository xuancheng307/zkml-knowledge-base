量化（Quantization）

ZKML 的核心優化

量化是將浮點數模型轉換為定點數/整數的過程。對 ZKML 而言，量化不僅是優化手段，更是必要前提——ZK 電路只能處理有限域元素。

量化基礎

為什麼需要量化

傳統 ML：
  - 使用 32 位浮點數（float32）
  - 支援任意精度運算
  - GPU 原生支援

ZK 電路：
  - 只能處理有限域 F_p 的元素
  - 不支援浮點運算
  - 需要將實數映射為整數

量化公式

均勻量化（Uniform Quantization）：
  q = round((x - z) / s)

  其中：
    x = 浮點數值
    q = 量化後整數
    s = 縮放因子（scale）
    z = 零點偏移（zero point）

反量化：
  x' = s · q + z

量化類型

按位寬分類

類型位寬範圍精度損失ZKML 適用性
INT88 位[-128, 127]小最常用
INT1616 位[-32768, 32767]極小高精度需求
INT44 位[-8, 7]中等極端壓縮
Binary1 位{-1, +1}大特殊應用

按粒度分類

Per-Tensor 量化：
  整個張量使用同一個 (s, z)
  優點：簡單，約束少
  缺點：精度較低

Per-Channel 量化：
  每個輸出通道獨立 (s_c, z_c)
  優點：精度高
  缺點：需要更多參數

Per-Group 量化：
  將通道分組，每組獨立量化
  優點：平衡精度與複雜度

按時機分類

訓練後量化（PTQ）：
  - 訓練完成後直接量化
  - 簡單快速
  - 精度損失可能較大

量化感知訓練（QAT）：
  - 訓練時模擬量化效果
  - 精度更高
  - 需要重新訓練

ZKML 專用量化考量

有限域約束

問題：
  ZK 電路在有限域 F_p 運算
  p 通常是 254 位素數
  但實際運算需避免 overflow

解決方案：
  選擇適當位寬 b
  確保中間值 < p/2

  例：矩陣乘法 y = Wx
  |y_i| ≤ Σ|w_ij · x_j| ≤ n · 2^(2b)
  需要 n · 2^(2b) < p/2

非線性函數處理

問題：
  激活函數輸入/輸出都需量化
  查表需要固定輸入範圍

解決：
  建立輸入範圍 → 查表索引的映射

  例：ReLU 查表
  輸入範圍：[-128, 127]（INT8）
  查表大小：256 項
  table[i] = max(0, i - 128)

累積誤差問題

深度網路的挑戰：
  每層都有量化誤差
  誤差會累積傳播

對策：
  1. 使用較高位寬（16 位）
  2. 層間重新量化（rescaling）
  3. 誤差校正技術

量化配置空間

可調參數

每層可獨立配置：
  - 權重位寬：w_bits ∈ {4, 8, 16, 32}
  - 激活位寬：a_bits ∈ {4, 8, 16, 32}
  - 量化粒度：per-tensor / per-channel
  - 縮放因子：symmetric / asymmetric

配置空間大小：
  假設 L 層，每層 4 個選項
  總配置數 = 4^L（指數級）

混合精度量化

策略：
  不同層使用不同位寬
  敏感層用高精度
  不敏感層用低精度

敏感度分析：
  1. 計算每層的 Hessian
  2. 評估量化對輸出的影響
  3. 分配位寬預算

量化與 ZK 成本

約束數量影響

整數乘法約束：
  a × b = c 需要 1 個約束
  與位寬無關（在域內）

範圍證明：
  證明 x ∈ [0, 2^b - 1]
  需要 O(b) 個約束

位寬越大：
  - 範圍證明成本增加
  - 但精度更高，soundness 更強

查表成本影響

b 位輸入的查表：
  表大小 = 2^b 項

8 位輸入：256 項（實用）
16 位輸入：65536 項（較大但可行）
32 位輸入：2^32 項（不實際）

→ 查表傾向使用較低位寬

實作建議

ZKML 量化最佳實踐

1. 從 INT8 開始
   - 大多數模型可接受
   - 約束成本低

2. 敏感層提升精度
   - 第一層和最後一層
   - Attention 相關層

3. 使用 Per-Channel 量化
   - 精度提升明顯
   - 成本增加有限

4. 驗證精度損失
   - 比較量化前後輸出
   - 設定可接受閾值

5. 考慮 QAT
   - 若 PTQ 精度不足
   - 重新訓練代價
